## [2026-09-04] 배치 — 통합 월드모델과 의미 분할이 만나는 지점

### 🌍 [[Puffin-World]] — 물리·기하·외형을 한 모델의 네이티브 상태로 (업보트 31, ACE Robotics)
볼트에 월드모델 소스가 **28건** 쌓였지만 대부분 *"미래 프레임을 그럴듯하게 그린다"* 쪽이다. Puffin-World의 차이는 **무엇을 상태로 두는가**에 있다 — **물리(중력장·위도) · 기하(깊이) · 외형(이미지)** 을 **네이티브 월드 상태 3종**으로 함께 모델링하고 **외부 오프라인 모듈에 의존하지 않는다**.
- **Omni-Camera 표현**으로 카메라를 통일, **절대 카메라 속성을 실세계에 접지(grounding)** → 물리적 일관·시각적 안정 주장
- 외형과 기하를 **단일 생성 과정에 결합** — 미래 뷰를 합성하면서 **그 뷰의 기하를 동시에 복원** → 닫힌 루프(mimic·자기 보정 월드 탐색)
- **Puffin-16M**: **1,500만 vision-language-camera 트리플렛 + 100만 궤적**
- **"외부 모듈 없이"가 실질 주장**이다 — 기존 파이프라인은 깊이 추정기·포즈 추정기·물리 엔진을 따로 붙이고, **모듈 경계는 곧 드리프트 발생 지점**이다([[LIO-SAM]] 계열 고전 문제)
- 🚨 **정량 수치 0건**: 벤치마크·비교군·SOTA 주장 **전부 없음**. *"physically consistent and visually stable"* 은 **주장**이다. 코드·모델·데이터셋을 *"released"* 라 했으나 **HF 페이지에 링크 없음**. [[PAWBench]] 교훈(월드모델 11개 시스템 전멸)을 감안해 **특히 보수적으로** 읽을 것
- → **우선순위는 데이터 > 모델**: Puffin-16M의 **실재·라이선스만 먼저 확인**한다. 사실이면 이 축 최대 획득물

### 🔗 [[sam3]]와의 교차 — 의미가 붙은 3D 재구성
[[Puffin-World]]가 **깊이·기하**를 생성하고 [[sam3]]가 **개방 어휘 의미 분할**(텍스트로 모든 인스턴스, 비디오 추적)을 붙이면 **의미가 붙은 3D 재구성**으로 간다. [[X2SAM]]·[[4D-Human-Scene-Reconstruction]] 축과 직결되며, SAM 3는 **🤗 Transformers 정식 통합**이라 실험 진입 비용이 낮다.

### 축 관측
[[Puffin-World]]가 중력·위도·깊이를 **암묵적 학습에 맡기지 않고 상태 변수로 승격**시킨 것은, 이번 배치 5건에서 반복된 [[암묵을-명시로]] 패턴의 3D판이다. 방향은 [[JEPA-vs-Diffusion-월드모델]]의 *"무엇을 예측 대상으로 삼는가"* 논점의 확장.

# 📦 2026-09-07 배치 — [[WorldSculpt]] (재분류: ai-news → slam-3dgs)

## 통짜 재구성에서 **분해 가능성(decomposability)** 으로

목표 표현이 *"공유 월드 프레임에 배치된 **개별 오브젝트 메시들의 집합**"* 이고, 초록이 이유를 명시한다 — **게임·AR/VR·시뮬레이션·로보틱스가 그걸 요구하기 때문**이다.

기존 두 갈래의 실패를 논문이 직접 짚는다:
- **기하 기반**: 장면을 **하나의 표현**으로 재구성 → **가려진 영역의 기하가 미완성**
- **기존 조합적 방법**: **비교적 단순한 장면**에 한정

→ 볼트의 3DGS 축([[GlobalSplat]]·[[anyrecon]]·[[Beyond-Pixels-4D]])이 대체로 **통짜 표현**이었다면 이건 **분해** 축이다. **로보틱스에 쓰려면 물체 단위로 잡히지 않으면 쓸모가 없다**는 요구가 표현 방식을 결정한다.

> [!insight] 학습 분포와 추론 복잡도가 **분리됐다**
> 초록 원문: *"the model is finetuned **entirely on single objects in canonical space**, it generalizes to large scenes with severe occlusion **without any scene-level training**."*
> **밀집 장면을 생성하기 위해 밀집 장면을 학습할 필요가 없었다.** 단일 오브젝트 prior(**Pixal3D**)에 **multi-view conditioning 경로**만 달면 된다.
> 그리고 주장의 형태가 좋다 — *"**격차가 장면 복잡도와 가림이 커질수록 벌어진다**"*. 평균 우위가 아니라 **겨냥한 실패 모드를 실제로 푼다**는 증거 형태.

## 🔗 [[월드모델]] 축과 [[slam-3dgs]] 축이 여기서 **연결된다**

초록 마지막: *"생성된 **3DGS 월드**(**Marble**, **HY-World 2.0**)를 compositional **mesh** scenes로 변환"*.
→ 볼트가 따로 추적하던 두 축 사이에 **변환 경로**가 생겼다. 3DGS로 만든 월드를 **게임/시뮬레이터에 넣을 수 있는 형식**으로 내리는 다리다.

## 벤치마크: UE-MeshyScene
수백 오브젝트 · **오브젝트별 주석** · **GT 메시** 를 갖춘 포토리얼 밀집 장면. → [[검사가능성-공사]]

> [!warning] 확인 안 된 것
> - **절대 수치 전무** — *"일관되게 상회"* 이상 인용 금지
> - **실시간성 판정 불가** — 생성 시간이 초록에 없다. 오브젝트 수백 개를 개별 생성하면 **오브젝트 수에 선형 이상**일 가능성
> - **코드·모델 공개 미확인** · **저자 소속 미확인**
> - 🔴 **오브젝트 경계를 누가 정하는가** — *"grounded video"* 는 **분할이 이미 주어졌음**을 시사한다. 그렇다면 실사용 난이도가 **분할 품질에 종속**되고 [[X2SAM]] 계열이 전처리로 붙는다

## [2026-09-08] 배치 — 검증 루프를 지었더니 메모리 부재가 드러났다

**신규 1건**: [[EmbodiedSkills]](HF 논문 · 업보트 5 · 저자 17인 · 코드 공개)

### 구조 — 모델 출력을 "결정"이 아니라 "제안"으로 격하시킨다

*"행동 예측이나 모델이 생성한 스킬 결정은 **그 자체로는** 제안된 조작이 현재 상태에서 유효한지, 결과가 검증될지를 보장하지 않는다."*
→ **제안 → 사전조건 검사 → 실행 → 사후 검증**을 **고정된 실행가능 스킬 인터페이스**로 강제한다.

**고정 인터페이스의 효과**: 저수준 VLA 정책을 **에이전트 루프를 안 바꾸고 교체**할 수 있다. VLA 모델의 교체 주기가 짧다는 점(볼트 관측: 파운데이션 모델 세대 교체가 [[timesfm-3.0-pytorch]] 사례에서 **4일**)을 고려하면 실질적 이득이다. 소프트웨어 공학의 **의존성 역전**을 로봇 스택에 적용한 형태.

**부수 효과가 더 중요하다**: 인터페이스가 계획·실행·검증·복구를 **구조화된 궤적으로 기록**하고, **그 기록이 다시 각 구성요소의 감독 신호**가 된다. → **검사 창을 지으면 로그가 남고, 로그는 학습 데이터가 된다**([[검사가능성-공사]] 확장).

### 실측 — 그리고 저자가 자기 한계를 먼저 썼다

| 벤치마크 | 성공률 |
|---|---|
| RoboTwin 2.0 50태스크 평균 | **86.20%** |
| LIBERO 4스위트 | **97.40%** |
| **RMBench 기억의존 4태스크** | **🔴 12.5%** |

**구성**: Qwen3-VL(고수준) + OpenPI/pi0.5(저수준).

📌 **12.5%를 초록에 쓴 것**, 그리고 *"이 결과들은 **태스크 적응된 저수준 VLA 정책의 실행 성능**을 확립한다"* 며 **86.20%를 프레임워크의 공으로 주장하지 않은 것** — 둘 다 신뢰도를 올린다. 볼트가 [[Thinkingbox]]·[[apache-maka]] 에서 경고한 *"중간 지표 ≠ 최종 결과"* 의 **역방향 사례**다.

### 🔴 12.5%가 말하는 것 — 검증 루프를 잘 지어도 메모리는 별도 문제다

사전조건 검사 → 실행 → 사후 검증은 **전부 현재 상태에 대한 판단**이다. **과거에 무엇을 했는지**는 이 루프에 들어갈 자리가 없다.
→ [[에이전트-메모리-레이어]] 축과 정확히 만난다. **구조적 검사는 *"지금 유효한가"* 를 답하지 *"아까 뭘 했나"* 를 답하지 않는다.**
⚠️ RMBench 태스크가 **4개뿐**이라 표본이 작고, 저자도 실패 원인을 분해하지 않았다.

### 도메인 템플릿 미답 항목
- **실시간 가능성**: **미확인.** 초록에 지연시간·주기 수치가 **전혀 없다.** 매 스킬마다 사전·사후 검증을 돌리면 오버헤드가 있을 수밖에 없는데 그 값이 없다 — 로봇에서 이건 결정적이다.
- **카메라 파이프라인**: Qwen3-VL이 시각 입력 처리, 구체 형식 미기재.
- **필수 레퍼런스**: **RoboTwin 2.0 · LIBERO · RMBench — 볼트에 페이지가 없다. 추적 공백 3건 등록.**

### 📌 도메인 간 수렴 — 이번 배치 최대 신호
[[EmbodiedSkills]](로봇 제어)와 [[TGOPD]](LLM 학습)가 **서로를 인용하지 않고 같은 골격**에 도달했다: *"신뢰할 수 있는지 먼저 검증하고, 통과할 때만 쓴다."* 도메인이 최대한 멀리 떨어져 있는데 처방이 같다 → [[검사가능성-공사]] 가 도메인 특수적 유행이 아니라는 **지금까지 중 가장 강한 근거**.

## [2026-09-09] 배치 — 단안 깊이추정이 1-step으로 내려왔다

> [!insight] [[Marigold-V2]] — HF 데일리 1위(업보트 24)
> raw는 `ai-news` 로 보냈지만 **단안 깊이추정은 이 도메인의 입력단**이다.
> 기여는 새 모델이 아니라 **레시피**: 사전학습된 **다단계 flow-matching DiT**를 **1-step 추론**으로 돌려 SOTA 깊이추정기로 전환.

### 처방 두 가지 (순진한 학습의 아티팩트 진단 후)
1. **모델 내부 표현을 GT에서 추출한 의미 피처와 정렬**
2. **Sinkhorn 기반 신규 손실을 축으로 한 2단계 파인튜닝**
필요시 **양자화**를 적용해 모델 용량은 보존하면서 실행 비용을 낮춘다.

### 현재 SOTA 수치
- **KITTI · ETH3D에서 AbsRel 기존 최고 대비 16–26% 개선**
- **표면 법선 추정 · 본질 이미지 분해** 등 다른 밀집 회귀 과제에서도 SOTA
- 정성: *"**fur, foliage, and hair-thin edges**"* — 기존 모델이 놓치던 **머리카락 두께 경계**를 해결

> [!action] 즉시 할 것
> **HF Space에서 내 소스 이미지로 먼저 돌린다**(설치 0): https://hf.co/spaces/huawei-bayerlab/marigold-v2-web
> 판단 기준은 벤치마크가 아니라 **내 데이터에서 경계 디테일이 실제로 살아나는가**. 3DGS 초기화·깊이 프라이어에서 경계 품질이 병목이었다면 직접적 개선.

> [!question] 미확인
> **fps 수치가 논문에 없다.** 1-step + 양자화로 "cheap to run"이라 주장하지만 **30fps+ 실시간 가능 여부는 판정 불가** — DiT 백본 크기가 지배할 것으로 보인다. 실측 필요.
