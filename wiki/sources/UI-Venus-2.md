# UI-Venus-2 Technical Report

**arXiv**: 2609.00028 · **HF**: https://huggingface.co/papers/2609.00028
**지표(2026-09-02)**: 업보트 **50**(데일리 **3위**) · 저자 **31인**(⚠️**이번 배치 최다**) · 공개 **2026-08-27** — HF API 실호출 + **초록 원문 대조**
**드리프트**: raw와 **완전 일치**(50 · 31인)

> [!insight] 핵심 인사이트 — **검증(verification)을 스케일링 축으로 승격**시켰다
> 저자들이 지목한 병목이 정확하다: 벤치마크용 모델에서 신뢰할 만한 실사용으로 넘어가지 못하는 이유는 **① 제한된 환경 커버리지 ② 취약한 태스크 구성 ③ 신뢰할 수 없는 보상 검증**이다.
> 그래서 **3축을 동시에 확장**한다 — Environments · Tasks · **Verification**.
> **세 번째가 핵심이다.** 보통 "스케일링"이라 하면 데이터·파라미터·환경을 늘리는 것을 뜻하지, *채점기*를 늘린다고는 하지 않는다. UI-Venus-2는 RL 신호의 신뢰성을 확보하려고 **시각 키포인트 + 다중모델 투표** 기반의 **트레이스 단위 · 샘플 단위 평가자**를 도입한다.
> 이는 08-31 [[Agentic-Artifact-Creation]] 서베이(259편)가 내놓은 **부정적 결론** — *"LLM 심판이 생성기와 선호·맹점을 공유하면 독립 증거가 못 된다"* — 에 대한 **공학적 응답**으로 읽힌다. **다중모델 투표는 심판 비독립성을 완화하려는 직접적 처방**이다. 다만 투표에 참여한 모델들이 서로 독립인지는 초록에 없다 — **처방이 문제를 완전히 해소했다고 볼 근거는 없다.**

> [!insight] 커버리지 주장 — 규모는 구체적, 성능은 공백
> - **170개 이상 다국어 모바일 앱** + **네이티브 데스크톱 OS**
> - 태스크는 *deep-research 파이프라인*으로 **기능 기반(function-grounded) 지시문 생성**
> - 모바일·웹·데스크톱을 **하나의 폐루프 추론-행동 프레임**으로 통합
> - **오픈소스**임을 명시(*"By offering a capable, efficient, and **open-source** foundation"*)
> - 안전: *"consequential actions"*(결과를 되돌리기 어려운 행동)에 대한 **안전 인지 메커니즘 통합**을 언급 — 다만 **구체 메커니즘 미기재**
>
> "170개 이상"처럼 **셀 수 있는 것은 숫자로 적었는데, 성능은 하나도 숫자로 적지 않았다.** 이 비대칭 자체가 정보다.

> [!warning] ⚠️ 저자 31인 · 데일리 3위 · 벤치마크 점수 **0개**
> 초록에 **점수·비교 모델·모델 크기가 전량 부재**하다. GUI 에이전트 분야에는 ScreenSpot·AndroidWorld·OSWorld 등 확립된 벤치가 여럿 있는데 **이름조차 언급되지 않는다.**
> "Technical Report"라는 제목상 본문에 표가 있을 개연성은 [[Qwen-Drive-1.0]]보다 높다. 그러나 **초록 단계에서는 능력 수준을 판단할 근거가 없다.**
> 미기재: 벤치명 · 절대/상대 점수 · 모델 규모 · 베이스 모델 · 가중치 공개 범위(오픈소스라 했으나 코드/가중치/데이터 중 무엇인지 불명) · 안전 메커니즘의 실체 · 평가자 투표에 쓰인 모델 구성.

> [!question] 🎯 이번 배치에서 처음 잡힌 상관 — **저자 수와 수치 제시가 반비례한다**
> 5편을 저자 수로 정렬하면 경계가 깨끗하게 갈린다.
> - **수치 없음**: [[UI-Venus-2]] **31인** · [[Safin-1]] **18인** · [[Qwen-Drive-1.0]] **16인**
> - **수치 있음**: [[SMELT]] **9인** · [[DiagEvo]] **8인**
>
> **16인을 경계로 완전 분리된다.** 표본 5개이므로 **상관이지 인과가 아니며, 우연일 수 있다**(무작위로 이 분리가 나올 확률도 무시할 수준은 아니다). 그러나 그럴듯한 기전은 있다 — 대형 팀 = 기업 대형 프로젝트 = **기술 보고서형 발표**로 초록이 홍보문에 가깝고, 소형 팀 = 학술 논문형 = 초록에 핵심 수치를 넣어 심사를 통과해야 한다.
> **판정 보류.** 볼트 규칙 *"단일 시점의 방향 전환은 2회 연속 확인 전까지 해석하지 않는다"*(08-31 신설)를 적용해, **다음 배치에서 재현되면 관측 규칙으로 승격**한다.

## 도메인별 추출 (ai-news)

- **신뢰도**: **high**(문헌·주장) / **능력 수준은 판단 불가**.
- **즉시 활용**: **간접**. GUI 자동화는 현재 내 작업 대상이 아니나, **"채점기를 학습 축으로 취급한다"** 는 발상은 볼트의 자체 검증 절차(수치 교차 확인·드리프트 규칙)와 같은 계열이다.
- **6개월 영향력**: **중**. 오픈소스라면 실측 가능해지므로 재평가 여지 큼. 수치 부재는 초록의 문제이지 모델의 문제가 아닐 수 있다.
- **대체 관계**: 플랫폼별 개별 GUI 에이전트를 **단일 폐루프 프레임으로 통합**.
- **허와 실**: 걷어내면 = **"환경·태스크·검증 3축 확장 + 다중모델 투표 채점기"**. 검증 축 승격이 실질 기여이고, 나머지는 규모 확장이다.
- **액션**: [[actionable]]에 **① 본문 수치 확인 대기** · **② "저자 수 ↔ 수치 제시" 가설 다음 배치 재현 검사** 등재.
