# open-code-review — 이 배치에서 자체 벤치마크를 가진 유일한 레포

**제공**: [[Alibaba]] · OpenSSF Best Practices **Gold** 배지(배치 유일)

> [!insight] 핵심 인사이트
> **공급자가 스스로 지표를 분해해 자기 약점을 지목했다.** 범용 에이전트(Claude Code) 대비 **Precision·F1 은 높고 토큰은 ~1/9, 시간은 더 짧지만 Recall 은 더 낮다** 고 명시하며 *"노이즈보다 정밀도를 택한 의도적 트레이드오프"* 라 한다.
> ⇒ ⚖️ **[[복합지표-분해]] 의 자발적 사례 — 금일 최선명.** 대부분의 소스가 유리한 축만 남기는 자리에서 불리한 축(Recall)을 먼저 적었다. → [[숨김유인-부호]] 반례 후보.

> [!insight] 자체 벤치 구성이 구체적이다
> *"50개 인기 오픈소스 레포 · 실제 PR 200건 · 10개 언어 · 선임 엔지니어 80명+ 교차검증 · 정답 이슈 **1,505건** 주석"*
> 📌 **실세계 코드리뷰 벤치를 선언한다.** 저자 자작 벤치이므로 [[측정도구-먼저-반증]] 대상이지만, **구성 수치를 공개한 점은 이 배치 최고 수준**이다.

> [!warning] 🔴🔴 그런데 수치 표 자체가 이미지다
> `imgs/benchmark-en…` — **README 본문의 정량값은 `~1/9 토큰` 과 벤치 구성 수치(50/200/10/1,505)뿐이고 Precision·Recall·F1·Avg Time 의 실제 값은 텍스트로 없다.**
> ⇒ 🆕 **[[벤치마크-이미지-봉인]] 재발 1건**(09-26 신설 개념). **볼트 확인 필요: 이미지 OCR 또는 벤치 레포 원본.**

## 도메인별 추출 (ai-news)

- **신뢰도**: ⭐⭐⭐⭐ — Apache-2.0 · OpenSSF Gold · 벤치 구성 공개. 🔴 **단 핵심 수치가 이미지에 봉인**돼 검증 경로가 끊긴다.
- **즉시 활용**: 🎯 **YES — 금일 2순위 actionable.** Git diff 기반이고 **줄 단위 위치가 붙은 리뷰 코멘트**를 낸다. 볼트가 쓰는 `/code-review` 와 **직접 비교 대상**이다(결정론 룰셋 + LLM 병행 구조).
- **6개월 영향력**: "LLM 리뷰 vs 정적분석" 이항 선택이 **"둘을 한 파이프라인에 넣고 각각의 Precision/Recall 을 따로 본다"** 로 바뀐다. 토큰 1/9 주장이 사실이면 리뷰 비용 구조가 달라진다.
- **대체 관계**: 범용 코딩 에이전트의 리뷰 용도를 **부분 대체**한다(Recall 은 더 낮다고 자인하므로 완전 대체 아님).
- **허와 실**: 🏆 **구조 분리가 명확하다** — 결정론 파이프라인(NPE·스레드 안전성·XSS·SQL 인젝션 다언어 룰셋)과 LLM 에이전트를 함께 돌리고 **코멘트 위치 모듈과 코멘트 반추 모듈을 외부에 따로 둔다.** ⇒ [[요약자와-판정자-분리]] 의 코드리뷰 구현체다.
