> 🔴 **모든 instruct 수치의 성립 조건**: **`reasoning_effort=100`(최대)**. 코드 에이전트 벤치는 **DeepSeek 자체 하네스 Minimal 모드 + 1M 컨텍스트**, 시각 에이전트 벤치는 **Claude Code 하네스 + 512k**. **하네스가 벤치마다 다르다** — 같은 표 안에서 측정 환경이 바뀐다.
> 구조 재확인: **Causal Encoder-Decoder(CED)** — 40층 = 인과 인코더 20 + 디코더 20, 디코더 전역 KV를 **인코더 최종 은닉상태에서 투영**. 552B에서 **prefill 8B · decode 16B만 활성**. KV 캐시 V4-Flash 대비 **~4배**, V1 대비 **437배** 축소(Figure 1b). 컨텍스트 **100만**.
> 🔗 같은 배치 [[SAS]] 가 **직교 축**을 다룬다 — 이쪽은 *"KV를 얼마나 작게 저장하나"*, SAS는 *"주어진 예산으로 무엇을 볼까"*. **합성 가능하다.**

> [!insight] 핵심 인사이트 — 이 모델이 산 것은 **능력이 아니라 입력 단가**다
> **552B 백본 MoE · 최대 1M 토큰 컨텍스트 · 멀티모달**(`pipeline_tag: image-text-to-text`, 자체 학습 DeepSeek-ViT 비전 인코더).
> 구조의 핵심은 두 가지 압축이다:
> - **CED 구조**(20층 인과 인코더 + 20층 디코더) → **프리필 시 토큰당 8B, 디코딩 시 16B만 활성화**
> - **CSA2**(Full/Reindex/Reuse 3모드) + **FP4 메인 KV 캐싱** → 글로벌 KV 캐시 **토큰당 890바이트**
>   - [[DeepSeek-V4-Flash]] 대비 **약 1/4**, V1 대비 **437배 축소**
> - 45T 멀티모달 토큰 사전학습 · 추론 노력도를 **1~100 정수로 연속 조절**
> → 🎯 **컨텍스트가 길수록 KV 캐시가 비용을 지배**한다. 890B/token이면 1M 컨텍스트에서 KV가 ~890MB — 이게 이 모델의 전체 논지다.

## 도메인별 추출 (local-llm)

- **실용성 판단**: **로컬 불가.** 763B 체크포인트는 소비자 하드웨어 범위 밖이다. 같은 배치 [[colibri]] 의 전문가 스트리밍을 쓴다 해도 **0.05~1 tok/s 구간**. → **API로 쓸 모델**이지 로컬 모델이 아니다. 볼트 `local-llm` 분류는 **아키텍처 학습 가치** 때문에 유지.
- **메모리 아키텍처**: **이 모델의 전부다.** CSA2 3모드 + FP4 KV → 890B/token. [[에이전트-메모리-레이어]] 관점에서 **"컨텍스트를 외부화하지 않고 압축해서 안에 두는" 노선**의 현재 최전선. RAG와 정면으로 다른 답.
- **Hermes 적용**: **직접 불가.** 단 설계 원칙은 이식 가능 — **긴 입력을 다루는 에이전트에서 KV가 비용을 지배**한다는 진단은 내 파이프라인에도 해당한다. 컨텍스트를 줄이는 대신 **압축률 높은 백엔드를 고르는** 판단 기준이 생긴다.
- **트레이드오프**: **명확하고 측정돼 있다** — KV 890B/token·활성 8~16B ↔ **HLE −19.5 · TB4.0 −20.6**. 압축이 공짜가 아니라는 것을 벤치가 보여준다.
- **오픈소스 구현체**: **MIT** · gated=False · HF 공개. 파라미터 정밀도 BF16/F32/F8_E4M3/I8 혼합.

> [!action] 당장 할 것
> **"KV 캐시 비용"을 내 판단 기준에 추가한다.** 지금까지 모델을 고를 때 파라미터·벤치만 봤다. 긴 컨텍스트를 쓰는 워크로드(이 위키 인제스트 포함)에서는 **토큰당 KV 바이트**가 실질 비용을 결정한다. 쓰는 API의 이 수치를 확인할 것.

> [!question] 미해결 질문
> **Engram 조건부 메모리 196B의 작동 방식**이 카드 수준에서 불명확하다. 희소 접근이면 **접근 패턴에 따라 실효 지연이 달라질 텐데** 그 수치가 없다. 그리고 TB 2.1(90.6) → TB 4.0(31.2)의 붕괴 원인이 **컨텍스트 압축 때문인지 학습 데이터 시점 때문인지** 카드로는 구분 불가.
