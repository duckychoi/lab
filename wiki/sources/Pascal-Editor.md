# Pascal Editor

> [!insight] 핵심 인사이트
> **에이전트가 조작할 수 있는 3D 저작 도구**를 로컬 우선으로 만든 사례. `npx @pascal-app/cli editor` 하나가 에디터와 **인증된 MCP 서비스**를 동시에 띄우고, 충돌 없는 루프백 포트를 자동 선택하며, 프로젝트는 `~/.pascal/data/pascal.db` 에만 남는다. **계정·API 키 불필요, 자동 업로드 없음.**
> → MCP가 "채팅에 도구 붙이기"를 넘어 **GUI 애플리케이션의 조작 인터페이스**로 쓰인 형태.

> [!insight] 🎯 이 배치에서 가장 배울 점 — 스킬이 자기 능력에 상한을 건다
> `furniture-fit` 스킬은 카드에 **자기가 하지 않는 것을 먼저 못박는다**: *"높이·개폐·배송 검증을 주장하지 않는, 경계가 명시된 근거 기반 **설치면적** 평가"* 만 산출한다.
> 더 중요한 건 실행 규약이다 — 스킬이 **MCP 툴 스키마를 먼저 조회해 옵션 필드 유무를 확인**하고, 없으면 **더 좁은 결과를 보고**하도록 규정한다.
> → **"레포에 기능이 있어도 설치된 릴리스에는 없을 수 있다"를 전제한 설계.** 대부분의 스킬은 레포 최신 상태를 가정하고 깨지는데, 이건 런타임에 확인한다.
> → 내 스킬 작성 규약에 바로 이식 가능한 패턴 → [[에이전트-스킬]]

> [!note] 구성
> React Three Fiber + **WebGPU** 기반 로컬 우선 3D 건물 에디터. 공개 에이전트 스킬은 **2개**(`pascal-3d`, `furniture-fit`) — 수가 적다는 것은 곧 **표면적이 좁고 검증됐다**는 뜻이기도 하다.

> [!warning] 운용 제약 — README가 스스로 밝힌 것
> - **로컬 CLI 서비스당 활성 에이전트 클라이언트 1개.** 로컬 HTTP 런타임이 씬 상태를 공유하므로 **병렬 에이전트 불가**.
> - npm `beta` 태그(`1.0.0-beta.1`)가 **레포보다 뒤처져** 있어 신규 기능은 GitHub 프리릴리스 수동 설치 필요.
> - README 자인: *"레포 패키지는 엔드포인트·OAuth·도메인 검증·포털 스캔이 **심사 준비됐음을 증명하지 않는다**."*
> → **자기 한계를 명시하는 드문 README.** [[PI-Desktop]] 의 샌드박스 자인과 같은 계열.
