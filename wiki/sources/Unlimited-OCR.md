> [!note] 2026-07-16 갱신

> [!insight] 핵심 인사이트
> Baidu가 공개한 3B 비전-언어 OCR/문서 파싱 모델. **HF 다운로드 1.43M (2026-07-12, 좋아요 1.94k) ← 885k (07-03, 1.67k) ← 630k (07-01) ← 429k (06-30).** 143만 돌파·좋아요 1.9k로 실사용층이 확고히 형성, 커뮤니티 Spaces 33개. 모델카드 확인 결과 **"One-shot Long-horizon Parsing"**을 표방하며 [DeepSeek-OCR](https://github.com/deepseek-ai/DeepSeek-OCR)을 한 단계 밀어붙이는 것을 목표로 함 — arXiv 논문(2606.23050), vLLM 추론·Baidu Cloud API 지원, PDF(pymupdf) 다중페이지 처리. **ParseBench 평균 46.17, 텍스트 추출 86.81로 강하나 포맷 보존은 0.97로 서식 재현이 약점.** OCR은 위키 인제스트에서 *스크린샷·PDF·이미지 소스를 텍스트로 끌어들이는 입력 게이트*라 직접 효용이 있음.

## 도메인별 추출 (ai-news)

- **신뢰도**: ⭐⭐⭐ — Baidu 공식 + arXiv 논문 + HF 885k DL(5일 연속 폭증)로 관심도·실체 입증. ParseBench 수치는 자체발표라 잠정, 한국어·표·수식 정확도와 라이선스는 여전히 미확인.
- **즉시 활용**: YES(후보) — 내 위키 파이프라인에 이미지/PDF 소스를 텍스트화하는 단계가 필요. [[mark-clean]]이 웹 HTML 담당이라면 OCR은 이미지·스캔·PDF 담당. 텍스트 추출 86.81은 순수 추출용으로 실용적 수준. 한국어 정확도 검증 시 인제스트 입력 확장.
- **6개월 영향력**: 문서 AI는 RAG·지식베이스의 입력 품질을 좌우. 고정밀 오픈 OCR은 [[olmocr]]·[[MinerU]]·[[markitdown]] 류 수집 레이어를 이미지·PDF 영역으로 보강. DeepSeek-OCR 대비 우위 주장은 독립검증 대상.
- **대체 관계**: [[olmocr]], [[MinerU]], [[PaddleOCR]], Tesseract, [[markitdown]]의 OCR 단계 대체/보강. 3B 비전-언어라 레이아웃 이해가 강점이나 **포맷 보존 0.97로 서식 재현(표/수식 마크다운화)은 전용 파서 대비 약함**.
- **허와 실**: "Unlimited"는 마케팅. 텍스트 추출(86.81)은 강하지만 포맷 보존(0.97)이 낮아 표·서식이 살아있는 마크다운이 필요하면 별도 후처리 필요. 손글씨·저해상도 한계 확인 필요.
- **액션**: 한국어 표/스캔/PDF 샘플로 텍스트추출 vs 포맷보존 각각 테스트 → 순수 추출은 편입, 서식 재현은 [[MinerU]] 등과 조합 검토.

> [!warning] 자체발표 벤치 — 독립검증 전까지 잠정
> ParseBench 평균 46.17·텍스트추출 86.81·포맷보존 0.97 및 "DeepSeek-OCR 한 단계 개선" 주장은 Baidu 자체발표. 특히 포맷 보존 0.97은 서식 재현이 약하다는 신호이므로 표/수식 재현이 중요한 워크로드엔 부적합할 수 있음.

> [!question] 미해결 질문
> 한국어/표/수식 정확도? 최대 처리 해상도·문서 길이? 라이선스(상업 사용 가능)? 추론 비용(3B라 낮을 것으로 추정)?

> [!action] 당장 할 것
> HF Spaces 데모 또는 vLLM로 한국어 표/스캔 PDF 샘플 정확도 테스트 → 순수 텍스트추출 합격 시 위키 인제스트의 이미지·PDF 입력 단계에 편입.
