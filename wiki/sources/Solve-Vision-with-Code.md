**논문**: arXiv 2611.34813 · 업보트 **61**(수집기 11-28 = 볼트 API 일치) · Carnegie Mellon University

## 핵심 인사이트
> [!insight] "영상을 볼 줄 아는가"의 최강자는 영상 모델이 아니라 코드를 짜는 에이전트였다
> 첫 프레임 + 질문만 주고 **정답 영상**을 만들어야 하는 과제(VBVR-Pro-Bench 500)에서 코딩 에이전트가 영상 모델을 압도: **Codex(gpt-6-astra) 0.923 · Claude Code(Fable 5.1) 0.894 · Gemini CLI(Gemini 3.1 Pro) 0.893** — 최고 영상 모델보다 각각 **0.22p 이상** 높음. 오픈웨이트 최고는 GLM-5 0.572(클로즈드 에이전트와 격차 큼).

> [!warning] 결론의 적용 범위는 저자 스스로 제한했다 — [[자기제한-명시]] 표본
> 이 우위는 **"첫 프레임+프롬프트로 도구 사용으로 계산 가능한 과제"** 한정 — 저자 명시. 일반 영상 이해(실시간 스트리밍 · 자연어 서술) 전반으로 확장 불가. 벤치 설계 자체가 "계산 가능성"을 favor하므로 영상모델에 불리한 구조.

## 도메인별 추출 (ai-news)
- **즉시 활용**: 영상 분석이 "프레임 추출 + 측정 + 비교"로 분해되는 과제라면 에이전트 + 도구 조합이 SOTA — 파이프라인 설계 시 영상 VLM에 바로 넣기 전 분해 가능성 검토.
- **설계 교훈**: 과제 형태가 도구 사용과 일반 지각 중 어느 쪽을 favor하는지가 리더보드 해석을 바꿈 — [[복합지표-분해]] 의 벤치 버전.
- **6개월 영향력**: "비전도 에이전틱하게" 흐름 강화 — [[하네스-설계-축]] 과 결합해 영상 과제용 에이전트 프레임워크 경쟁 예상.
