## 도메인별 추출 (video-saas)

- **기능 벤치마킹**: 🎯 **구현 난이도가 갈린다** — 2D 레이어 컴포지팅은 웹에서 가능하고, **3D 캐릭터 포징·카메라 배치는 씬 그래프 + 뷰포트가 필요**해 Rust 데스크톱을 택한 이유로 보인다. 볼트 `reat` 파이프라인([[reat-layout]]·[[reat-scene]])은 **이미 stack_root JSON 트리로 레이아웃을 구조화**하므로 **"입력을 구조로 고정한다"는 같은 방향**이다 ⇒ 📌 **차이는 3D·카메라 축의 유무**다.
- **크리에이터 인사이트**: 사용자가 원하는 것은 "더 좋은 프롬프트"가 아니라 **같은 결과를 두 번 내는 것**이다. 입력을 씬으로 고정하면 재현성이 생긴다 — ⚖️ **단 본 레포가 재현성 수치를 제시하지 않았다.**
- **프롬프트 패턴**: 🔴 **해당 없음 — 이 레포의 주장이 곧 "프롬프트 패턴을 줄인다"다.**
- **워크플로우**: 컴포지팅 → 포징 → 카메라 → 생성. 🔴 **단계별 화면 기록은 미확인**(데모 영상 미열람).
- **디자인 레퍼런스**: 🔴 미확인 — 데모 영상을 보지 않았고 UI 수치(레이아웃·색상·타이포)를 추출하지 않았다. 볼트 video-saas 템플릿의 **시각 분석 항목을 집행하지 못했다.**
- **경쟁 우위 빈틈**: 🎯 **생성 전 단계가 비어 있다** — 기존 툴은 프롬프트 입력창에서 바로 모델로 간다. 그 사이에 **씬 편집기**를 넣은 제품은 드물다. ⚖️ 단 Apache-2.0 이므로 빈틈이 오래 남지 않는다.
