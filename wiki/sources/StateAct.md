# StateAct (Program State before Pixels, 논문 2607.22798)

> [!insight] 핵심 인사이트
> 컴퓨터 사용 에이전트가 **스크린샷(픽셀) 대신 프로그램 상태를 우선 접지**하도록 뒤집은 프레임워크. HF 논문 2607.22798·업보트 **42**. [[Salesforce]] AI Research(Yan Yang 외). 핵심 주장: 렌더링은 손실적(lossy)이라 **숨은 행·수식·오프스크린 데이터**를 놓친다 → 코드로 **파일·앱 백엔드·DOM 구조를 직접 조회**하고, 시각이 진짜 필요한 **1.1% 스텝에서만 GUI 서브에이전트** 호출, 완료는 **독립 검증 게이트가 실제 아티팩트를 점검**해 확인. 통찰: *"상태 접지는 주 병목을 지각→추론으로 옮긴다 — 실패가 '무엇을 보는가'보다 '무엇을 생각하는가'에 더 좌우"*. OSWorld 2.0에서 **바이너리 26.9%·부분 61.6%·태스크당 ~$7.80(~9배 저렴)**, 참조모델(Claude Opus 4.8) 대비 +6.3%p, 이전 공개 최고(Claude Opus 4.7 18.2%) 대비 +8.7%p. 07-22 [[StateAct 계열|프로그램 상태 우선]] 흐름이 07-27 [[impeccable]]·[[open-code-review]] "결정론 보강"과 만나 **"픽셀 추론 대신 구조 접지 + 검증 게이트"**로 수렴.

> [!warning] 자체발표 벤치 · 미래형 ID
> OSWorld 2.0 수치·비용·비교(Claude Opus 4.7/4.8 대비)는 초록 WebFetch 실확인이나 **저자 자체 리포트**로 독립 재현 전. 논문 ID(2607.22798)가 미래형이라 원문 검증 불가 medium. 바이너리 26.9%는 **컴퓨터 사용 태스크의 절대 난이도가 여전히 높음**을 보여줌(부분 61.6%와 큰 격차).

## 도메인별 추출 (ai-news)

- **신뢰도**: ⭐⭐ — 초록·수치·비교 WebFetch 실확인, 자체발표·미래형 ID로 medium.
- **즉시 활용**: 설계 참고 — 내 스케줄·브라우저 자동화(lightpanda)가 사실상 컴퓨터 사용. **"스크린샷보다 DOM/파일 상태 직접 조회 + 완료를 아티팩트로 검증"**은 즉시 이식 가능한 원칙(스크린샷 토큰·오탐 절감).
- **6개월 영향력**: 컴퓨터 사용 에이전트가 "화면 보고 클릭"에서 **구조 접지(DOM/파일/백엔드) + 검증 게이트**로 이동하는 신호. 픽셀 의존을 1.1%로 낮춰 비용 9배 절감은 실용화 압력.
- **대체 관계**: 순수 스크린샷 VLM 에이전트 대비 **상태 접지로 비용·신뢰성** 우위. [[impeccable]]·[[open-code-review]](결정론 감사)·[[StateAct 계열]]과 "LLM 판단을 구조/검증으로 게이트" 공유.
- **허와 실**: 바이너리 26.9%는 여전히 낮아 "해결"이 아님 — 가치는 **비용 9배 절감 + 검증 게이트로 구조적 실패 포착**. "픽셀보다 상태"는 GUI 없는/API 있는 앱에 유리, 순수 시각 태스크엔 여전히 GUI 필요.
- **액션**: 내 브라우저 자동화에 "**DOM/파일 상태 직접 조회 우선 + 완료를 산출물로 검증**" 패턴 적용해 스크린샷 의존·토큰 절감 실험.

> [!action] 당장 할 것
> lightpanda 기반 브라우저 작업에서 **스크린샷 대신 DOM 상태 우선 조회 + 완료 검증 게이트(실제 산출물 점검)** 패턴을 스팟 적용해, 토큰·오탐 절감 효과 실측.
