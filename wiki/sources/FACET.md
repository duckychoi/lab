# FACET — Preserving Source Intent and Executable State in Terminal Task Synthesis (HF 데일리 2위·업61)

**HF Papers**: https://huggingface.co/papers/2608.18580
**지표**: 업보트 **112** (2026-08-23 HF API 실검증) ← 61(최초 수집) (HF 데일리 **2위**) · arxiv **2608.18580**(미래형 ID) · **도메인**: ai-news (agent-cli)

> HF 업보트 **112** (2026-08-23 HF API 실호출) ← 111(08-22). 이틀 **+1**로 **완전 정체**. 데일리 2위 유지.
> 초록 원문 재대조로 확정한 구조: 터미널 태스크 하나는 **지시문·초기화된 환경·참조 해법·실행 가능한 verifier 4종 산출물**의 결합인데, 이들이 **서로 다른 가정에서 생성되면 풀 수 없거나 잘못 채점되는 태스크**가 나온다. FACET은 (1) 에이전트 스킬을 일관된 정보 밀도 높은 시나리오로 재구성하고 (2) **최종 산출물 생성 전에 실행 환경을 먼저 실현·수리**해, 그 **컨테이너 상태를 지시문·해법·verifier의 공유 기준점(shared grounding)**으로 삼는다. 실행 기반 검증으로 **실패한 산출물만 표적 수리**하고 멀쩡한 것은 재생성하지 않는다 — 합성 비용 절감의 핵심.
> ⚠️**성능 수치는 초록에 미기재**: "다중 스케일 모델 파인튜닝에서 **Terminal-Bench 2.1 성능이 일관 향상**"이라는 방향성만 있고 구체 점수가 없다. 08-22 기록과 동일하게 **정량 주장 금지** 상태 유지.
> [[EnvHarness]]가 *환경을 감싸 재구성*한다면 FACET은 *태스크 자체를 처음부터 합성*한다 — 같은 병목(학습용 실행 감독의 부족)에 대한 상보적 두 접근.

> *공통 유의(2026-08-23): HF 데일리 페이퍼는 **최신 배치가 2026-08-21에 멈춰 있어** 08-22·08-23 요청 시에도 동일 목록을 반환한다(주말 미갱신). 따라서 이번 배치 논문 5건은 **신규 발표가 아니라 기존 인제스트 항목의 업보트 재수집**이며, 순위 역시 08-21 배치 기준이 그대로 유지된 값이다.*

> [!insight] 핵심 인사이트
> **터미널 태스크를 합성(생성)할 때 원 의도(source intent)와 실행 상태(executable state)를 함께 보존**하는 방법 — 에이전트 학습·평가용 터미널 태스크를 자동 생성하되, "무엇을 하려 했는가(의도)"와 "실제로 실행 가능한 상태인가(파일시스템·프로세스·환경)"가 어긋나지 않게 붙잡는다. 그간 위키의 CLI 에이전트 축([[CLI-Anything]] 기존 SW를 에이전트-네이티브 CLI로 래핑·[[CLI-Universe]])이 "조작 인터페이스"였다면, FACET은 그 위에서 **"에이전트를 훈련·평가할 터미널 태스크 데이터를 신뢰성 있게 찍어내는" 공급 쪽 문제**를 다룸 — [[EnvHarness]](정적 월드→학습 환경)와 같은 배치 1·2위로, "환경·태스크 공급의 충실도"가 이 배치의 공통 주제임을 보여줌. 검증 게이트로 코드 생성 신뢰성을 잡는 [[SemaPLC]]와도 "생성물의 실행 가능성 보증"에서 결이 맞닿음.
