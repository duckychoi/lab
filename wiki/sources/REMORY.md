# REMORY: Learning Residual Memory for Context Compaction

**HF 논문**: https://huggingface.co/papers/2610.11287 · **arXiv 2610.11287** · 공개 2026-10-08 · 업보트 **40**
✅ **본문 열람(HTTP 200)** — 초록 수치(5.2%)만으로 손익 구조를 알 수 없어 Table 1~3 추출.
방법: 텍스트 요약 **뒤에 소프트 메모리 토큰을 덧붙여** 압축 손실을 복구한다. **동결 LLM** 기준 · 입력 위치의 **5.2%** 만 사용 · 시퀀스 방향 residual connection 유사 구조.

> [!insight] 🏆🏆 **[[복합지표-분해]] 확증 사례 — 종합 점수 동급의 내부는 정반대다**
> **SummHay 실측(동일 92개 질의, Table 1)**:
>
> | 설정 | Coverage | Citation F1 | **Joint** |
> |---|---|---|---|
> | Raw context(전체) | **72.46** | 56.60 | **43.41** |
> | Summary | 67.55 | 56.98 | 39.84 |
> | Summary++ | 67.52 | 56.94 | 39.78 |
> | **Summary + REMORY** | 67.95 | **61.03** | **43.39** |
>
> ⚖️ **초록의 *"approaches the full-context joint score"* 는 참이다** — 43.39 vs 43.41, 차이 **0.02**.
> 🎯 **그러나 분해하면 구조가 완전히 다르다**: Citation F1 은 전체 컨텍스트를 **넘고**(61.03 > 56.60 = **+4.43**), Coverage 는 **못 미친다**(67.95 < 72.46 = **-4.51**).
> ⇒ 🏆 **Joint 동급은 성능 동급이 아니라 두 반대 방향 오차가 거의 정확히 상쇄된 결과다**(+4.43 과 -4.51 의 합이 거의 0).
> 📌 **이것이 10-10 [[Learn2Play]](Max 는 인간 우위 · Mean 은 에이전트 우위)와 같은 구조이고, 여기서는 상쇄가 소수점 둘째 자리까지 맞아떨어져 더 선명하다.**

> [!insight] ⚖️ 그런데 초록이 스스로 분해해 적었다 — [[숨김유인-부호]] 정방향
> 초록은 *"improves source attribution at nearly unchanged insight coverage"* 로 **두 축을 따로 적는다.**
> 🎯 **부호상 정직하다**: **요약 대비로는** 커버리지 유지가 맞다(67.55 → 67.95, +0.40). ⚖️ **"전체 컨텍스트 대비 -4.51"을 적지 않은 것은 비교 기준을 요약으로 둔 것이고, 그 기준은 논문의 과제 설정(압축)과 일치한다.**
> ⇒ 📌 **따라서 이것은 은폐가 아니다.** 10-10 에 세운 규약(*"반례는 그 서술이 저자에게 이득인가로 등급을 매긴다"*)을 적용하면 **저자가 자기 약점 축을 먼저 쪼개 보여준 쪽**이다.

> [!insight] 🏆 가장 큰 변화는 점수가 아니라 "재시도 낭비 제거"다
> **BrowseComp 도구 출력(Table 3)**: 반복 **25,801 → 18,105**(**-29.8%**) · 오류 **25,244 → 12,698**(**-49.7%**)
> **Terminal-Bench 오류**: 933 → 568(**-39.1%**)
> 🎯 **점수 상승폭(74.0 → 77.0 = +3.0)보다 오류 감소폭(-49.7%)이 압도적으로 크다.**
> ⇒ 🆕 **[[claude-mem]] 전제에 대한 3번째 압박 축이다**: 메모리의 효과가 *"정답률 상승"* 이 아니라 **"같은 실수를 다시 하지 않음"** 으로 먼저 나타난다. 📌 **볼트가 [[claude-mem]] 에 요구해 온 측정은 정답률이었고, 이 논문은 그 요구 자체가 잘못된 축일 수 있다고 말한다.**
> 선행 2건: 10-10 [[MemAdapter]](올바른 메모리조차 아첨 유발) · 10-10 [[Learn2Play]](전체 기록 보존 > 요약).

> [!insight] 비용이 같이 내려간다 (하네스 축의 비용 판본)
> **에이전트 벤치(Table 2, [[Qwen3.8-27B]], 5회 평균±표준편차)**: AutomationBench 35.5±1.3 → **45.3±1.0**(비용 **$0.59 → $0.53**) · JobBench 33.4±1.25 → **41.0±1.41**(비용 $3.09 → $3.21)
> **Table 3(1회 실행)**: Terminal-Bench 2.1 [[Qwen3.8-27B]] 71.9 → **76.4**(비용 **$4.29 → $2.86 = -33.3%**) · GLM-5.3-Flash 84.3 → **87.6** · BrowseComp 74.0 → 77.0 / 84.9 → 89.0
> 🎯 **점수가 오르면서 비용이 내려간 사례 2건**(AutomationBench · Terminal-Bench)인데 **JobBench 는 비용이 올랐다**($3.09 → $3.21) ⇒ ⚖️ **비용 개선은 보편이 아니다.** 10-10 [[Learn2Play]] 토큰 56% 절감과 같은 방향이지만 **여기서는 반례가 같은 표 안에 있다.**

> [!warning] 🔴 Table 3 은 구성당 1회 실행이다
> 저자가 명시한다. Table 2 의 표준편차가 **±1.0~1.41** 이므로, **Table 3 의 차이 3.0~4.5 는 분산 범위를 넘지만 여유가 크지 않다**(약 2~3σ).
> ⇒ [[유의성-자기제한]] — 저자가 1회 실행임을 **스스로 적은 것은 정방향**이지만, **그 수치로 결론을 세운 것은 별개 문제**다. 📌 **GLM-5.3-Flash 84.3 → 87.6(+3.3)은 1회 실행이므로 볼트는 확정으로 쓰지 않는다.**
> 🔴 **교차 주의**: 같은 Terminal-Bench 2.1 에서 본 논문은 [[Qwen3.8-27B]] 71.9 를 적고 같은 배치 [[MiMo-V2.6-Tech-Report]] 는 MiMo Pro **89.9** 를 적는다 — **하네스가 다르므로 직접 비교 불가** → [[하네스-설계-축]].

## 도메인별 추출 (local-llm / agent-memory)

- **실용성 판단**: 🎯 **동결 LLM 기준이라는 것이 결정적이다** — 백본을 재학습하지 않고 소프트 토큰만 학습하면 **볼트급 환경에서 적용 가능성이 있다.** 🔴 단 소프트 토큰 학습 비용(GPU·시간·데이터량)이 추출 범위에 없어 판정 불가.
- **메모리 아키텍처**: **텍스트 요약 + 소프트 토큰 하이브리드**다. RAG(외부 검색)도 KV 캐시 압축도 아닌 **제3의 위치**: 요약을 버리지 않고 **그 잔차를 연속 벡터로 보강**한다.
- **Hermes 적용**: ⚖️ **직접 적용은 NO** — 소프트 토큰은 모델 내부 임베딩 공간에 넣어야 하므로 **API 모델에는 못 쓴다.** 📌 **그러나 설계 교훈은 바로 쓸 수 있다**: 요약을 "대체"로 쓰지 말고 **요약 + 원문 포인터 2층**으로 두라는 것이고, 이것은 10-10 [[Learn2Play]] 결론(전체 기록 보존 > 요약)과 같다.
- **트레이드오프**: 입력의 **5.2%** 로 Joint 43.39 vs 전체 컨텍스트 43.41 ⇒ 🎯 **약 19배 압축에 Joint 손실 0.02**. ⚖️ **단 커버리지는 -4.51 을 지불했다** — 압축비만 보면 무손실로 보이고, 분해하면 커버리지를 팔아 인용 정확도를 샀다.
- **오픈소스 구현체**: 🔴 **미확인** — 코드·가중치 공개 여부가 추출 범위에 없다. ⬜ 확인할 것.

> [!question] 미해결
> - 🔴 코드·가중치 공개 여부 미확인(이것이 "실용성"의 전제다).
> - 소프트 토큰 **개수**와 학습 비용 미확인.
> - SummHay 92개 질의의 도메인 구성 미확인 — 커버리지 -4.51 이 특정 질의 유형에 몰렸는지 알 수 없다.
> - 🔴 **Table 2 와 Table 3 의 실행 횟수가 다른 이유**(5회 vs 1회)를 저자가 설명했는지 미확인.
