# T1 (2609.11042)

> [!insight] 핵심 인사이트 — **보상을 사람이 아니라 「작업 자신의 검증기」가 준다**
> HF 업보트 **47**(2026-09-12 API 실호출 · raw와 **일치**) · published **2026-09-10** · 저자 **7인**(Junyao Yang, Yucheng Shi, Zhongzhi Li, Ruhan Wang, Zongxia Li 외).
> 초록 원문: 총 **122B MoE** 모델이 **클라우드 샌드박스에서 실제 셸을 조작**하며 **작업당 300+ 툴콜 턴**까지 가고, *"rewarded by **executing each task's own verifier**"*.
> 🎯 이 설계의 요점은 규모가 아니라 **보상 신호의 출처**다. 사람 라벨도, 별도 리워드 모델도 아니고 **작업에 딸린 검증기를 실행한 결과**다. 게다가 dense process reward가 *"the **absolute number** of passing verifiers"* 로 궤적을 채점한다 — **부분 성공이 부분 점수로 들어온다.**
> → 같은 배치 [[hyperresearch]] 가 리서치 산출물에 **기계 검사 게이트**를 붙인 것과 **정확히 같은 발상**이다. 한쪽은 검사를 출고 조건으로, 한쪽은 검사를 **학습 신호**로 쓴다.

> [!note] 수치 — 초록 원문 대조 (raw 기록 전건 일치)
> - **Terminal-Bench 2.1**: 베이스 **43.8% → T1 64.0%** resolved (**+20.2p**)
> - **Long-Horizon Terminal Bench**: **27.9%** — *"surpasses **GPT-5.4 and GLM-5.1**"*
> - **학습-추론 로그확률 괴리**: TITO + R3 로 **0.021 → 0.013**, 손실 영역에서 *"exactly aligned **zero token drift**"*
> - 기법 3종:
>   - **공격적 웜스타트** — actor-critic 학습 안정화
>   - **TITO** — *"training on the **exact sampled token identifiers**"* + 턴 경계 드리프트 보정
>   - **R3(rollout routing replay)** — *"recording the sampler's **per-token expert choices at every MoE layer** and replaying them during training"* → **MoE 특유의 라우팅 불일치**를 정면으로 다룬 부분

> [!insight] 🎯 가장 인용 가치 높은 문장은 성능이 아니라 **오염 방어 설계**다
> 초록 원문: *"**fully out-of-distribution training corpus**: isolated seeds and synthesized tasks **disjoint from Terminal-Bench 2.1** ensures gains reflect **genuine capability transfer over benchmark overfitting**."*
> → raw도 이 점을 짚었다(*"학습 코퍼스를 벤치와 분리했다고 명시(과적합 방어)"*) — **정확하다.**
> → 그리고 이 문장이 **같은 배치 [[SWE-Bench-Pro-Verified]] 와 정면으로 맞물린다.** 저쪽은 *"기존 벤치가 유출·리워드 해킹으로 오염돼 점수가 부풀려졌다"* 를 실증했고, 이쪽은 *"우리는 학습 코퍼스를 벤치와 분리했다"* 를 선제 방어로 명시했다.
> → 🎯 **같은 날 두 논문이 벤치마크 신뢰성의 공급 측과 수요 측에 각각 서 있다.** 앞으로 에이전트 성능 수치를 읽을 때는 **점수보다 "학습·평가 분리를 명시했는가"** 가 1차 필터가 된다.
> ⚠️ 다만 **분리를 「명시했다」는 것과 「검증됐다」는 것은 다르다.** SWE-Bench Pro Verified가 보여준 대로 오염은 저자 선언이 아니라 제3자 감사로 드러난다. T1의 주장도 **현재는 자기 신고 단계**다.

> [!warning] 미확인 — 비용과 접근성
> 초록에 **없는 것**: 모델·코드·가중치 공개 여부, 학습 연산량, **활성 파라미터 수**(122B는 총합이고 MoE 활성치가 없다 → [[단위-불일치]] ③번 유형과 동일), 300+ 턴 실행의 추론 비용.
> → *"122B MoE"* 만으로는 **내가 돌릴 수 있는지 판단 불가**다. 온디바이스·로컬 관점([[local-llm]])에서는 현재 판정 불가.

## 도메인별 추출 (ai-news)

- **신뢰도**: ⭐⭐⭐ — HF API 업보트 실호출 + **초록 원문 전문 대조**. 베이스 대비 델타·경쟁 모델 비교·기법별 수치(0.021→0.013)까지 제시. 오염 방어를 명시 → **high**. ⚠️ 자기 신고 성격은 유지.
- **즉시 활용**: **NO.** 122B MoE 학습은 내 스케일이 아니다. 다만 **"작업 자신의 검증기로 보상한다"** 는 설계는 규모와 무관하게 이식 가능한 발상이고, 볼트에서는 **인제스트 결과를 원문 재대조로 자동 채점**하는 형태가 그 축소판이다([[hyperresearch]] quote-integrity 액션과 동일 목적지).
- **6개월 영향력**: 에이전트 RL의 병목이 **환경**(실제 셸 + 검증기 있는 작업)임을 다시 확인시킨다. 그리고 **MoE 라우팅 리플레이**는 MoE로 에이전트를 학습시키는 모든 팀이 마주할 실무 문제라 재사용될 기법.
- **대체 관계**: [[WMRL]]·[[AgentGrad]] 계열(에이전트 학습·개선)과 같은 축. GPT-5.4·GLM-5.1([[Zhipu AI]])을 **직접 비교 대상으로 지목**한 점에서 프론티어 모델의 터미널 능력에 대한 공개 도전.
- **허와 실**: 형용사가 적고 수치가 많다. 걷어낼 것은 *"comprehensive recipe"* 정도. 실질적 미확인은 **공개 여부와 활성 파라미터**다.
- **액션**: **Terminal-Bench 2.1 / Long-Horizon Terminal Bench 를 볼트 기준 벤치로 등록.** 앞으로 "터미널 에이전트가 강해졌다"는 주장을 볼 때 43.8 / 64.0 / 27.9 를 앵커로 쓴다.
