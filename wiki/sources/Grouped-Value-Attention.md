# Grouped Value Attention (GVA)

> [!insight] 핵심 인사이트 — **값만 저장하고 키는 필요할 때 만든다**
> GQA는 키·값 헤드를 공유해 비용을 줄이지만 **매 스텝 키와 값을 둘 다 저장**한다. GVA는 **값을 그룹 저장하고, 콘텐츠 키는 학습된 선형 사상으로 복원**한다. 추론 시 그 사상을 **쿼리에 흡수**시켜 의도된 디코드 경로에서 콘텐츠 키를 **물질화하지 않는다.** 위치 정보는 별도 캐시되는 **소형 decoupled RoPE 채널**이 담당.
> 효과: 매칭된 GQA 대비 **영속 캐시 스칼라 약 45~47% 감소**.
> 🎯 **볼트 [[에이전트-메모리-레이어]] 4분류(RAG / KV / 압축 / 외부DB)의 KV 항에서, 세 번째로 다른 공격법이다**:
> - [[Random-Attention]]([[Salesforce]]): KV **점수화가 무용**함을 증명 → *고르지 마라*
> - [[Declarative-Attention]]: 모델이 참조 범위를 선언해 **읽기를 건너뛴다** → *읽지 마라*
> - **GVA: 키를 아예 저장하지 않고 복원한다 → *두지 마라***
> **셋 다 "KV를 더 잘 압축한다"가 아니다.** 저장·선택·읽기라는 **다른 동사**를 각각 공격한다.

> [!warning] 🔴 저자가 직접 적은 두 개의 제약 — 둘 다 결론을 바꾼다
> 1. **정확도가 GQA보다 낮다.** 350M 파라미터 · FineWeb-Edu 30B 토큰에서 16차원 위치 변형이 5개 태스크 평균 **44.18**, GQA **44.36**, MLA **43.88**. 🎯 **GQA에 0.18 뒤지고 MLA보다 0.30 앞선다.** 초록의 표현도 우위가 아니라 *"**near-GQA** benchmark accuracy"* 다.
> 2. 🔴 **속도가 측정되지 않았다.** 초록 마지막 문장 원문: *"we have developed custom decoding kernels and **are currently evaluating their end-to-end inference performance** with an open-source release **planned soon**."*
> → **45~47% 캐시 감소가 실제 추론 속도 이득으로 얼마가 되는지 이 논문은 말하지 않는다.** 캐시 감소는 **메모리 축의 수치이지 시간 축의 수치가 아니다.**
> 📌 **[[단위-불일치]] 예방 사례다**: *"45~47% 감소"* 를 속도로 읽으면 안 된다. 볼트가 [[Declarative-Attention]] 에서 이미 같은 경고를 적었다 — *"-52.0%는 **참조 토큰이지 wall-clock이 아니다**"*. **같은 함정이 KV 축에서 두 번째로 나왔다.**

> [!warning] ⚠️ 규모 한정어 — 350M은 작다
> 초록: *"For the **configurations studied**"* · *"**At the 350M-parameter scale** with 30B FineWeb-Edu tokens"*.
> 🔴 **350M은 볼트가 다루는 대역(7B~27B)의 1/20~1/80이다.** GQA↔MLA↔GVA 의 서열이 규모에 따라 유지된다는 근거는 초록에 없다. 0.18 이라는 격차는 **이 규모에서만 측정된 값**이다.
> ✅ 저자가 두 한정어를 모두 명시적으로 달았다 — [[한정어-탈락]] 은 인용하는 쪽의 몫이다.
