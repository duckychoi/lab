# AgSpec — 코딩 에이전트 파이프라인용 검색 기반 추측 디코딩 (arXiv:2610.01108)

**HF**: https://huggingface.co/papers/2610.01108 · **arXiv**: 2610.01108
**지표(수집 2026-10-02 09:01:53 UTC / 볼트 실측 동일자)**: upvote **4**(**완전 일치, 드리프트 0**) · publishedAt **2026-10-01**(일치) · 저자 **4명**(일치) · 초록 **1,296자**(**완전 일치**)
**볼트 지위**: 🆕 **신규** — 언급 0회

> [!insight] 🎯 핵심 인사이트 — **에이전트의 "낭비"가 추측 디코딩의 연료라는 관점 전환**
> 추측 디코딩(speculative decoding)은 보통 **작은 초안 모델**을 쓴다. 검색 기반(retrieval-based) 변종은 모델 대신 **기존 텍스트를 복사**해 초안을 만든다. 📌 **코딩 에이전트는 이 방식에 구조적으로 유리하다** — 초록 원문: *"suits coding agents that **repeatedly reproduce code, logs, and earlier attempts**."*
> 🎯 **즉 에이전트가 같은 것을 또 뱉는 성질(= 보통은 비효율로 취급되는 것)이 여기서는 자원이 된다.** 볼트가 수집해 온 하네스 논의가 대부분 *"반복을 줄이자"* 였는데([[ponytail]] LOC −54% · [[PyRUA-Lean]] 토큰 −65%), **이쪽은 반복을 전제로 두고 그 위에서 속도를 번다.** 방향이 반대인 두 처방이 **같은 배치에 동시 도착**했다 → [[대립레시피-동시도착]].
>
> **기존 방법의 실패 2가지(초록이 직접 지적)**:
> 1. **코퍼스 문제** — *"much of the reusable text is **missing from their corpora** or **stored in a form that differs from what the agent emits**"* ⇒ 재사용 가능한 텍스트가 없거나, 있어도 **에이전트 출력 형식과 다르게 저장**돼 매칭이 안 된다
> 2. **초안 길이 문제** — *"their draft lengths **ignore that accept length varies across agents and drifts over turns**"* ⇒ 수용 길이가 **에이전트마다 다르고 턴이 갈수록 변하는데** 고정 길이를 쓴다
>
> **AgSpec 의 처방이 정확히 1:1 대응한다**:
> - 코퍼스 → **세션 · 워크스페이스 · 전역** 3계층 검색 + **진행 중 세션 궤적 보존** + **열린 파일을 에이전트 출력 형식으로 색인**
> - 초안 길이 → **오프라인 프로파일 상한** + **검증 피드백 기반 온라인 적응**
> 🎯 **"에이전트 출력 형식으로 색인한다"가 이 논문에서 가장 실용적인 한 줄이다** — [[포맷-불일치-오염]] 과 같은 뿌리다: 같은 내용이 다른 표현으로 저장되면 검색이 실패한다.

> [!insight] ✅ 정량 결과 — 초록 전수 대조 일치
> | 조건 | 자가회귀 대비 처리량 |
> |---|---|
> | batch size **1** | 최대 **4.37배** |
> | batch size **16** | **4.76배** |
> 🎯 **배치가 커질 때 배율이 떨어지지 않고 오른 것(4.37 → 4.76)이 눈에 띈다.** 추측 디코딩은 보통 배치가 커지면 이득이 줄어든다(검증 비용이 병렬성을 먹는다). 🔴 **단 초록에 이유가 없고 "최대(up to)" 한정어가 batch 1 에만 붙어 있다** — 4.76 에는 `up to` 가 없다. 📌 **[[한정어-탈락]] 역방향 주의: 한정어가 한쪽에만 붙은 것을 양쪽으로 퍼뜨리거나, 양쪽에서 떼면 둘 다 왜곡이다.** 원문 그대로 보존한다.
> **비교 대상**: 검색 기반 드래프터 **5종** 및 **EAGLE-3** 대비 *"in **most** evaluated settings"* 우위. ✅ 적용 범위: 레포·멀티에이전트 **없는** 벤치에서도 유효(*"gains generalize to coding agents broadly"*).

> [!warning] 🔴 봉인된 것 — 이름이 전부 없다
> 초록 전문(1,296자, 오늘 5건 중 **최단**) 전수 대조 결과:
> 1. **벤치마크 2종 이름 없음** — *"two repository-level multi-agent coding benchmarks"* 로만 적힘
> 2. **드래프터 5종 명단 없음** — *"five retrieval-based drafters"*. EAGLE-3 만 유일하게 호명됨
> 3. **"most evaluated settings" 의 예외 구간 없음** — 어디서 졌는지 모른다. 🔴 **이것이 가장 중요한 공백이다**: *"대부분에서 우위"* 는 **"일부에서 열위"** 를 포함하는 문장인데 그 일부가 어디인지 알 수 없으면 **적용 조건을 판단할 수 없다.**
> 4. **코드 공개 선언 자체가 없다** — 초록에 URL 0개. ⇒ [[선언된-구현체-공백]] 의 **선언 이전 단계**([[OneStreamer]] 와 동일).
> ⚖️ **볼트 판정: 4.37/4.76 은 조건부 인용(벤치 이름 불명 명기), "5종+EAGLE-3 대비 우위"는 예외 구간 미공개로 한정 인용.**
