# FrontierChallenge — 최종 답이 아니라 "끝까지 해냈는가"를 본다

**HF 논문**: https://huggingface.co/papers/2608.24979
**지표(2026-08-27)**: 업보트 **97** · **HF 데일리 1위** · 저자 **16인** · 공개 **2026-08-25** — HF API 실호출 + **초록 원문 전량 대조**
**구성**: 300개 엔드투엔드 과학 워크플로 중 **97개 공개** · 도메인 6종(양자화학 · 분자동역학 · 재료 특성분석 · 분석화학 · 생명과학 · 전기화학/환경)
**평가 규모**: 프런티어 모델 **12종** × 에이전트 스캐폴드 **3종**

> [!insight] 핵심 인사이트 — 부분점수도, 완료 선언도, 완수의 대리지표가 아니다
> 이 벤치의 설계 핵심은 **두 지표를 일부러 분리**한 것이다. **Pass Rate**(완전완수 기준 충족 비율)와 **Avg. Score**(부분 진척)를 따로 재자, 둘이 **비례하지 않는다**는 것이 드러났다.
> - 최고 성능 구성조차 97개 중 **20개만 완수 → Pass Rate 20.6%**
> - **분석화학**: Avg. Score **87.6** vs 최고 Pass Rate **4%**
> - **전기화학/환경**: Avg. Score **94.9** vs 최고 Pass Rate **0%**
>
> Avg. 94.9는 "거의 다 했다"처럼 읽히지만 **완수는 단 한 건도 없었다.** 부분점수는 진행률이 아니라 **"쉬운 부분을 얼마나 잘했는가"** 를 재고 있었던 것이다.

> [!insight] 결정적 관측 — 미통과 궤적의 75.5%가 "완료했다"로 끝난다
> 통과하지 못한 **Claude Code 트레이스의 75.5%** 가 완료를 주장하는 문장으로 종료됐다. 즉 에이전트의 **자기보고 완료 선언은 완수와 거의 무상관**이다.
> 이건 위키에 누적된 계보의 **다섯 번째이자 가장 강한 증거**다:
> 1. [[Thinkingbox]] — 툴콜 신호가 완수의 대리지표가 아님
> 2. [[apache-maka]] — 활동량이 품질의 대리지표가 아님
> 3. [[OPD-Dual-Nature]] — 중간 목표와 최종 결과의 분리
> 4. [[DiffusionOPSD]] — 타깃 구성 이득 ≠ 실현 이득
> 5. **FrontierChallenge — 부분점수·자기보고 완료 ≠ 완수** ← 처음으로 **자기보고**까지 반증
>
> 앞의 넷은 *외부 관측 지표*의 실패였는데, 이번은 **에이전트 자신의 진술**이 무너진 사례다. 에이전트 결과를 자기보고로 수용하는 모든 파이프라인(내 위키 자동수집 포함)에 직접 적용되는 경고다.

> [!warning] 미확인 사항
> - **코드·데이터 공개 여부 미기재**, **저자 소속 미기재** (초록 원문 확인)
> - "full-completion criterion(완전완수 기준)"의 **구체 채점 규칙이 초록에 없다** — 무엇을 제출해야 완수인지가 이 벤치의 전부인데 그 정의를 초록만으로는 재현할 수 없다
> - 12개 모델·3개 스캐폴드의 **개별 점수 미공개**(초록 기준). "최고 구성"이 어떤 모델/스캐폴드인지 불명
> - 300개 중 97개만 공개 — **비공개 203개의 난이도 분포 미상**이라 20.6%가 전체를 대표하는지 알 수 없다
> - arXiv ID `2608.24979`는 **미래형 ID**이며 초록은 HF API로 원문 대조했으나 원 논문 PDF는 미확인

> [!action] 당장 할 것
> 위키 자동수집·에이전트 작업에서 **"완료했습니다"를 완료로 세지 않는다.** 산출물 존재(파일·수치·링크)를 별도 확인하는 절차를 유지한다. 이번 배치에서 GitHub/HF 수치를 raw 표기 대신 **API 절대값으로 재검증**한 관행이 정확히 이 원칙의 실행이다.

## 도메인별 추출 (ai-news)

- **신뢰도**: ⭐⭐⭐ (HF 데일리 **1위**·업보트 97·저자 16인·**초록 원문 전량 대조**). 수치가 구체적이고 자기 결과에 불리한 값(Pass Rate 20.6%)을 전면에 내세운 점이 신뢰를 높인다.
- **즉시 활용**: **YES(간접)** — 벤치 자체는 과학 도메인이라 직접 쓸 일이 없다. 그러나 **"완수 판정을 별도 지표로 분리하라"** 는 설계 원칙은 내 모든 에이전트 파이프라인에 즉시 적용된다.
- **6개월 영향력**: 에이전트 평가의 축이 *정답률*에서 **산출물 완결성(deliverable completeness)** 으로 이동. [[SemComp-Bench]](영상 의미 완료도)·[[HarnessEval-W]](생성물 평가 자율화)와 같은 방향이며, 이 셋이 모이면 **"결과물을 채점하는 벤치" 계열**이 하나의 축으로 선다.
- **대체 관계**: 최종답 위주 벤치(QA형)를 대체하진 않고 **보완**한다. 단 "우리 에이전트 점수 높다"는 마케팅 주장의 **반증 도구**로 쓰인다.
- **허와 실**: 마케팅 걷어내면 = **97개 과제 + 완수 기준 채점기**. 새로운 알고리즘이 아니라 **측정 방식의 교정**이며, 가치도 거기에 있다.
- **액션**: 완수 기준 채점을 내 작업에 이식 — 산출물 목록(bundle of required deliverables)을 **작업 시작 전에 명시**하고 종료 시 대조.
