# Scaling the Horizon, Not the Parameters

> [!insight] 핵심 인사이트
> HF 데일리 upvote 54 (2026-06-30 데일리 상위). **파라미터를 키우는 대신 추론 "호라이즌"(에이전트 행동/사고의 길이)을 확장해, 35B 모델로 조(兆)단위 파라미터급 성능에 도달했다는 주장.** 사실이라면 [[local-llm]]에 결정적 — *모델을 키울 자본 없이도 추론 시간(test-time compute)을 늘려 대형 모델을 따라잡는다*는 방향. [[온폴리시-증류]]·test-time scaling 계보와 맞닿으며, "작은 모델 + 긴 추론"이 "큰 모델 + 짧은 추론"을 대체할 수 있는가라는 핵심 질문을 던진다.

## 도메인별 추출 (local-llm)

- **실용성 판단**: 35B면 로컬/엣지 구동 가능 범위(양자화 시). 단 "호라이즌 확장"은 추론 시간·비용을 늘리므로, *지연시간 vs 모델 크기*의 교환을 면밀히 봐야 한다.
- **메모리 아키텍처**: 긴 행동 시퀀스 유지가 핵심 → 에이전트 [[에이전트-메모리-레이어]]·KV 캐시 효율이 병목이 될 가능성.
- **Hermes 적용**: ChinameBot 류 에이전트에 "더 긴 추론 호라이즌"을 적용해 소형 모델로 품질을 끌어올리는 전략 검토 가능.
- **트레이드오프**: 파라미터 절약(메모리·배포 비용↓) vs 추론 호라이즌 증가(레이턴시·토큰 비용↑). 실효는 태스크 종류에 따라 갈림.
- **오픈소스 구현체**: 논문 단계 — 코드·체크포인트 공개 여부 확인 필요.

> [!warning] 신뢰도 주의 — 클레임 검증 필요
> "35B로 조 단위 파라미터급"은 강한 주장. 비교 벤치마크의 공정성(동일 추론 예산? 태스크 편향?)과 재현성 확인 전까지 마케팅 수사일 수 있음. HF upvote는 관심도이지 검증이 아님.
