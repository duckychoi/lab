# EmbodiedSkills: A Unified Framework for Orchestrating, Training, and Deploying VLA Agents

**HF 논문**: https://huggingface.co/papers/2609.01281
**업보트 5** (2026-09-08 API 실측 · raw 5 **완전 일치**) · 게시 **2026-09-01** · 저자 **17인**
**코드**: https://github.com/DCDmllm/EmbodiedSkills

> [!insight] 🎯 **핵심 — 모델의 출력을 "결정"이 아니라 "제안"으로 격하시킨다**
> 초록 원문 실측: *"행동 예측이나 모델이 생성한 스킬 결정은, **그 자체로는** 제안된 조작이 현재 상태에서 유효한지, 결과가 검증될지를 **보장하지 않는다**."*
> **해법**: 각 스킬 결정을 **실행 제안(execution proposal)** 으로 취급 → 런타임이 **① 실행 전 사전조건 검사 → ② 실행 → ③ 사후 결과 검증**.
> → 이건 볼트의 [[검사가능성-공사]] 를 **로봇 도메인에서 강제 구조로 구현**한 것이다. 모델을 더 똑똑하게 만드는 대신 **모델 출력을 통과시키는 관문**을 만든다.
> 📌 그리고 이 배치의 [[TGOPD]] 와 **골격이 같다**: *"신뢰할 수 있는지 먼저 검증하고, 통과할 때만 쓴다."* 한쪽은 교사 신호, 한쪽은 로봇 행동 — **도메인이 완전히 다른데 처방이 같다.**

> [!insight] 🔴 **고정 인터페이스의 효과 — 정책을 갈아도 루프가 안 바뀐다**
> 초록: *"**이 인터페이스가 고정돼 있기 때문에**, 저수준 VLA 정책을 에이전트 루프를 바꾸지 않고 교체하거나 적응시킬 수 있다."*
> → 소프트웨어 공학의 **의존성 역전**을 로봇 스택에 적용한 것. VLA 모델은 교체 주기가 짧은데(볼트 관측: 파운데이션 모델 세대 교체가 [[timesfm-3.0-pytorch]] 사례에서 **4일**), **에이전트 루프까지 매번 다시 짜는 비용**을 없앤다.
> **부수 효과가 더 흥미롭다**: 인터페이스가 **계획·실행·검증·복구 이벤트를 구조화된 궤적으로 기록**한다 → 그 기록이 **개별 구성요소의 감독 신호**가 되고, 상호작용 피드백이 있으면 **온라인 적응**도 지원.
> → **검사 장치가 로그를 남기고, 그 로그가 다시 학습 데이터가 된다.** [[검사가능성-공사]] 의 *"볼 수 있게 만들면 고칠 수 있다"* 가 **자기 강화 루프**로 확장되는 사례다.

> [!insight] 실측 — 그리고 저자가 자기 한계를 초록에 썼다
> 구성: **Qwen3-VL**(고수준) + **OpenPI/pi0.5**(저수준) · **RoboTwin 2.0** · **LIBERO**
> | 벤치마크 | 성공률 |
> |---|---|
> | RoboTwin 2.0 **50개 태스크 평균** | **86.20%** |
> | LIBERO **4개 스위트** | **97.40%** |
> | **RMBench 기억의존 4개 태스크** | **🔴 12.5%** |
> raw 기재와 **전건 일치**.
> 📌 **12.5%를 초록에 쓴 것**이 이 논문의 신뢰도를 올린다. 86.20%/97.40%만 쓰고 끝낼 수 있었는데 **가장 나쁜 숫자를 같은 문단에 넣었다.**
> **그리고 저자는 성과의 귀속도 정확히 한다**: *"이 결과들은 EmbodiedSkills에서 사용된 **태스크 적응된 저수준 VLA 정책의 실행 성능**을 확립한다."* → **86.20%는 프레임워크의 공이 아니라 저수준 정책의 공**이라고 스스로 선을 긋는다. 프레임워크의 기여는 *"훈련 가능하고 검사 가능한 에이전트 층"* 이라고 별도로 주장한다.
> → 볼트가 [[Thinkingbox]]·[[apache-maka]]·[[DiffusionOPSD]] 에서 반복 경고한 **"중간 지표의 개선이 최종 결과를 보장하지 않는다"** 의 **역방향 사례**다: 여기선 저자가 먼저 *"이 수치는 내 기여가 아니다"* 라고 말한다.

> [!warning] 🔴 **12.5%가 말하는 것 — 기억이 빠져 있다**
> 기억 의존 태스크 **4개에서 12.5%** 는 사실상 실패다(무작위 수준일 가능성).
> **왜 그런가**: EmbodiedSkills의 구조는 **사전조건 검사 → 실행 → 사후 검증**이며, 이는 전부 **현재 상태**에 대한 판단이다. **과거에 무엇을 했는지**는 이 루프에 들어갈 자리가 없다.
> → 볼트의 [[에이전트-메모리-레이어]] 축과 정확히 만난다: **검증 루프를 잘 지어도 메모리는 별도 문제다.** 구조적 검사는 *"지금 유효한가"* 를 답하지 *"아까 뭘 했나"* 를 답하지 않는다.
> ⚠️ 단 **RMBench 태스크가 4개뿐**이라 표본이 작다. 저자도 *"기억 의존"* 이라고만 하고 실패 원인을 분해하지 않았다.

## 도메인별 추출 (slam-3dgs / 임바디드)

- **현재 SOTA**: RoboTwin 2.0 50태스크 **86.20%**, LIBERO 4스위트 **97.40%** — 단 **저자 본인이 이를 저수준 정책의 성과로 귀속**한다. 프레임워크 자체의 SOTA 주장이 아니다.
- **실시간 가능성**: **미확인.** 초록에 지연시간·주기 수치가 전혀 없다. 사전조건 검사 + 사후 검증을 매 스킬마다 돌리면 **오버헤드가 있을 수밖에 없는데 그 값이 없다.**
- **카메라 파이프라인**: Qwen3-VL이 시각 입력 처리 — 구체 형식 미기재.
- **응용 가능성**: 볼트 운영자에게 **직접 로봇 응용은 없으나**, *"모델 출력을 제안으로 격하하고 관문을 두는"* 패턴은 **에이전트 설계에 그대로 이식 가능**하다. 실제로 [[TGOPD]] 가 같은 골격을 학습 도메인에서 쓴다.
- **필수 레퍼런스**: RoboTwin 2.0 · LIBERO · OpenPI/pi0.5 — 볼트에 이들 벤치마크 페이지가 **없다**(추적 공백).
- **즉시 활용**: **🟡 원칙만.** 코드는 공개돼 있으나 로봇 하드웨어가 없으면 실행 불가.

> [!action] 당장 할 것
> **"제안 → 사전검사 → 실행 → 사후검증" 4단 관문을 에이전트 설계 패턴으로 [[검사가능성-공사]] 에 등재**한다. 이 배치에서 **로봇([[EmbodiedSkills]])과 LLM 학습([[TGOPD]])이 독립적으로 같은 구조에 도달**했다 — **2도메인 수렴은 개념 승격의 강한 신호**다.

> [!question] 미해결
> **검증 루프의 실행 오버헤드가 얼마인가** — 초록에 지연시간 수치 없음. 로봇 실시간성에서 이건 결정적이다.
> **12.5%의 실패 원인이 메모리 부재인가 다른 것인가** — 저자가 분해하지 않았다.
> **RoboTwin 2.0 / LIBERO / RMBench** — 볼트에 페이지 없음. **추적 공백 3건 등록.**
