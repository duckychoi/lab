# JIT-Agent — 하네스를 사람이 짜지 않고 모델이 뽑는다

**HF 논문**: https://huggingface.co/papers/2608.25593
**코드**: https://github.com/bingreeky/JIT (raw 기재)
**지표(2026-08-27)**: 업보트 **39** · **HF 데일리 5위** · 저자 **16인** · 공개 **2026-08-26** — HF API 실호출 + **초록 원문 대조**(raw 표기 38 → API **39**)
**형식화**: 하네스 = **고정 4모듈 프로토콜**을 따르는 **합성 가능·기계 생성 가능한 산출물**
**4모듈**: 메모리 관리 · 계획 전략 · 행동 프로토콜 · 툴/스킬 오케스트레이션

> [!insight] 핵심 인사이트 — "하네스 지능"을 모델 스케일링과 직교하는 축으로 선언
> 이 논문의 주장은 두 단계다. (1) **에이전트 능력은 모델만으로 결정되지 않으며, 하네스가 기반 모델의 기여를 압도할 수 있다.** (2) 그런데 하네스 설계는 **수작업·태스크 특화·본질적으로 확장 불가**다 — 그래서 **하네스를 만드는 모델을 학습**시킨다.
> 결론 문장이 이 논문의 야심을 요약한다: 하네스 지능은 **학습 가능(trainable)·이전 가능(transferable)·누적적(compounding)** 이며 **모델 스케일링과 직교(orthogonal)** 하는 능력 차원이다.
> 이건 위키에 쌓인 [[에이전트-스킬]] 4층 구조에서 **4층(진화)을 모델화한 첫 사례**다.

> [!insight] 위키 계보 안에서의 정확한 위치 — 오프라인 패치의 온라인·생성형 대응물
> 하네스 개선 축에 이미 세 사례가 있다. JIT-Agent는 **네 번째이자 가장 상위 층**이다.
> - [[AutoSaddler]] — **설계시점** 하네스 코드 패치 (오프라인·수정형)
> - [[Recuris]] — **실행시점** 메모리 진화 (온라인·부분 갱신)
> - [[SkillEvo]] — 멀티턴 피드백 기반 **스킬 자가갱신**
> - **JIT-Agent** — **즉석(just-in-time) 하네스 전체를 생성·수리·자가진화** ← 패치가 아니라 **생성**
>
> 앞의 셋이 *기존 하네스를 고치는* 방식이라면 JIT-Agent는 **태스크마다 하네스를 새로 뽑는다.** 그리고 이전 하네스 구성의 **아카이브에서 성능 신호를 증류**해 자가진화한다 — 누적성(compounding)의 근거가 여기다.

> [!insight] 가장 도발적인 주장 — 생성 하네스가 성숙 런타임과 대등
> **JIT-Agent가 생성한 하네스가 OpenCode·[[anthropic-claude-code]] 같은 성숙 런타임과 성능상 경쟁력 있다**고 주장한다. 사람이 오래 다듬은 런타임을 **기계 생성물이 따라잡는다**는 뜻이라 검증 부담이 큰 주장이다.
> 수치: DeepSeek-V4-Flash가 **DeepSearchQA +9.1 · OdysseyBench +4.3** 으로 **GPT-5.6을 추월**, 이미 강한 **GLM-5.2는 최대 +20.2점** 상승. 추가로 **DeepSeek V4 · Mimo-V2.5 · Qwen3.6** 다중 규모 모델 계열 전반에서 일관 개선(초록 명시 — raw 한줄요약에는 누락된 부분).

> [!warning] 미확인 사항 — "경쟁력"의 판정 기준이 없다
> - **절대 점수 전면 미기재** — 전부 상대 증분(+9.1·+4.3·+20.2). 기준선이 없어 개선의 실질 크기를 알 수 없다
> - **"성숙 런타임과 경쟁력 있다"의 판정 기준·비교 조건 미기재** — 이 논문에서 가장 큰 주장인데 근거 서술이 가장 얇다
> - **하네스 생성 비용 미기재** — 태스크마다 하네스를 뽑는다면 **생성 자체의 시간·토큰 비용**이 실용성을 좌우하는데 초록에 없다
> - **고정 4모듈 프로토콜**이 표현할 수 있는 하네스의 범위(표현력 한계) 미논의
> - arXiv ID `2608.25593`는 **미래형 ID**, 초록은 HF API 원문 대조

> [!question] 미해결 질문
> [[FrontierChallenge]]가 같은 날 **스캐폴드 3종을 바꿔도 Pass Rate 20.6%가 천장**이었다고 보고했다. JIT-Agent는 **하네스를 바꾸면 크게 오른다**고 주장한다. 두 결과는 **직접 모순은 아니지만**(태스크·측정이 다름) 함께 읽으면 질문이 생긴다 — **하네스 개선은 어디까지 올리고 어디서 멈추는가?** 하네스가 지배하는 구간과 모델 능력이 천장을 만드는 구간의 경계가 이 축의 다음 쟁점이다.
