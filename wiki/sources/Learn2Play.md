# Learn2Play Bench — 인간이 이기는 열과 에이전트가 이기는 열이 갈린다

**HF/arXiv**: https://huggingface.co/papers/2610.08215 · arXiv **2610.08215**
**업보트 128**(HF 데일리 **2위**) · 저자 7명 · published 2026-10-08
**독립 검증**: 🆕 `arxiv.org/html/2610.08215` **HTTP 200 · 1,977,425B 본문에서 Table 1 전체 확보**

> [!insight] 핵심 인사이트
> 규칙이 **새롭거나 반직관적인** 텍스트 게임 20종(도전 5 + 일반 15, 양 그룹 총가중치 동일)을 새로 설계해 **사전학습 지식이 아니라 상호작용으로만** 규칙을 얻게 강제하고, 재현 가능한 피드백·자동 채점으로 반복 시도 간 학습을 측정하며 게임 인스턴스를 변형해 전이까지 본다.

> [!insight] 🏆🏆 [[복합지표-분해]] 사상 최선명 사례 — 지표 선택이 결론을 뒤집는다
> **Table 1 (Max / Mean / LG / LS)**
> - Claude Opus 5.5 + OpenCode **80.1 / 61.0 / +23.0 / +5.22** (최고 에이전트)
> - GPT-6 Astra 76.2 / 56.1 · Claude Opus 5 74.5 / 53.8 · Qwen 3.8 Max 72.5 / 51.1
> - Gemini 3.5 Flash 72.0 / 52.2 · Kimi K3 68.5 / 50.2 · Gemini 3.7 Flash 58.3
> - **인간 Top-1 84.3 / 53.5 / +21.6 / +7.33** · Top-3 79.1 / 50.1 · Top-5 75.1 / 47.1
>
> ⇒ **Max 는 인간 Top-1(84.3) > 최고 에이전트(80.1)** 인데 **Mean 은 에이전트(61.0) > 인간 Top-1(53.5)**.
> ⚖️ **"인간이 더 잘한다/못한다"가 지표 선택으로 뒤집힌다. 한 숫자로 인용하면 반드시 틀린다.**

> [!insight] 🎯 하네스는 품질과 비용을 동시에 움직인다 — [[하네스-설계-축]] 에 비용 축 추가
> 백본 고정 시 하네스 교체가 성능을 올리면서 **추정 추론비용을 낮춘다.** Kimi K3 에서 OpenCode 는:
> - Memory 대비 입력 토큰 **56% 절감**
> - EvoTest/ReasoningBank 대비 생성 토큰 **71% / 41% 절감** (Table 11)
>
> ⇒ 지금까지 볼트는 하네스를 **점수 축**으로만 봤다. **비용 축이 같은 방향으로 움직인 첫 실측이다.**

> [!warning] ⚖️ 10-06 [[claude-mem]] 의 설계 전제와 정면 충돌한다
> **경험 보존 형태가 중요하다**: 행동·피드백 **전체 기록 보존**이 규칙·전략으로 **요약**하는 것보다 효과적이다.
> ⇒ [[claude-mem]] 은 *"세션 활동을 AI 로 압축해 재주입"* 으로 ★96,801 을 모았는데, 본 논문은 **압축이 아니라 원본 보존이 이긴다**고 측정한다.
> 📌 [[대립레시피-동시도착]] **강한 후보** — 제품과 논문이 같은 질문에 반대로 답한다. → [[에이전트-메모리-레이어]]

> [!insight] 인간-에이전트 학습 양태 차이가 수치화됐다
> 점수 하락 직후 다음 시도에서 **개인 최고를 새로 쓰는 비율**: 인간 **13/39 = 33.3%** vs 에이전트 **52/238 = 21.8%**.
> 📌 즉 **인간은 실패 직후 더 자주 돌파한다.** 에이전트는 하락 후 회복이 덜하다.
