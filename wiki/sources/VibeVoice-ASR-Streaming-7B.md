# VibeVoice-ASR-Streaming-7B (microsoft/VibeVoice-ASR-Streaming-7B)

> [!insight] 핵심 인사이트 — **화자분리를 별도 단계로 두지 않는다**
> 30일 다운로드 **2,279**(2026-09-12 HF API 실호출 · raw와 **일치**) · ♥**213**(raw와 **일치**) · **MIT** · created **2026-09-02** · modified 2026-09-03 · `pipeline_tag: automatic-speech-recognition`.
> '누가 무엇을 말했는지'를 **후처리 다이어리제이션 없이 스트리밍으로 직접 출력**한다 — 고정 청크 + 소량 lookahead + 이전 텍스트 인터리빙 구조. 핫워드 지정 지원.
> **언어 10종 실측 확인**(메타 `language` 필드): `en, zh, es, pt, de, ja, ko, fr, ru, it` — **한국어 포함**. raw의 *"10개 언어(한국어 포함 — 카드 본문과 메타 필드 10개 일치 확인)"* **정확**.
> 계보: 볼트에 이미 [[VibeVoice]](Next-Token Diffusion TTS·⭐51,534) 와 [[VibeVoice-microsoft]](TTS 1.5B / **ASR 7B** / 실시간TTS 0.5B 3모델 구성)가 있다 → **이 리포는 그 ASR 축이 스트리밍 대응으로 독립 공개된 것**이다.

> [!warning] 🔴 **모델카드에 숫자가 하나도 없다 — 카드 전체가 2,236B**
> **볼트 실측**: 카드 크기 **2,236바이트**. `## Evaluation` 섹션(54~56행)의 내용물은 **이미지 태그 1줄뿐**이다:
> ```
> <img src="figures/VibeVoice_ASR_Streaming_results.png" width="80%">
> ```
> **정규식으로 카드 전체에서 백분율·WER·CER 형태의 수치를 검색한 결과 → 0건.** raw의 *"Evaluation이 이미지 1장뿐"* **정확하다.**
> → 테크리포트(arXiv **2609.02812**)도 raw 기록대로 **상대 표현만** 제시한다(*"5개 평가셋 평균 WER/CER 최저"*, *"화자귀속 13개 설정 중 12개에서 최고 또는 공동최고"*) — **절대 수치 없음.**
> → 🎯 **"최저/최고"는 순위이지 성능이 아니다.** WER 3%에서 1등인 것과 WER 25%에서 1등인 것은 **도입 판단이 정반대**로 갈린다. 이 카드로는 그 구분이 불가능하다.
> → **도입 검토 시 자체 측정이 선택이 아니라 필수다.** raw 결론 **동의**.

> [!warning] 🔴 **볼트 추가 발견 — 이름은 7B인데 실측 8.67B (raw 미탐지)**
> **HF API `safetensors` 필드 실측**: `{"BF16": 8674021857}` → **8,674,021,857 파라미터 = 8.67B**.
> 모델명은 **`VibeVoice-ASR-Streaming-7B`** 다. **차이 +1.67B, 약 +24%.**
> → 이것은 [[MiniCPM5-2B]] 의 *'2B'=2.52B* 같은 **반올림 수준이 아니다.** 24%는 다른 크기 등급에 가깝다.
> → **가장 그럴듯한 설명**: 7B급 LM 백본 + 별도 **오디오 인코더 타워**의 합계. 즉 *"7B"* 는 백본만 세고 `safetensors` 는 체크포인트 전체를 센다.
> → ⚠️ **그러나 이는 볼트의 추정이고, 카드는 아무 설명도 하지 않는다.** 카드 2,236B 안에 파라미터·아키텍처·구성요소 수치가 **전혀 없다**(`grep` 결과 `7B`는 제목 한 곳에만 등장).
> → 🎯 **[[단위-불일치]] ②번(백본 ≠ 체크포인트)의 재현**이다. 09-11 [[DeepSeek-V4.1-Flash]] 에서 *"카드 552B 백본 vs safetensors 763B"* 로 확인해 개념으로 승격한 바로 그 형태가, **하루 만에 다른 벤더에서 반복됐다.**
> → **실무 영향이 크다**: VRAM 산정 시 7B로 잡으면 **BF16 기준 약 17.3GB 필요한 모델을 14GB로 오산**한다. 로컬 배치 계획이 어긋난다.
> → raw는 이 항목을 **다루지 않았다.** 09-11 배치에서 볼트가 *"수치·라이선스·모달리티는 잘했으므로 그대로 유지"* 라고 한 영역이지만, **safetensors 총계 대조는 raw의 점검 목록에 없다**(볼트가 09-11에 직접 실측했던 항목이다).

> [!note] 왜 다운로드가 2,279뿐인가 — 낮은 수치의 해석
> 오늘 모델 3건 중 **다운로드 최저**(MiniCPM5-2B-GGUF 70,755의 **1/31**). 그런데 **♥213 으로 좋아요는 GGUF(183)보다 많다.**
> → 🎯 **관심 대비 실사용이 낮다.** 그럴 만한 이유가 있다: ① 공개된 지 **10일**(09-02) ② **8.67B BF16 = 로컬 문턱이 높다** ③ **성능 수치가 없어 도입 판단이 불가능하다.**
> → ③이 특히 크다. 이 카드는 **평가하려는 사람을 되돌려보낸다.**

## 도메인별 추출 (ai-news)

> [!note] 🔀 도메인 판정 — `ai-news` 유지
> 기존 [[VibeVoice]]·[[VibeVoice-microsoft]] 두 페이지가 모두 `ai-news` 이므로 **계보 일관성**을 위해 유지한다. 다만 온디바이스 관점 검토는 [[local-llm]] 에 교차참조(8.67B는 소비자 GPU 경계선).

- **신뢰도**: ⭐⭐ — 다운로드·♥·라이선스·언어 10종·**파라미터 실측**까지 HF API로 대조했고 카드 원문(2,236B)을 전수 확인했다. **메타는 high, 성능은 검증 불가**(수치 0건) → 종합 **medium**.
- **즉시 활용**: **보류.** 한국어를 지원하는 **MIT 라이선스 화자귀속 스트리밍 ASR** 은 [[reat-voice]]·[[down-analysis]] 파이프라인에 직접 쓸 자리가 있다(영상 다화자 전사 → 화자별 자막). **그러나 성능을 모르는 채로 기존 경로를 바꿀 수 없다.**
- **6개월 영향력**: 화자분리를 **별도 파이프라인 단계에서 모델 내부로 흡수**하는 방향. 성공하면 "ASR + 다이어리제이션 + 정렬" 3단 구성이 1단으로 접힌다 — 영상 자막 워크플로가 단순해진다.
- **대체 관계**: [[VibeVoice-microsoft]] 의 ASR 7B 축을 **스트리밍으로 갱신**. 잠재적으로 [[silero-vad]]+ASR 조합 대체 후보. 같은 배치 [[X-AuT]] 와 **정반대 방향**이다 — X-AuT는 *음성 LLM을 줄이는* 쪽, 이쪽은 *늘려서 기능을 흡수하는* 쪽.
- **허와 실**: 마케팅 문구조차 거의 없다(카드가 2KB다). 문제는 과장이 아니라 **정보 부재**다. 🎯 **"과장이 없다"가 "검증됐다"는 뜻이 아니라는 사례** — 볼트가 보통 경계하는 방향과 반대편의 실패 모드다.
- **액션**: ① 한국어 샘플 5분으로 **WER + 화자귀속 정확도 자체 측정**(카드가 안 준 수치를 직접 만든다) ② 측정 전까지 파이프라인 변경 금지 ③ VRAM 산정은 **8.67B 기준**으로.
