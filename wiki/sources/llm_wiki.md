# llm_wiki

> [!insight] 핵심 인사이트 — 이 저장소는 **이 볼트가 하는 일을 제품으로 만든 것**이다
> PDF·오피스·EPUB·이미지를 **2단계 CoT**로 인제스트해 출처 추적 가능한 entity/concept 페이지를 생성하고, 페이지 간 관계를 **가중 신호로 계산**한다. [[LLM-Wiki]] 패턴의 두 번째 본격 구현체([[claude-obsidian]] 다음).
> 🪞 **그런데 이 소스의 진짜 값은 기능 목록이 아니라, 이 볼트에 없는 것을 정확히 짚어준다는 점이다.**

> [!warning] 🪞 볼트 자기점검 — llm_wiki에는 있고 여기에는 없는 것
> README 146~170행이 제시하는 **4-신호 관련성 모델**(가중치 원문):
> - **직접 링크** · **출처 중첩** · **Adamic-Adar ×1.5**(공통 이웃을 이웃의 차수로 가중) · **타입 친화도 ×1.0**(entity↔entity, concept↔concept 보너스)
>
> 그리고 결정적으로 **Louvain 커뮤니티 탐지 + 응집도 점수화**(162~170행):
> *"each community scored by intra-edge density (actual edges / possible edges); **low-cohesion clusters (< 0.15) flagged with warning**"*
>
> → **이 볼트는 소스 1,001개를 쌓는 동안 링크 구조를 한 번도 정량 측정한 적이 없다.** grep과 `[[wikilink]]` 로 "연결됐다/안 됐다"만 봤다. 응집도·차수 가중·클러스터 자동 발견은 전부 없다.
> → [[검사가능성-공사]] 가 말한 *"검사기가 피검사자와 같은 실패 모드를 공유하면 계기판이 아니라 거울이다"* 의 실물이다. **내 lint는 고아 페이지만 센다 — 그건 차수 0만 잡고 차수 1짜리 죽은 클러스터는 못 잡는다.**
> → 게다가 llm_wiki는 **cross-community edge·cross-type link·주변↔허브 결합을 "예상 밖 관계"로 따로 탐지**한다(181행). 볼트가 synthesis/ 를 **2건**밖에 못 만든 이유가 여기 있다 — **교차 연결을 찾는 절차가 없어서 사람이 눈으로 볼 때만 생긴다.**

> [!note] 구조
> - **2단계 CoT 인제스트** — 원문 → 구조화 → 페이지. entity/concept 페이지에 `sources[]` 배열 유지
> - **삭제 안전성**(343행): 소스를 지워도 **여러 소스에 걸린 entity/concept는 `sources[]` 에서 해당 항목만 제거**하고 페이지 자체는 남긴다 → 볼트의 `raw.md` 항목 삭제 정책과 같은 사상, 다만 **자동화돼 있다**
> - **Rust 백엔드 챗 에이전트 + 로컬 `SKILL.md` 스킬**(48행) — `/skill` 로 선택, 에이전트가 필요 시 읽는다. [[에이전트-스킬]] 규약을 **지식베이스 앱이 채택**한 사례
> - `dataVersion` 신호로 그래프·UI 자동 갱신(377행)

> [!warning] 🔴 라이선스 정정 — `NOASSERTION` 이지만 실제는 **GPL-3.0**

> ```

> → **GPL-3.0 전문이 그대로 들어 있다.** 자동탐지가 실패한 원인은 어제 [[teamai-cli]] 와 **완전히 동일** — 전문 앞에 저작권 1줄이 붙어 정규식이 깨졌다.
> → [[파생표기-함정]] 규칙이 **이틀 연속 적중**. 그리고 함의가 다르다: **GPL-3.0이면 이 코드를 참고해 내 도구를 만들 때 전염성 조항이 걸린다.** `NOASSERTION` 을 "라이선스 불명"으로 넘겼으면 이 판단을 못 했다.
