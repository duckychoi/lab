# MemTrapBench — 충실히 저장된 메모리조차 추론을 망가뜨린다

**논문**: https://huggingface.co/papers/2608.20202 (arXiv 2608.20202)
**지표**: HF 데일리 **6위** · 업보트 **31** · 게재 2026-08-20 · 저자 9인(Mengru Wang·Haozhe Luo·Zhenqian Xu 외)
**검증**: 2026-08-22 HF API 실호출 — 제목·초록·업보트·저자 **원문 대조 완료**

> [!insight] 핵심 인사이트 — 메모리 평가의 축을 "저장·검색"에서 "추론 오염"으로 옮김
> 기존 메모리 벤치마크는 정보가 **정확히 추출·저장·검색됐는가**만 측정하고, 검색된 메모리가 **현재 태스크의 추론을 어떻게 재형성하는가**는 사실상 방치했다. 이 논문은 **memory-induced cognitive traps(메모리 유발 인지 함정)** 를 정의한다 — *충실히 기록되고 의미적으로도 관련 있는* 메모리조차 모델의 추론·믿음을 왜곡하고 현재 성능을 떨어뜨린다는 것. 함정은 두 형태: **Reasoning Fixation**(추론 고착)과 **Belief Distortion**(믿음 왜곡).
>
> 가장 강한 결과: **2개 모델 패밀리 × 5개 대표 메모리 프레임워크 실험에서, 평가된 모든 메모리 전략이 "메모리 없음(no-memory)" 설정보다 못했다.** 최강 방법조차 **10% 이상** 하락. 완화책으로 추론 시점 방법 **AdaptiveMem**(LLM에게 메모리 함정을 피하도록 지시)을 제안 — 표준 메모리 벤치 성능은 보존·개선하면서 함정은 완화.

> [!warning] 이 결과가 [[에이전트-메모리-레이어]] 전제를 정면으로 흔든다
> 볼트가 [[OpenViking]]·[[ai-memory]]·[[MobileMem]] 등으로 누적해 온 "에이전트에 메모리를 붙일수록 좋다"는 암묵 전제에 대한 **최초의 정량 반례**. "메모리 품질 = 저장·검색 정확도"라는 지표 설계 자체가 틀렸을 수 있음을 시사한다. 단 5개 프레임워크·2개 모델 패밀리라는 **표본 범위**와 태스크 구성이 결과를 좌우할 수 있으므로 "메모리는 해롭다"로 일반화하는 것은 금물 — 정확한 주장은 **"현행 메모리 전략들은 자신이 유발하는 추론 오염을 측정도 통제도 하지 않는다"**.

## 도메인별 추출 (ai-news / 교차: local-llm · agent-memory)

- **신뢰도**: ⭐⭐⭐⭐ — HF 데일리 6위·업31. **초록·수치 원문 실검증 완료**(이전 배치 HF논문들과 달리 medium이 아닌 high). 단 벤치 공개 여부·5개 프레임워크의 구체적 정체는 초록 미기재.
- **즉시 활용**: **YES(개념 수준)** — AdaptiveMem은 "추론 시점 프롬프트 지시"이므로 별도 학습 없이 내 봇의 메모리 주입 프롬프트에 **"검색된 메모리가 현재 질문과 충돌하면 메모리를 무시하라"** 류 가드 문장을 얹는 것으로 즉시 모사 가능.
- **6개월 영향력**: 높음 — 메모리 레이어를 도입할 때 **"메모리 ON vs OFF A/B"를 필수 관문으로** 만들 근거. 지금까지 볼트의 메모리 축 소스들은 전부 ON을 전제했다.
- **대체 관계**: 대체가 아니라 **감사(audit) 계층** — [[OpenViking]]·[[ai-memory]] 같은 저장·핸드오프 레이어 위에 얹는 실패 모드 측정자.
- **허와 실**: "모든 메모리 전략이 no-memory보다 못하다"는 강한 문장이지만, 이는 **MemTrapBench가 함정을 겨냥해 설계된 벤치**라는 점을 감안해야 한다(적대적 벤치에서 낮은 점수는 부분적으로 설계 의도). 그럼에도 10%+ 하락 폭은 무시하기 어렵다.
- **액션**: 내 에이전트 메모리 주입 경로에 ON/OFF 비교를 1회 돌려 **추론 고착**이 실제 발생하는지 스팟체크.
