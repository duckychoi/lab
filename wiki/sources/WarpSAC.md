# WarpSAC — "안정화 기법은 보편 진리가 아니라 데이터 체제의 함수다"

**HF 논문**: https://huggingface.co/papers/2608.24479
**코드**: https://github.com/wzhhasadream/warprl (★1 · raw 기재)
**지표(2026-08-28 최신)**: 업보트 **134**(+56) · **HF 데일리 2위** · 저자 **12인** · 공개 **2026-08-25** — HF API 실호출 + 초록 원문 재대조
**지표(2026-08-27)**: 업보트 **78** · **HF 데일리 3위** · 저자 **12인** · 공개 **2026-08-25** — HF API 실호출 + **초록 원문 대조**(raw 표기 77 → API **78**)
**진단 실험**: 벤치마크 **8계열** 통제실험

> [!update] 2026-08-28 갱신 — 업보트 78 → **134**(+56) · 데일리 **3위 → 2위** · 초록 수치 전량 재확인
> **HF API 실호출 재검증**. 공개 3일째에 업보트 **134**로 데일리 2위. 같은 배치 1위 [[VoiceMem]](159)과 함께 **최근 배치 상위 2편이 모두 08-25~26 공개 논문**이다 — 관심이 하루 만에 붙지 않고 **이틀에 걸쳐 누적**되는 패턴.
> **초록 원문 재대조 — 08-27 기록 수치 전량 일치, 추가 확인 2건**:
> - FlashSAC 대비 정규화 점수-스텝 **AUC: CPU 규모 9환경 +4.5% · GPU 병렬 14환경 +23.1%**
> - **UnitreeG1TransportBox-v1 성공률 19.8% → 96.4%**
> - **MuJoCo Playground 평균 정규화 wall-time AUC +19.1%** · **Unitree G1 sim-to-real 배치 36.4% 단축**
> - ✅ **추가 확인**: 변종 구성이 초록에 명시돼 있다 — **WarpSAC-L**(Norm **ON** + clipped double-Q, 데이터 제한 CPU 규모) / **WarpSAC-A**(Norm **OFF** + **단일 Q**, 데이터 풍부 GPU 병렬). 08-27 기록에 구성 상세가 축약돼 있었으므로 **여기서 보강한다.**
> - ✅ **추가 확인**: age-biased replay weighting은 **"체제 전반에 걸쳐, 특히 네트워크 용량이 제한적일 때" 학습 효율을 개선**한다 — 용량 조건이 붙는다는 점이 08-27 기록보다 정확하다.
>
> ⚠️ 한계도 유지된다: **절대값·벤치 8계열의 이름·체제 전환 임계점 미기재.**

> [!insight] 핵심 인사이트 — 기법이 틀린 게 아니라 전제가 바뀌었다
> 오프폴리시 RL의 표준 안정화 장치들은 **데이터가 귀하던 시절(data-limited replay)에 설계**됐다. 대규모 병렬 시뮬레이션이 데이터를 흔하게 만들자 **같은 기법이 반대로 작동**한다는 것이 이 논문의 진단이다.
> - **파라미터 정규화**: 리플레이 커버리지가 좁을 때만 이롭고, **데이터가 풍부하면 가치 적합(value fitting)을 제약**한다
> - **clipped double-Q**: 고처리량 매니퓰레이션에서는 **완화 가능**하다
> - **age-biased replay 가중**: 체제와 무관하게 이롭고, 특히 **네트워크 용량이 작을 때** 효율이 오른다
>
> 즉 "좋은 기법 목록"이 아니라 **"어떤 조건에서 좋은가"** 로 지식이 조건화된다. 이건 위키에 반복 등장하는 **[[FrontierChallenge]]식 교훈의 RL판** — 지표든 기법이든 **맥락 없이 옮기면 무너진다**.

> [!insight] 결론이 알고리즘 하나가 아니라 "분기"다
> 단일 최적해를 주장하지 않고 체제별로 **두 변종**을 낸 점이 이 논문의 정직한 부분이다.
> - **WarpSAC-L** (Norm **ON** · clipped double-Q) — 데이터 제한적인 **CPU 규모** 학습용
> - **WarpSAC-A** (Norm **OFF** · single-Q) — 데이터 풍부한 **GPU 병렬** 학습용
> - 공통: **Sample Weight Decay**(효율적 exploitation용)
>
> 성능(FlashSAC 대비): 정규화점수–스텝 AUC **CPU 9환경 +4.5% / GPU 병렬 14환경 +23.1%** — **이득이 GPU 병렬에서 5배 크다**는 사실 자체가 "체제 의존성" 주장의 자기 증거다.

> [!insight] 가장 실무적인 수치 — 19.8% → 96.4%
> **UnitreeG1TransportBox-v1 성공률 19.8% → 96.4%.** 안정화 장치의 ON/OFF 조합만 체제에 맞춰 바꿔 **거의 실패하던 과제를 거의 성공**으로 뒤집었다. 모델 구조나 규모를 키운 게 아니라 **하이퍼/설계 전제를 조건에 맞춘 결과**라는 점에서, [[JIT-Agent]]가 같은 날 주장하는 *"하네스가 모델 기여를 지배할 수 있다"* 와 **동일한 형태의 메시지**다 — 층은 다르지만 둘 다 **"모델 밖의 설정이 성능을 지배한다"**.
> 추가: MuJoCo Playground 실시간(wall-time) AUC **+19.1%**, Unitree G1 **sim-to-real 배포 36.4% 단축**.

> [!warning] 미확인 사항
> - **절대 성능값 없음** — 전부 FlashSAC 대비 상대 개선. 96.4%만 절대값이다
> - **8개 벤치 계열의 이름 미기재**(초록 기준) — 통제실험의 커버리지 검증 불가
> - **"데이터 체제"의 조작적 정의 부재** — 어느 지점부터 abundant인지 임계가 초록에 없어 **내 환경이 어느 체제인지 판별할 방법이 없다**. 실사용의 최대 걸림돌
