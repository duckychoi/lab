# Recuris — 메모리를 "쌓는 것"에서 "검증 게이트로 진화시키는 것"으로

**HF 논문**: https://huggingface.co/papers/2608.24876 · **arXiv**: 2608.24876
**원제**: *Recursive Experiential-Working Memory Evolution for Long-Horizon Agent Harnesses*
**지표**: 업보트 **16** · **HF 데일리 5위** · 저자 **8인** · 공개 **2026-08-25** — **HF API 실호출 + 초록 원문 대조 검증**(2026-08-26)
**공개**: 코드 공개 — https://github.com/Gen-Verse/Recuris (초록 원문 명시)

> [!insight] 핵심 인사이트
> **문제 진단이 [[MemTrapBench]]가 제기한 것과 정확히 같은 곳을 겨눈다: "히스토리가 길어질수록 태스크 상태가 가려지고 스킬 호출이 어긋난다."**
> Recuris의 답은 메모리를 **세 층으로 쪼개고 서로 감시하게** 만드는 것이다:
> - **Working Memory** — 태스크 진행 상태를 추적하고, 이걸로 **Experiential Memory에서 스킬을 선택**한다. 핵심은 *"전체 히스토리가 아니라 현재 필요에 근거해 스킬을 고른다"* 는 것.
> - **실행 = 구조화된 증거** — 실행 결과가 **어느 메모리 구성요소가 잘못됐는지 국소화(localize)** 한다.
> - **Meta-Agent** — 그 증거를 **검증 게이트를 통과한(validation-gated) 국소 갱신**으로 바꿔 **Skill Memory**에 반영한다. 갱신된 스킬이 실행을 바꾸고 새 증거를 낳는 **유계 재귀 루프**.
>
> **볼트 관점에서 이게 중요한 이유: [[MemTrapBench]]는 "평가된 5개 메모리 프레임워크가 전부 no-memory보다 못했다"고 보고했다. 그 반증이 될 첫 후보다.** MemTrapBench의 진단은 *메모리가 오염되면 없느니만 못하다*였고, Recuris의 처방은 정확히 그 지점 — **검증 게이트 없는 무조건 축적을 막는 것**이다.

> [!insight] 실측: 37쌍 중 35쌍 개선, Opus 5를 tau-bench 87.9%로
> 초록 원문 수치 — **4개 롱호라이즌 벤치 × 10개 모델, 완료된 37개 (모델,벤치) 쌍 중 35쌍에서 성공률 개선**.
> - **tau-bench: [[Claude Opus 5]] +15.6점 → 87.9%** · **GPT-5.6 Sol +17.8점**
> - **SkillFlow: Qwen3.6-27B +16.6점 · Qwen3.6-35B +13.5점** (raw 수집 메모에 누락됐던 수치 — **API 초록에서 확인·보강**)
> - **가장 긴 태스크에서 +32.2점** — 이득이 **상호작용 지평이 길어질수록 커진다**
> - **흔한 롱호라이즌 실패가 최대 80% 감소** (raw 누락 수치 — 보강)
>
> **"길수록 이득이 커진다"가 이 논문의 서명이다.** 대부분의 개선 기법은 쉬운 구간에서 벌고 어려운 구간에서 무너지는데, 여기선 반대다. 그리고 **프런티어 모델(Opus 5)에서도 +15.6점이 나온다** — 즉 **모델이 좋아져도 메모리 구조가 남긴 여지가 여전히 크다**는 뜻이다.

> [!warning] 업보트 16 — 배치 최하위인데 내용은 가장 실용적이다
> **데일리 5위·업보트 16으로 이번 배치 최저 관심**이다(1위 [[OraRL]] 65의 약 1/4). 그런데 **코드가 공개돼 있고 수치가 가장 구체적**이다 — [[free-claude-code]]에서 확인한 *"인기 지표와 신뢰성 지표가 정반대를 가리킨다"* 의 재현 사례로 기록한다.
> 검증 한계도 명확히 둔다: **"완료된 37쌍"이라는 표현은 일부 (모델,벤치) 조합이 완료되지 않았음을 시사**하는데, **몇 쌍이 미완이고 왜인지 초록에 없다.** 실패한 2쌍의 정체도 없다. 그리고 **Meta-Agent 자체의 비용**(추가 LLM 호출 횟수·토큰)이 초록에 전혀 없다 — 메모리 진화 루프는 공짜가 아니다.

## 도메인별 추출 (ai-news · 교차 local-llm)

- **신뢰도**: ⭐⭐⭐⭐⭐ high — 초록 원문 대조 완료 + **코드 공개** + 벤치 4종·모델 10개라는 폭 + 절대 점수(87.9%) 제시. 이번 배치에서 **재현 가능성이 가장 높은 논문**.
- **실용성 판단**: **높음** — 학습이 아니라 **하네스 아키텍처**라서 모델 재학습 없이 적용 가능하다. 코드가 공개돼 있어 구조를 읽고 이식할 수 있다.
- **메모리 아키텍처**: **Working / Experiential / Skill 3층 + 검증 게이트 + Meta-Agent 재귀 갱신.** [[에이전트-메모리-레이어]] 페이지의 분류에 **"검증 게이트를 통과한 갱신만 반영"이라는 새 축**을 추가해야 한다 — 기존 축(RAG/KV/압축/외부DB)은 *저장 방식*만 다뤘지 *갱신 승인 조건*을 다루지 않았다.
- **Hermes/ChinameBot 적용**: **가능성 높음.** 전체 히스토리를 밀어 넣는 대신 **진행 상태 요약(Working Memory)으로 필요한 것만 꺼내는** 구조는 컨텍스트 예산이 빠듯한 로컬·소형 모델에서 이득이 더 크다. 실제로 **Qwen3.6-27B/35B에서 +16.6/+13.5점**이 나온 게 근거다 — 프런티어 전용 기법이 아니다.
- **트레이드오프**: Meta-Agent 호출과 검증 실행이 **추가 비용**이다. 수치 미공개라 손익 계산 불가 — 짧은 태스크에서는 손해일 가능성이 높다(이득이 지평 길이에 비례하므로).
- **오픈소스 구현체**: **https://github.com/Gen-Verse/Recuris** — 이번 배치에서 바로 열어볼 수 있는 유일한 에이전트 하네스 코드.
- **액션**: **레포를 열어 3층 메모리 구조와 검증 게이트 구현을 읽고, 내 스킬 파일 관리에 "게이트 통과 시에만 갱신" 규칙 도입** (높음).

> [!question] 미해결 질문
> - **미완료된 (모델,벤치) 쌍은 몇 개이고 왜 미완인가?** 37쌍이 전체가 아니라면 분모가 흐려진다.
> - **Meta-Agent의 추가 비용** — 태스크당 몇 회 호출인가? 손익분기 지평 길이는?
> - **검증 게이트의 판정 기준**은 무엇인가? [[Thinkingbox]]가 실증한 *"깨끗한 종료가 완수를 뜻하지 않는다"* 를 감안하면, 게이트가 exit code류 신호를 쓰면 오염을 못 막는다.
> - **[[MemTrapBench]]로 직접 평가하면 no-memory를 이기나?** 이게 메모리 프레임워크 논쟁의 결정적 실험이다.
> - [[AutoSaddler]](오프라인 하네스 패치)와 **동시 적용 시 충돌하나** — 둘 다 하네스를 고치는데 시점이 다르다.
