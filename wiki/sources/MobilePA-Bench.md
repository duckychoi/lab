# MobilePA-Bench — GUI 벤치와 function-calling 벤치 사이의 사각지대를 메운다

**논문**: https://huggingface.co/papers/2608.23035 (arXiv 2608.23035)
**지표**: HF 데일리 **2위** · 업보트 **31** · 게재 **2026-08-24** · 저자 **11인**
**검증**: 2026-08-25 HF API 실호출 — 제목·초록·업보트·저자수 **원문 대조 완료**

> [!insight] 핵심 인사이트 — 기존 모바일 에이전트 벤치는 두 진영 모두 반쪽이었다
> 논문의 진단이 날카롭다. 기존 벤치는 두 갈래인데 **각각 치명적 맹점**이 있다.
> - **GUI 중심 벤치**: 화면 조작이라는 *표면 수준*만 테스트하고, **백그라운드 툴 사용과 장기 지평 계획을 놓친다.**
> - **정적 function-calling 벤치**: **오프라인 API 매칭**에 의존해 **실제 런타임 제약과 분리**돼 있다.
>
> MobilePA-Bench는 **살아있는 애플리케이션 DB를 유지하고 구조화된 피드백을 반환하는 실행 샌드박스** 위에서 돌아간다 — **13개 기능 도메인 · 212개 현실적 모바일 툴**. 즉 "API 이름을 맞췄는가"가 아니라 **"상태가 실제로 바뀌었는가"** 를 묻는 쪽으로 이동한 벤치다.

> [!insight] 진짜 기여는 "상위 3차원"을 따로 잰다는 점
> 기본 툴 사용을 넘어, **중앙 플래닝 에이전트를 3개 상위 차원에서 별도 평가**한다:
> 1. **서브에이전트 협업** — 복잡 태스크를 분해해 능력 있는 서브에이전트에 위임
> 2. **메모리 사용** — 저장된 메모리·사용자 프로필·과거 선호를 되살려 **암묵적 요청을 해소**
> 3. **스킬 사용** — 매번 처음부터 계획하는 대신 **사전 패키징된 복합 스킬을 호출**
>
> 이 3차원은 [[에이전트-스킬]]·[[에이전트-메모리-레이어]] 개념이 **평가 항목으로 승격**된 사례다. 지금까지 스킬·메모리는 "있으면 좋은 기능"으로 다뤄졌지, **점수가 매겨지는 축**이 아니었다.

> [!warning] 실패 조건은 밝혔지만 모델별 점수가 없다
> "현재 프론티어 LLM들은 모바일 환경에서 여전히 **신뢰할 수 없다**"고 결론내며, 성능이 급락하는 조건을 **엄격한 툴 순서 제약·권한 제한·예기치 못한 런타임 오류** 셋으로 특정했다. 그러나 **모델별 절대 점수·순위가 초록에 전혀 없다.** [[Thinkingbox]]가 같은 배치에서 pass@1 65.36% / pass^20 25.25%라는 **구체 수치로 신뢰성 간극을 못박은 것과 대비**된다.

## 도메인별 추출 (ai-news / 교차: agent-eval · 모바일 에이전트)

- **신뢰도**: ⭐⭐⭐⭐ — 초록 원문 실검증 완료. 설계·규모(13도메인·212툴)·3차원 평가축·실패 조건은 확정, **점수는 미공개**.
- **즉시 활용**: **부분 YES(설계)** — 212개 툴 목록과 13개 도메인 분류는 공개되면 **툴 스키마 설계의 참조 카탈로그**가 된다. 더 즉시적인 건 **평가 관점의 이식**: 내 에이전트 워크플로를 점검할 때 "툴 순서를 강제하면? 권한을 뺏으면? 툴이 에러를 뱉으면?" 세 조건을 **의도적 실패 주입 체크리스트**로 쓸 수 있다([[Claude-Code-워크플로우]] 적용 가능).
- **6개월 영향력**: 높음 — 온디바이스 LLM 에이전트가 개인 코파일럿으로 굳는 흐름에서 **모바일 OS가 핵심 시험장**이라는 전제 자체가 업계 합의에 가깝다. 저자들이 **에이전틱 RL의 상호작용 기반**으로도 쓰라고 명시한 만큼 학습 환경으로 재활용될 여지가 크다.
- **대체 관계**: [[MemGUI-Agent]]·[[MobileForge]]·[[MobileMem]]과 같은 모바일 축. GUI 조작 중심 벤치를 **직접 대체 주장**. [[AdaPlanBench]]·[[Thinkingbox]]와는 "상태 기반 채점"이라는 같은 결.
- **허와 실**: **212개 툴이 "현실적(realistic)"이라는 것과 "실제 앱"이라는 것은 다르다** — 샌드박스가 실제 안드로이드/iOS 앱을 구동하는지, 모사 DB인지 초록만으로는 불명확하다("live application databases"는 후자에 가깝게 읽힌다). 모사라면 **런타임 제약의 현실성**이 벤치의 생명인데 그 검증 방법이 미기재다.
- **액션**: 코드 공개 시 **212툴 스키마**를 내려받아 툴 정의 작성 레퍼런스로 활용. 점수표 공개 여부 추적.

> [!question] 미해결 질문
> 모델별 점수는? 샌드박스가 실제 앱을 구동하는가 모사 DB인가? 13개 도메인의 구체 목록은? "사전 패키징된 복합 스킬"의 형식은 [[에이전트-스킬]] 규격과 호환되는가? 코드·데이터 공개 여부는?
