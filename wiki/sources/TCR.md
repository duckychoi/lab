# The Missing Temporal Link: Temporal Context Routing for Script-Driven Audio-Video Generation

**arXiv**: 2609.02367 · **HF 데일리 업보트 18** · **방법명: TCR** (Temporal Context Routing)
**이 배치에서 볼트 자체 파이프라인과 가장 가까운 소스**

> [!insight] 핵심 인사이트 — 진단이 해법보다 값지다
> 결합 오디오-비디오 생성 모델은 화질과 **오디오-비디오 동기화**를 이미 잘한다. 그런데 *언제 컷이 바뀌고 언제 대사가 나오는지*는 제어가 안 된다. 논문이 짚은 원인이 급소다 — **비디오와 오디오는 공유 시간축 위에 정렬되지만, 구조화된 프롬프트에 적힌 컷·대사 타이밍은 오직 프롬프트의 *텍스트 표현*에만 인코딩되어 어느 모달리티의 시간 좌표와도 정렬되지 않는다.** 그 결과 **영상과 오디오는 서로 완벽히 동기화된 채로 둘 다 대본 타임라인을 벗어난다.** TCR은 시간 정렬을 비디오·오디오 **너머 대본까지** 확장해, 각 프롬프트의 가이던스를 **두 모달리티의 해당 위치로 라우팅**한다.

## 수치 (초록 실측 · 200개 테스트 대본)

- **Shot Boundary MAE: 1.11초 → 0.042초** (**96% 감소**)
- **Dialogue Acc@0.5s: 28.3% → 84.1%** (약 3배)
- 화질과 오디오-비디오 동기화는 **베이스라인과 동등 유지** (성능을 뺏어 온 게 아님)
- 사용자 연구: **평가 5개 차원 전부**에서 TCR 선호

> [!action] 당장 할 것 — 볼트 파이프라인 직결
> 이 볼트 사용자의 `reat-*` 스킬 체인은 **`/reat-chunk`(SRT → beats) → `/reat-scene`(scene-plan) → `/reat-render`** 로, **대본 타이밍을 씬 경계로 바꾸는 일**을 정확히 수행한다. TCR의 진단은 **그 파이프라인이 왜 필요한지에 대한 외부 근거**다. 지금 할 것:
> 1. `/reat-scene` 산출물에서 **Shot Boundary MAE에 해당하는 값을 실제로 측정**한다(계획된 컷 시각 vs 렌더된 컷 시각). 볼트는 이 수치를 **한 번도 잰 적이 없다**.
> 2. `/reat-voice` 의 SRT 타임스탬프와 최종 렌더 씬 경계의 **오차 분포**를 뽑는다.
> → TCR의 0.042초는 **비교 기준선**으로 쓸 수 있다. 우리 파이프라인이 명시적 타이밍 제어(자막 기반)를 쓰므로 **더 정확해야 정상**이며, 아니라면 그게 버그다.

> [!insight] 볼트 교차 — "명시적 시간축"이 생성 모델의 약점이라는 확증
> 볼트의 `reat-*` 체인은 **생성 모델에 타이밍을 맡기지 않고** SRT/beats로 **밖에서 시간축을 강제**하는 설계다. TCR은 **그 선택이 옳았음을 정량으로 보여준다** — 맡기면 MAE 1.11초가 나온다(1초 넘게 어긋나면 편집물로 못 쓴다). 동시에 [[humanizer]]·[[EarlyEval]]·[[DeepSWE]]에서 반복된 축과 같은 결이다: ***모델 안에서 암묵적으로 처리되던 것을 밖으로 꺼내 명시하면 성능이 오른다.*** 이 배치에서만 **네 번째 사례**다.

## 도메인별 추출 (video-saas)

- **기능 벤치마킹**: 구현 난이도는 **모델 재학습이 필요한 쪽**(라우팅 모듈이 생성 과정에 개입). 우리처럼 **씬 단위 조립형** 파이프라인은 TCR 없이도 타이밍을 제어하지만, **단일 모델로 긴 클립을 뽑을 때** 필요해진다.
- **크리에이터 인사이트**: 사용자가 원하는 건 *"화질 좋은 영상"* 이 아니라 **"내가 쓴 대본대로 정확히 끊기는 영상"** 이다. 기존 모델들이 화질·동기화에 투자하는 동안 **1.11초짜리 타이밍 오차를 방치**했다는 게 이 논문의 시장 진단이며, 이는 볼트가 [[Higgsfield-벤치마킹]] 이래 관측해 온 *"툴이 주는 것과 원하는 것의 갭"* 의 구체적 실체다.
- **프롬프트 패턴**: **구조화된 프롬프트에 컷 전환·대사 시각을 명시**하는 형식이 전제. 이 형식 자체가 우리 `beats.json` 과 개념적으로 같다.
- **워크플로우**: 대본(타임스탬프 포함) → 시간축 라우팅 → 영상+오디오 동시 생성. **단일 패스**라는 게 조립형과의 차이.
- **경쟁 우위 빈틈**: 상용 툴들이 **타이밍 정확도를 수치로 공개하지 않는다.** Shot Boundary MAE는 **측정 가능하고 비교 가능한 지표**이며, 이걸 공개하는 것 자체가 차별화가 된다.

> [!warning] 확인 안 된 것
> ① **베이스라인 모델명 미상** — *"the baseline"* 이라고만 함. 어떤 모델 대비 96% 감소인지 모른다. ② **코드·프로젝트 페이지 없음**(저자가 *"곧 공개"* 라고만 댓글). ③ **200개 대본의 구성 미상**(길이·언어·복잡도). ④ 화질/동기화가 *"comparable"* 이라는 건 **동등**이지 향상이 아니다. ⑤ HF에 *"Models citing this paper 1"* 이 있으나 어떤 모델인지 미확인. → **재현 불가 상태**이므로 수치는 **목표치 참조용**으로만 쓰고 인용 시 조건 명시.
