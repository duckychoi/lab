# VGI-BENCH — "그럴듯한 결말"이 아니라 "타당한 전개"를 요구하는 벤치

**HF 논문**: https://huggingface.co/papers/2608.19583
**코드/데이터**: https://github.com/hexuan21/VGI-Bench (**공개 예정** — 초록에 "We will release" 명시)
**지표(2026-08-27)**: 업보트 **65** · **HF 데일리 4위** · 저자 **22인** · 공개 **2026-08-20** — HF API 실호출 + **초록 원문 대조**(raw 표기 61 → API **65**)
**구성**: **27과제 · 810인스턴스** · 과제 도메인 × 스킬 태그 **2단 분류체계**

> [!insight] 핵심 인사이트 — 최종 프레임이 아니라 전개 과정을 채점한다
> 영상 생성 모델이 생성 프레임을 통해 **제로샷 시각 추론**을 한다는 주장을 검증하려는 벤치인데, 설계 원칙이 명확하다: **그럴듯한 최종 상태(plausible final state)가 아니라 유효한 전개 과정(valid evolving process)을 요구**한다.
> 이건 [[FrontierChallenge]]가 같은 날 과학 워크플로에서 한 것과 **정확히 같은 교정**이다 — 결과만 보면 통과하는 것들이 과정을 보면 무너진다. 두 논문이 서로 다른 도메인(과학 에이전트 / 영상 생성)에서 **독립적으로 같은 결론**에 도달했다는 점이 오늘 배치의 최대 구조적 관측이다.

> [!insight] 결정적 관측 — 후반 디노이징은 오류를 고치지 못한다
> 내부 디노이징 분석에서 **후반 스텝이 초기 가설을 다듬을 뿐 추론 오류를 교정하지 못한다**(limited self-correction)는 것이 관측됐다.
> **실무 함의가 직접적이다**: 영상 생성에서 스텝 수를 늘리는 것은 **화질을 올리지 추론을 고치지 않는다.** 구도·물리·인과가 틀린 샷은 **더 오래 돌려도 안 고쳐진다** — 다시 뽑거나 프롬프트/입력 조건을 바꿔야 한다. 내 video-saas 파이프라인의 **재시도 전략**을 바꾸는 관측이다(스텝 증가 재시도 → 조건 변경 재시도).

> [!insight] 최강 모델도 51.0%
> **Seedance 2.0**이 자체 기준 **51.0%** 에 그쳤다. 현행 모델들은 시각 기반 추론 과제의 **일부만** 풀며 신뢰할 수준과는 거리가 멀다. [[Seedance]]는 위키에 VFX 특화로 등록된 모델인데, **생성 품질과 시각 추론 능력이 별개**임을 보여주는 수치다.

> [!warning] 미확인 사항
> - **다른 모델의 개별 점수 미기재** — Seedance 2.0 하나만 공개되어 **모델 간 비교 불가**
> - **"자체 평가 기준(our evaluation criteria)"의 채점 규칙 미공개** — 51.0%가 무엇 대비 51%인지 재현 불가
> - **코드·데이터 미공개 상태**("will release") — 현재 시점 **제3자 재현 불가**
> - 난이도 캘리브레이션("challenging yet partly feasible")의 **기준이 주관적**일 수 있음
> - arXiv ID `2608.19583`는 **미래형 ID**, 초록은 HF API 원문 대조

> [!action] 당장 할 것
> 내 영상 파이프라인 재시도 규칙 점검: **품질 불만 → 스텝/해상도 증가**로 대응하는 분기가 있다면, **구도·인과 오류일 때는 조건 변경으로 라우팅**하도록 분리한다. (근거: 후반 스텝의 자기교정 한계)

## 도메인별 추출 (video-saas)

- **기능 벤치마킹**: 벤치 자체를 구현할 일은 없다. 다만 **"전개 과정 타당성"을 결과 QA 항목으로 넣는 것**은 구현 가능 — 최종 프레임만 보지 말고 중간 프레임의 인과 일관성을 확인하는 체크.
- **크리에이터 인사이트**: 사용자가 원하는 것은 "예쁜 마지막 컷"이 아니라 **말이 되는 움직임**인데, 현행 모델은 전자에 최적화돼 있다. 51.0%라는 수치가 이 갭의 크기다.
- **프롬프트 패턴**: 직접적 패턴 제시는 없음. 단 **입력 조건 민감도(input condition sensitivity)** 를 분석했다고 명시 — 코드 공개 시 **어떤 입력이 추론 성공률을 올리는지** 확인할 가치가 높다.
- **워크플로우**: 재시도 전략 분리(위 [!action] 참조)가 유일하고 확실한 변경점.
- **디자인 레퍼런스**: 해당 없음.
- **경쟁 우위 빈틈**: **"결과 QA를 과정 기준으로 하는 툴"** 이 비어 있다. [[SemComp-Bench]](의미 완료도 채점)와 VGI-BENCH(전개 타당성)를 합치면 **생성 영상 자동 검수 렌즈**의 밑그림이 된다 — 툴 대비 차별화 지점으로 유효.
