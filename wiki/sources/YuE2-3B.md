# YuE2-3B (m-a-p/YuE2-3B)

> [!insight] 핵심 인사이트 — **가사에서 바로 오디오로 가지 않는다. 중간에 「악보」를 놓는다**
> 30일 다운로드 **971**(2026-09-12 HF API 실호출 · raw와 **일치**) · ♥**271**(raw와 **일치** · 오늘 모델 3건 중 **좋아요 최다**) · **cc-by-nc-4.0** · created **2026-09-09** · modified 2026-09-11 · `pipeline_tag: text-to-audio` · safetensors **3,630,684,224(3.63B)**.
> 파이프라인 4단계: **기호적 기획(symbolic planning) → 시맨틱 생성 → 합성 → 디코드**. 카드 55행: *"Turn lyrics and a style prompt into a complete song with vocals and accompaniment, then **shape its melody and chords through an editable score**."*
> 🎯 요점은 품질보다 **편집 가능성**이다. 중간에 **사람이 고칠 수 있는 악보 표현**이 있어서, 결과가 마음에 안 들 때 **프롬프트를 다시 굴리는 대신 멜로디·코드를 직접 수정**한다. [[국소-수리-원리]] 가 음악 생성에 나타난 형태 — 같은 배치 [[Mi-Ripple]](이미지 열화를 전체 재생성 대신 진단 후 국소 처리)과 **같은 사고**다.

> [!note] 소비자 GPU 실사용 가능 — 카드 표 실측 (raw 일치)
> 카드 251·255행 원문 대조:
> - **RTX 4090 24GB / CoT full**: LM **139.48 tokens/s** · **생성 71.04초 → 오디오 214.85초**(≈3.58분) · **피크 VRAM 11.18 GiB**
> - melody 모드: 68.68 / 214.67초 · 11.02 GiB · off 모드: 57.91 / 196.88초 · 11.09 GiB
> - 조건(273행): PyTorch 2.10 · Transformers 4.57.6 · **양자화 없음** · 4090 값은 **32회 웜 요청 평균** · NVML 전구간 피크
> → raw의 *"3.6분 곡을 71초에 생성(VRAM 11.18GiB)"* **정확**. **실시간 대비 약 3배 빠르고 24GB 카드에서 절반만 쓴다** → 소비자 하드웨어 실사용 가능이 맞다.
> → 다만 *"양자화 없음"* 이 명시돼 있으므로 **이 수치는 최선의 조건**이다.

> [!warning] 🔴 **"Suno 상회"는 카드의 프레이밍이다 — 실제 2위는 Mureka 9이고 격차는 0.0255**
> raw 기록: *"WildSongBench 평균 6.9632로 **Suno v5(6.8721)·v6(6.5562) 상회**"*.
> **수치 자체는 전부 정확하다**(볼트 카드 표 300~314행 실측 확인). 문제는 **비교 대상 선택**이다.
> **볼트가 표 전체를 읽은 결과 — SongBench Avg 순위:**
> - **YuE2 (best-of-8) 6.9632** ← 1위
> - **Mureka 9 — 6.9377** ← **2위. 격차 +0.0255**
> - Suno v5 6.8721 (격차 +0.0911) · Suno v5.5 6.7150 · Suno v4.5 6.6995 · Suno v6 6.5562 · Suno v6 Wild 6.4195
>
> → 🎯 **raw가 인용한 "Suno v5 대비 +0.0911"은 실제 최근접 경쟁자와의 격차의 3.6배다.** 진짜 마진은 **Mureka 9 대비 +0.0255**다.
> → **이건 raw만의 잘못이 아니다** — 카드 헤드라인(55·57행) 자체가 **Suno만 지목**한다(*"competitive with **Suno v5/v6**"*). Mureka 9는 표 안에만 있다. **모델 카드가 비교군을 골라 제시했고 raw가 그 프레임을 그대로 옮겼다.**
> → [[한정어-탈락]] 의 변종: 한정어를 뗀 게 아니라 **문서가 이미 좁혀 놓은 비교 프레임을 검증 없이 승계**했다. 처방은 같다 — **표가 있으면 헤드라인이 아니라 표를 읽는다.**
>
> **📊 그리고 지는 축이 있다 (09-09 누락 금지 규칙 적용 · raw 미기록):**
> - **Q3O(프롬프트 준수, 0~5)**: YuE2 **0.5051** vs **Suno v5 0.5428**(표 내 최고) → **진다**
> - **PER(음소 오류율, 낮을수록 좋음)**: YuE2 **9.79%** vs Suno v5 8.10% · **Suno v4.5 5.80%(최저)** → **진다**
> - 이기는 축: Musicality **6.2666** · SongBench Avg **6.9632** · 한 지표 **4.7009** (표 내 최고)
> → 🎯 **요약하면: 음악성은 1위, 가사 전달과 지시 준수는 하위권이다.** *"프론티어 품질"* 이라는 카드 표현은 **음악성 축에 한정**된다.

> [!warning] 측정 프로토콜 — 조건이 균일하지 않다
> - **best-of-8**: 카드 316·335행 원문 — *"Standard YuE2 selects from **two** candidates; best-of-8 selects from **eight**."* 선택 기준은 Musicality → Q3O → PER. **1회 생성 비교가 아니다.** raw **정확히 지적**.
> - 비교군 프로토콜이 **다르다**(335행): 오픈 베이스라인·Suno v6·v6 Wild는 후보 2개 + 후보당 ASR 4회 → 낮은 PER 선택. **초기 상용 시스템은 "delivered-candidate" 프로토콜 유지.** → **모든 행이 같은 조건이 아니다.**
> - Q3O 가중치가 **192개 프롬프트 중 10개에서 두 YuE2 설정 간에 다르다**(335행 자기 고지)
> - **Suno v6(6.5562) < v5(6.8721)** — 신버전이 구버전보다 낮다. raw가 *"측정 프로토콜 확인 필요"* 로 표시한 것 **타당**. 볼트 판단: v6 Wild(6.4195)까지 함께 낮은 것을 보면 **평가 세트·채점 방식이 Suno 신모델 성향과 어긋날 가능성**이 있다. **단정 불가.**
> - 카드 63행이 표 갱신일을 **"September 12, 2026"** 로 적는다 — **오늘이다.** 매우 신선하지만 **제3자 재현 시간이 없었다는 뜻**이기도 하다.
