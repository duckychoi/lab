# needle (cactus-compute/needle)

> [!insight] 핵심 인사이트
> ⭐3,132 (2026-07-15, 당일 +92). **단 2,600만(26M) 파라미터로 함수 호출(function calling / tool use)만 초경량으로 처리하는 온디바이스 특화 모델.** 범용 대화·추론을 포기하고 "사용자 발화 → 어떤 도구를 어떤 인자로 부를지" 라우팅 한 가지에 집중해, 스마트폰·임베디드·웨어러블에서도 상시 구동 가능한 크기로 줄인 것이 핵심. [[MiniCPM5-1B]](1B, think+도구호출)·[[cactus-compute]] 계열 온디바이스 스택보다 **한 자릿수 더 작은** 극단적 경량화로, "에이전트의 도구 호출 판단만 로컬에서, 실제 추론은 상위 모델로" 하는 2단 분업 아키텍처의 밑단 후보. 함수 호출은 에이전트 루프에서 가장 빈번·정형적이라 초소형화 이득이 큰 지점.

## 도메인별 추출 (local-llm 템플릿)

- **실용성 판단**: MAYBE — 26M은 CPU·모바일 NPU에서 초저지연·초저전력 실행권. 단 26M 모델의 도구 라우팅 정확도(오호출률)가 실사용 임계치를 넘는지 실측 필수.
- **메모리 아키텍처**: 초소형 전용 분류·슬롯필링에 가까운 구조로 추정. 범용 지식이 아닌 "도구 스키마 → 인자 추출" 특화.
- **Hermes 적용**: 가능성 있음 — 상위 모델 앞단 라우터로 두면 토큰·지연·비용을 줄이는 게이트 역할. ChinameBot류 봇의 도구 호출 판단을 로컬에서 선처리.
- **트레이드오프**: 크기↓↓·속도↑↑ but 복잡한 다단계 도구 계획·모호한 발화 처리는 상위 모델 위임 불가피. 단일 턴 함수 호출에 국한.
- **오픈소스 구현체**: https://github.com/cactus-compute/needle — 온디바이스 배포 파이프라인 동반 예상.
- **액션**: 도구 스키마 5~10개로 오호출률·지연 벤치 → "로컬 라우터 + 클라우드 추론" 2단 분업 실현성 판단.

> [!note] 온디바이스 에이전트 분업 각도
> 에이전트 지연·비용의 상당 부분이 "매 턴 도구 호출 판단"에 쓰인다. 이걸 26M 로컬 모델로 내리면 상위 대형 모델 호출 횟수를 줄일 수 있음 — [[에이전트-메모리-레이어]]의 경량 백엔드 논의와 같은 결(무거운 일은 상위, 빈번·정형은 로컬).
