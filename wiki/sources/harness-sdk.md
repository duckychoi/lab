# harness-sdk

> [!insight] 핵심 인사이트 — 판매하는 것은 SDK가 아니라 **루프의 개입 지점**이다
> 컨텍스트 관리·실행 제한·관측성을 **설정 없이 기본 내장**하고, **훅으로 에이전트 루프의 임의 단계를 가로채 로깅·검증·리디렉트**할 수 있게 한다. MCP·스트리밍·멀티에이전트·구조화 출력 포함. Python·TypeScript 양쪽.
> 🎯 **이 배치에서 같은 축을 다루는 것이 4건이다** — 이것(SDK) · [[SoL-Pi]](자동탐색) · [[Harness-Design-Empirical]](대조실험) · [[NeoHorse-1-4B]](라우팅 하네스로 학습데이터 생성). **하네스가 하루치 트렌딩의 31%를 먹었다** → [[하네스-설계-축]]
> 🔴 **그리고 그 4건 중 이것만 측정치가 없다.**

> [!warning] 🔴🔴 볼트 최대 발견 — **열린 이슈 763개, ★의 10.39%다**
> ```
> 배치 5건 open issues / ★ 비율 (2026-09-18 볼트 API 실측)
>   harness-sdk      763 / 7,345  = 10.39%   ← 🔴
>   FastVideo        192 / 4,467  =  4.30%
>   BrowserSkill      51 / 4,740  =  1.08%
>   opensre           52 / 11,124 =  0.47%
>   MiniCPM           18 / 11,078 =  0.16%
> ```
> 🎯 **배치 중위값(1.08%)의 9.6배이고 최저값(MiniCPM 0.16%)의 65배다.**
> 🔴 **이 수치가 카드의 핵심 주장과 정면으로 부딪힌다.** 카드는 *"Guardrails catch mistakes before they run"* 이라 적었고 관측성·실행제한이 **설정 없이 동작**한다고 말한다. **그런데 미해결 이슈가 ★의 10분의 1이다.**
> ⚠️ **볼트는 이것을 품질 판정으로 쓰지 않는다** — 열린 이슈는 ① 버그 ② 기능 요청 ③ 방치 ④ **활발한 사용의 부산물** 을 구분하지 못한다. 1년 4개월차 · 당일 커밋(2026-09-18T08:00) 레포이므로 **방치는 아니다.**
> 🎯 **볼트가 말할 수 있는 것은 이것뿐이다: 무설정 동작을 주장하는 제품에서 이 비율은 배치 내 유일한 이상값이며, 그 원인을 README로는 알 수 없다.** → [[메타데이터-부재-추론]] 규율대로 **"나쁘다"가 아니라 "확인 필요"로 적는다.**
> 📌 **볼트 척도 신설**: 앞으로 GitHub 레포는 `open issues / ★` 를 함께 기록한다. 배치 5건으로 얻은 **잠정 대역은 0.16~1.1%가 정상, 4% 이상은 확인 대상**이다(표본 5, 신뢰도 낮음 — 누적 필요).

> [!warning] 🔴 성립 조건 — 기본값이 AWS다
> 카드 명시: **두 SDK 모두 기본 프로바이더가 Amazon Bedrock** 이라 **AWS 자격증명 + Claude Sonnet 모델 접근**이 필요하다. Anthropic·OpenAI·Gemini·Ollama는 **별도 설정**.
> 🎯 카드 설명은 *"any model, any cloud"* 다. **`any` 는 도달 가능성이고 기본값은 단일 벤더다** — 둘은 같은 문장에 있으면 안 되는 말이다 → [[한정어-탈락]] 의 **역방향 사례**(저자가 한정어를 *빼서* 범위를 넓혔다).
> 🔴 **벤치마크 섹션 자체가 없다**(155행 README, 전 섹션 헤딩 11개 스캔 완료). *"Guardrails catch mistakes before they run"* 은 능력 주장인데 **측정치가 0개**다.
> → [[opensre]] 와 대조하면 갈린다: opensre는 **주장을 안 했고**, 이건 **주장하고 안 쟀다.** 그래서 reliability가 다르다(high vs **medium**).

## 도메인별 추출 (ai-news)

- **신뢰도**: ★7,345 · Apache-2.0 · 당일 커밋. 🔴 **reliability medium** — 이유 2개: ① 능력 주장(`Guardrails catch mistakes`)에 측정치 0 ② `any cloud` 와 `기본값 Bedrock` 의 간극. ✅ 지표는 raw와 +1 드리프트로 일치.
- **즉시 활용**: 🔴 **NO — 기본값이 AWS다.** 내 스택에 AWS 자격증명이 없다. 별도 설정으로 Anthropic 직결이 가능하다지만 **그 경로의 문서 성숙도를 확인하지 않았다.** 그리고 나는 이미 Claude Code 하네스를 쓴다 — **하네스를 바꾸는 비용이 이득보다 크다.**
- **6개월 영향력**: 🎯 **"훅으로 루프를 가로챈다"는 인터페이스가 표준이 될지가 관전 포인트다.** [[Harness-Design-Empirical]] 이 같은 날 **컨텍스트 관리 전략의 우열을 대조 실험으로 재놨으므로**, 그 결론(규칙기반 생략 → LLM 요약 순서)을 **훅으로 구현할 수 있는지**가 이 SDK의 실질 가치다. **둘을 같이 읽어야 한다.**
- **대체 관계**: [[pi-agent-harness]](★106,058)와 **정면 경합**이고 규모는 14분의 1이다. 🔴 나는 둘 다 안 쓴다.
- **허와 실**: 걷어내면 — **하네스 부품을 라이브러리로 판 것**이고, 부품의 성능은 **아무도 재지 않았다.** 🎯 같은 날 논문 두 건이 **바로 그 부품들을 측정했다**는 점이 이 레포의 위치를 말해준다: **구현은 앞서 있고 근거는 논문 쪽에 있다.**
- **액션**: **읽기만.** [[Harness-Design-Empirical]] 결론과 훅 API를 대조한다.

> [!action] 당장 할 것
> **훅 API가 [[Harness-Design-Empirical]] 의 결론 ②를 표현할 수 있는지 확인한다** — *"규칙기반 생략을 LLM 요약보다 앞단에"* 를 훅 순서로 강제할 수 있나. 가능하면 이 SDK는 **논문 결론의 실행 환경**이 된다. 불가능하면 그냥 또 하나의 하네스다.

> [!question] 미해결 질문
> **훅이 강제하는 범위**가 문서 사이트 별도 확인 필요(수집기 미확인, 볼트 미확인). **가로채기가 관측만인지 차단까지인지**가 `Guardrails` 주장의 성립 여부를 가른다.
> 그리고 **open issues 763의 내부 구성**(버그 vs 기능요청 vs 방치)을 조회하지 않았다 — 라벨별 집계가 필요하다.
