# EvoDuet (Bilevel Co-Evolution of Web Searching and Task Solving)

> [!insight] 핵심 인사이트
> **"검색 도구를 붙였는데 왜 안 늘었나" 를 정확히 진단하고 그 진단이 설계를 결정한다.** 진화 탐색은 모델에 없는 외부 지식이 필요한 지점에서 멈추는데, 웹검색을 그냥 붙이면 **해(solution)가 바뀌어도 같은 페이지만 계속 돌아온다** — 쿼리가 진화하지 않기 때문이다. EvoDuet 은 **모델 파라미터를 고정한 채 해와 검색 쿼리를 함께 진화**시킨다.
> 🎯 **구조는 3층이다**: ① **검색 게이트** — LLM 이 자기 지식 격차를 평가해 *신규 검색 / 기존 재사용 / 검색 없이 진행* 중 선택 ② **내부 루프** — 쿼리를 정제하고 문서를 *"그 문서가 산출할 것으로 예측되는 해 점수"* 로 순위화 ③ **외부 루프** — 그 문서들로 후보를 병렬 생성하고 평가 결과를 **다음 검색을 위해 기록**한다.
> 🏆 **주목할 점: 학습이 없다.** 파라미터 고정 + 루프 설계만으로 이득을 낸다 → [[하네스-설계-축]] 의 순수 사례.

## 도메인별 추출 (ai-news)

- **신뢰도**: ⭐⭐ — 초록 전문 1,305자 확보, 수치 7개 대조. 🔴 PDF·코드 미확인 → medium.
- **즉시 활용**: 🎯 **MAYBE — 오늘 5건 중 모델 의존이 가장 낮다(파라미터 고정).** 볼트에 직접 쓸 수 있는 조각은 **검색 게이트**다: 볼트 인제스트도 매일 같은 API 를 같은 방식으로 호출해 *"해가 바뀌어도 같은 페이지"* 문제를 그대로 갖고 있다([[선발창-누락]] 이 그 증상이다 — 증분 기준만 쓰니 [[openclaw]] ★391K 가 10개월간 한 번도 안 걸렸다). **"기존 재사용 / 신규 검색 / 건너뛰기" 3분기를 선발 단계에 넣는 것**은 모델 없이 가능하다.
- **6개월 영향력**: 중간. OpenEvolve · Top-K · EvoX 등 **여러 스캐폴드에서 작동**한다고 주장하므로 진화탐색 계열의 **표준 보강**이 될 수 있다.
- **대체 관계**: OpenEvolve 를 **대체 아니라 보강**(정규화 발견 이득을 끌어올림). 다른 스캐폴드(Top-K · EvoX)에도 Sums/Diffs · Denoising 에서 개선.
- **허와 실**: 🔴 **모델 의존성이 조건부다 — 저자가 명시한다**: *"whereas **Qwen3.5-9B does not benefit**"*. 🎯 **이득이 나는 모델과 안 나는 모델을 같은 문장에 적었다** → [[자기제한-명시]] **3일 연속 수집**.
  - 🔴 **배수 주의**: Gemini-3.8-Flash 는 61.3 → 82.3(**+21.0p**)이고 GPT-5.6-Luna 는 74.1 → 78.0(**+3.9p**). **출발점이 낮은 모델에서 이득이 5.4배 크다** — *"EvoDuet 이 좋다" 가 아니라 "약한 베이스의 격차를 메운다" 로 읽어야 한다*([[분포내-우위]] 계열 주의).
- **액션**: 검색 게이트 3분기를 볼트 선발 단계 설계에 반영 검토 → actionable 등록.
