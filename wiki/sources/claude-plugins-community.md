# anthropics/claude-plugins-community — 벤더가 직접 운영하는 플러그인 배포 인덱스

**GitHub**: https://github.com/anthropics/claude-plugins-community
**지표**: ⭐**1,957** · 포크 **181** · 이슈 **42** · **Python** · **Apache-2.0** · 생성 **2026-03-20** · 최종 푸시 **2026-08-25** — 전량 **GitHub API 실호출 검증**(2026-08-26) · 트렌딩 데일리 **2위**(raw 표기 당일 +351 · raw 절대값 1,954 대비 API **1,957** +3 드리프트)
**소유**: **[[Anthropic]]** 공식 조직 계정(`anthropics/`)

> [!insight] 핵심 인사이트
> **[[에이전트-스킬]] 생태계에서 처음으로 "벤더가 직접 운영하는 배포 레지스트리"가 트렌딩 상위에 올라왔다.** 지금까지 볼트에 쌓인 스킬·플러그인 자산은 전부 **커뮤니티 개인 큐레이션**([[mattpocock-skills]]·[[superpowers]]·[[awesome-agent-skills]]·[[awesome-gpt-image-2]])이었고, 벤더 공식은 [[cursor-plugins]](규격+공식 플러그인)가 유일했다. 이 레포는 그 다음 단계 — **규격이 아니라 "남이 만든 것을 싣는 목록"을 벤더가 소유**하는 형태다.
> 구조적으로 중요한 건 **레포 자체가 read-only 미러**라는 점이다. 등록은 레포에 PR을 보내는 게 아니라 **외부 제출 폼**으로만 이뤄지고, 레포는 그 결과가 반영되는 인덱스 역할만 한다(raw 수집 메모 기준). 즉 **git 레포가 데이터베이스의 뷰(view)로 쓰이는 패턴** — [[apache-maka]]의 append-only 로그가 "실행 기록을 파일로 본다"면, 이건 **"레지스트리를 레포로 본다"**. 스킬 생태계가 자산 축적 단계에서 **배포·심사 인프라 단계**로 넘어가는 신호로 읽는 게 맞다.

> [!warning] 스타 1,957은 볼트 GitHub 소스 중 최하위권 — "벤더 공식"이 곧 채택은 아니다
> 이번 배치 GitHub 5건 중 **압도적 최하위**다([[TradingAgents]] 100,564 · [[ai-job-search]] 35,790 · [[awesome-gpt-image-2]] 19,958 · [[apache-maka]] 3,506 · **본 레포 1,957**). 그런데 **트렌딩 2위** — 이는 [[free-claude-code]] 사례에서 확정한 *"트렌딩은 절대 스타가 아니라 증분 속도를 반영한다"* 는 해석의 재확인이다(당일 +351은 절대값의 **18%**로 배치 최고 증분율).
> 더 주의할 것은 **이슈 42건**이다. 순수 인덱스 미러라면 이슈가 거의 없어야 정상인데([[awesome-gpt-image-2]] 10건 · [[ai-job-search]] 5건), 포크 181 대비 **0.23건/포크**는 자산 레포치고 높다. 등록 절차가 폼으로만 열려 있는 구조에서 **이슈 트래커가 사실상 등록 문의·심사 이의 창구로 쓰이고 있을 가능성**이 크다 — 미확인이며, 이슈 내용은 이번 회차에 실측하지 않았다.

> [!note] 생성 2026-03-20 — 5개월 축적 후의 노출
> 신규 공개가 아니다. 5개월 된 레포이며 최종 푸시 **2026-08-25**(전일)로 갱신은 진행 중이다. 언어가 **Python**으로 잡히는 것은 인덱스 검증·빌드 스크립트 때문으로 추정되며(미확인), 내용물의 본질은 플러그인 메타데이터다.

## 도메인별 추출 (ai-news)

- **신뢰도**: ⭐⭐⭐⭐ high — 소유 조직·라이선스·지표는 **GitHub API 실검증**이고 벤더 공식 계정이라 출처 자체가 명확하다. 다만 **"read-only 미러 + 외부 폼 등록"이라는 운영 방식은 raw 수집 메모 기준**이며 README 원문을 이번 회차에 실측하지 않았다(→ 미해결 질문).
- **즉시 활용**: **YES(탐색용)** — 내가 쓰는 [[Claude-Code-워크플로우]]에 붙일 플러그인을 **개인 레포 검색이 아니라 한 곳에서 훑을 수 있다.** 다만 *등재 = 검증*이 아니다. 마켓플레이스는 **발견 비용을 낮출 뿐 품질을 보증하지 않는다** — [[에이전트-스킬]] 페이지에 기록한 생태계 공통 약점(재현성 벤치 부재)이 그대로 남는다.
- **6개월 영향력**: 스킬·플러그인이 **"레포를 clone"에서 "레지스트리에서 install"** 로 옮겨 가면 내 워크플로우의 관리 단위가 바뀐다. 지금은 스킬을 파일로 직접 두고 있는데(`~/.claude/skills/`), 레지스트리 경유가 표준이 되면 **버전·업데이트·의존성**이 새 관리 대상이 된다.
- **대체 관계**: 대체가 아니라 **탐색 계층 추가**. 기존 개인 큐레이션 목록([[mattpocock-skills]] 등)을 **없애지는 않지만 상대적 가치를 깎는다** — 벤더 인덱스가 커질수록 "awesome 리스트"의 존재 이유는 줄어든다.
- **허와 실**: 실은 **배포 인프라의 등장**이라는 구조 신호. 허는 **"공식 = 안전·고품질"이라는 인상** — 심사 기준이 공개돼 있는지 미확인이고, 등재 항목의 코드 품질·보안 검토 여부는 근거가 없다.
- **액션**: star + **등재된 플러그인 목록을 한 번 훑어 내 워크플로우에 겹치는 것 3개만 추려 실사용 검증** (중간).
