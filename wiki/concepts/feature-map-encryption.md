# 딥러닝 피처맵 보호·학습형 암호화

> 교수님 질문: 딥러닝 피처맵을 암호화하는 AI 기술이 있나?

## 1. 동기 — 왜 피처맵을 가리나
**분할추론(split inference)**: 기기에서 앞단 층 → 중간 **피처맵만 클라우드 전송**. 이 피처맵에서 원본을 복원하는 **model/feature inversion 공격**이 가능 → 보호 필요. (온디바이스·엣지 시나리오 핵심)

## 2. 두 갈래
### 🅰 암호연산형 — 피처맵이 암호문
- **HE(동형암호)**: Enc(a) 위에서 바로 연산. CryptoNets(2016), CKKS-CNN, nGraph-HE. ⚠️ 매우 느림, ReLU 근사.
- **MPC(다자계산)**: 피처맵 비밀분할. Gazelle(HE+MPC), Delphi, Cheetah, CrypTFlow. 통신량↑.
- **TEE**: SGX 엔클레이브에서 민감 층 실행. Slalom(암호+TEE). 하드웨어 신뢰 필요.
- → 증명가능 보안 강점, 비용 약점.

### 🅱 학습형 특징 보호 — "AI다운" 쪽
- **학습형 암호화**(Kiya 그룹): 블록 셔플·채널/픽셀 순열·부호반전으로 피처맵 뒤섞고 **암호 도메인에서 학습**. 키 없으면 복원 불가, 정확도 유지.
- **정보병목·적대적 난독화**:
  - **NoPeek**: 작업손실 + $\lambda\,\mathrm{dCor}(x,z)$ 최소화 (원본 $x$ ↔ 피처 $z$ 거리상관 낮춤).
  - Shredder(노이즈 분포 학습), Cloak, DISCO(채널 프루닝), DPFE(민감속성 적대적 제거).
- **InstaHide**: 믹스업+랜덤 부호 은닉 → ⚠️ Carlini 등에 복원 공격으로 깨짐 (경험적 보안의 위험 사례).
- → 빠르고 정확, 단 증명가능 보안 약함.

## 3. 삼각 트레이드오프
**정확도 ↔ 보안강도 ↔ 연산/통신비용** — 셋 다 동시 만족 불가.
- HE/MPC: 보안 확실·느림 / 학습형: 빠름·휴리스틱 보안 / TEE: 중간·HW 신뢰.

## 4. 🟢 빈 땅 (연구 포지션)
1. **"양자화 = 피처맵 보호" 공동학습**: 4bit 압축이 동시에 inversion을 차단하도록 학습(경량화×프라이버시 일석이조).
2. **물리계층 피처암호**: 피처맵을 랜덤 빔/위상으로 전송 → **학습형 난독화 × 물리계층 보안(PLS)**.
