# 컨테이너 중복

> [!insight] 한 줄
> **`org/name` 리터럴 필터는 수집 단위 하나에 지식 객체 여러 개가 들어 있을 때 *올바르게* 통과시킨다. 필터가 틀린 게 아니라 단위가 1:1이 아니다.**

## 09-17 파생 중복과 구조가 반대다

```
파생 중복 ([[파생저장소-식별]], 09-17)
  원본 1 → 파생 N        같은 지식, 이름이 여러 개
  탐지: cardData.base_model (1홉) + 이름 부분문자열 (N홉)

컨테이너 중복 (09-18, 신설)
  레포 1 ⊃ 모델 N        한 이름, 지식이 여러 개
  탐지: 🔴 키가 없다
```

🎯 **두 유형은 같은 필터를 서로 반대 방향으로 무력화한다.** 파생은 **이름이 갈라져서** 못 잡고, 컨테이너는 **이름이 하나여서** 못 잡는다.

## 발견 사례 — [[MiniCPM]] (2026-09-18)

`github.com/OpenBMB/MiniCPM` 리터럴 **0히트 = 레포로서 진짜 미수집**이었다. ✅ **필터는 정확히 동작했다.**
🔴 **그러나 이 레포가 발표하는 모델이 HF 모델 페이지로 볼트에 4건 있었다**: [[MiniCPM5-2B]]·[[MiniCPM5-1B]]·[[MiniCPM5-2B-GGUF]]·[[MiniCPM-V-4.6]].
**레포 1개가 모델 4계열**(MiniCPM5-2B · MiniCPM5-1B · MiniCPM-SALA · MiniCPM4/4.1)을 담는다. README **1,373행 · 표 19개 · `### Evaluation Results` 섹션 4개**, 각 섹션의 소유 모델이 다르다.

> [!warning] 🔴 09-17의 2·3차 키가 채널을 넘으면 무력하다
> GitHub 레포에는 **`cardData.base_model` 이 없다.** 이름 부분문자열도 여기서는 무의미하다 — 컨테이너 이름(`MiniCPM`)은 구성원 이름의 접두사이므로 **부분문자열 매칭이 오히려 과탐**한다(MiniCPM5-2B·MiniCPM4·MiniCPM-V 전부 히트).
> 🎯 **결론: 교차유형 중복은 메타데이터 필터로 잡을 수 없다.**

## 볼트 판정 — 탐지 경로는 자진신고뿐이다

✅ **그리고 09-18 수집기가 실제로 자진신고했다** — 선발 후 자기 검증에서 걸러 *"유형을 넘으면 중복이다"* 라고 적고 판정을 요청했다. 🎯 **이 배치에서 가장 잘한 일이고, 필터로 대체 불가능한 종류의 기여다.**

📌 **처리 규약 (볼트 확정)**
1. 컨테이너에 **문서화된 신규 구성원**이 있으면 → 컨테이너 페이지를 **만든다**([[파생저장소-식별]] 의 *"새 축이 문서화됐는가"* 기준을 그대로 적용)
2. 🔴 **컨테이너 페이지는 이미 개별 페이지가 있는 구성원의 수치를 복제하지 않는다.** 구성원 목록 + 링크 + **컨테이너 고유 사실**(표 개수·귀속 구조·배포 정책)만 적는다
3. **상호링크는 장식이 아니라 중복 서술 금지 규약이다** — 복제하면 같은 사실이 두 곳에서 갈라진다
4. 지표(★·fork)는 **컨테이너에만 귀속**시킨다 — *"★11,078"* 은 어느 모델의 지표도 아니다

> [!warning] 🔴 이 개념의 한계 — 표본 1
> 사례가 **[[MiniCPM]] 하나**다. 다른 컨테이너형(모노레포 SDK·모델 허브·awesome 리스트)에서 같은 구조가 반복되는지 **미확인**. 특히 [[harness-sdk]] 같은 **6패키지 모노레포**가 같은 문제를 일으키는지 보지 않았다.
> 📌 **다음 배치에서 확인할 것**: 컨테이너 여부를 **수집 시점에 판별**할 수 있는 신호가 있는가(README 행 수? 평가 섹션 개수? `### ` 헤딩 밀도?).
