# 벤치마크-이미지-봉인

> [!insight] 정의
> **성능 주장은 문자로 하고, 그 근거 수치는 이미지 안에만 두는 관행.** 문서는 검색·인용·대조가 가능한 형태로 *주장*을 노출하지만, *값*은 PNG에 봉인되어 **텍스트 파이프라인에서 구조적으로 조회 불가**해진다.

## 왜 별도 개념인가

[[표-부분인용]] 은 **표가 있는데 일부만 옮기는** 독자 측 오류다. 이 개념은 **표가 애초에 텍스트로 존재하지 않는** 생산자 측 형식 선택이다. 🎯 **부분인용은 독자가 고칠 수 있고, 이미지 봉인은 고칠 수 없다.**

[[검사가능성-후퇴]] 와도 다르다. 후퇴는 *있던 산출물을 뺀* 시간적 변화이고, 봉인은 *처음부터 그 형식으로 낸* 정적 상태다. ([[Ternary-Bonsai-2-27B]] 는 전자, [[hindsight]] 는 후자)

## 누적 사례 (4건)

1. **[[PageIndex]]**(09-20) — 정확도가 *"그림 안에만"*. 러너·데이터·결과를 열어 둔 **열린 자기평가**인데 정작 점수가 이미지.
2. **[[agent-desktop]]**(09-24) — 한 단계 나쁜 형태. 수치가 `<img alt=>` **속성 안**에 있었다(30,743→383 = 98.75%). 🔴 그리고 **그 값이 헤드라인 범위(78–96%)를 위로 벗어났다.**
3. **[[hindsight]]**(09-26) — README **442행 본문 벤치 수치 0개**. *"most accurate agent memory system ever tested"* 바로 다음 줄이 `![Overview](…/hindsight-benchmarks.png)`.
4. **[[Qwen-Image-2.1]] / abenzerps UC-GGUF**(09-26) — 카드 `## Benchmark` **섹션의 내용이 이미지 1줄뿐**. 카드 전체에서 `%` 포함 줄 **0개**.

🎯 **3·4번이 같은 날, 서로 다른 생태계(GitHub 에이전트 메모리 / HF 이미지 양자화)에서 나왔다.** 특정 분야의 습관이 아니라 **형식의 편의**가 원인임을 시사한다 — 벤치 표를 마크다운으로 유지하는 비용보다 스크린샷 한 장이 싸다.

## 판정 규칙 (볼트 적용)

> [!warning] 봉인된 주장은 reliability **medium 이하**
> - 수치가 이미지에만 있으면 **"대조 불가"** 로 기록하고 주장을 인용할 때 **반드시 봉인 사실을 병기**한다.
> - 🎯 **단 low 로 내리지는 않는다** — [[hindsight]] 처럼 **누가 쟀는지(제3자 재현 여부)를 문자로 밝히면** 검증 경로가 남는다. **값의 봉인과 절차의 봉인은 다르다.**
> - 부속 논문·대시보드가 있으면 **actionable 에 "문자 수치 확보" 등록**(값이 다른 곳에 있을 수 있다).

## 탐지 시 함정 — grep 은 양방향으로 속인다

> [!warning] 🔴 마크업 속성이 거짓 음성과 거짓 양성을 모두 만든다
> - **거짓 음성**(09-24 [[agent-desktop]]): 어휘 grep(`benchmark|measured|baseline`)이 487행 전수에서 **0건**인데 수치는 `<img alt=>` 안에 있었다. → 속성을 **통과**한다.
> - **거짓 양성**(09-26 [[paperclip]]): 수치 grep(`[0-9]+%`)이 **5건**을 반환했는데 전부 HTML 표의 `width="33%"`·`width="50%"` 였다. 데이터는 **0건**. → 속성을 **데이터로 착각**한다.
>
> 📌 **같은 원인(HTML 속성)이 반대 방향의 오류를 낸다.** 볼트 grep 규칙: 수치 탐색 시 `alt=`·`title=`·`width=`·`height=` 를 **먼저 제외**하고, 그 뒤 **따로** 속성만 훑는다.

## 🔓 2026-09-28 — **봉인에 범위 한정자를 붙인다 (볼트 자기정정)**

이 개념의 창설 사례는 [[hindsight]] 였다. 볼트는 2배치 연속 *"벤치 수치는 **문자로 존재하지 않는다**"* 라고 썼다.

**09-28 볼트가 `benchmarks.hindsight.vectorize.io` 를 직접 열었고, 수치는 서버렌더 텍스트로 전부 공개돼 있었다.** 7개 모델 × 9개 지표의 완전한 표를 확보했다.

> [!warning] 🔴 볼트가 [[한정어-탈락]] 을 저질렀다
> 참이었던 것: *"**README 안에** 문자로 존재하지 않는다"*.
> 볼트가 쓴 것: *"문자로 존재하지 않는다"*.
> **범위를 떨어뜨린 채 일반화했다.** 그리고 그 일반화를 개념 페이지의 창설 근거로 썼다.

### 하위 유형 2종

| 유형 | 정의 | 해제 방법 | 오늘 사례 |
|---|---|---|---|
| **저장소-로컬 봉인** | README 에는 없지만 **다른 도메인/사이트에 텍스트로 있다** | **한 번 더 찾아본다** | [[hindsight]] — 해제됨 ✅ |
| **벤더-전역 봉인** | 어디에도 텍스트가 없다(이미지·SPA·비공개) | 렌더링 환경 필요 또는 해제 불가 | [[hindsight]] 의 **시스템 간 비교**는 여전히 이쪽 🔴 |

🎯 **같은 벤더가 두 층위를 동시에 갖고 있다.** *"어느 LLM을 쓸까"*(모델 내 비교)는 **열려 있고**, *"Hindsight 가 경쟁사보다 낫나"*(시스템 간 비교, **README의 실제 SOTA 주장**)는 **SPA라 닫혀 있다.**
📌 **열린 쪽은 주장의 옆칸이고, 닫힌 쪽이 주장 그 자체다.** 이 배치가 우연인지 설계인지 볼트는 모른다.

### ⚖️ 규약 (볼트 자기구속)

이후 *"수치가 봉인됐다"* 를 쓸 때는 **확인 범위를 반드시 병기한다** — *"README 442행 전문 기준"* 처럼. 범위 없는 봉인 선언은 금지한다.
📌 **그리고 봉인을 선언하기 전에 최소 1회는 벤더의 다른 도메인을 찾아본다.** 오늘 비용은 `curl` 두 번이었다.

### 🔴 새로 붙는 위험 — [[캐치올-200]]

봉인 해제 과정에서 **더 나쁜 형태**를 만났다. 리더보드가 원본 실행 출력을 링크하는데, **그 링크들이 200 OK 를 반환하면서 실제로는 SPA 셸을 준다.** 볼트가 지어낸 엉터리 경로까지 **md5 동일**이었다.
🎯 **봉인은 "못 읽게 한다" 이고 캐치올 200 은 "읽었다고 믿게 한다" 이다. 후자가 검증 절차를 통과하므로 더 위험하다.**

> [!insight] 🔓 2026-09-29 — **[[hindsight]] 봉인 완전 해제. 3배치 추적의 결말은 "봉인이 아니라 볼트의 조회 실패"였다**
> 이 개념의 대표 사례였던 [[hindsight]]("점수가 이미지 안에만 있다")는 **두 단계로 풀렸다**:
> 1. **09-28** — `benchmarks.hindsight.vectorize.io` 에 서버렌더 텍스트로 공개돼 있었다 → *"저장소-로컬 봉인"* 개념 분화
> 2. **09-29** — **논문 arXiv 2512.12818 에 system-vs-system 수치가 문자로 있었다**(LongMemEval **91.4%** · LoCoMo **89.61%** vs 최강 기존 오픈 **75.78%** · 20B 백본 **39% → 83.6%**). 🔴 **볼트가 3배치 동안 "논문 무응답"으로 기록한 것은 `curl` 의 301 미추종이었다** → [[무응답-오귀속]]
> 📌 **개념 수정**: *"봉인"* 판정 전에 **최소 3경로를 확인한다** — ① 저장소(README) ② 벤더 도메인 ③ **논문(arXiv)**. 세 번째를 빼먹은 것이 이번 실패다.
> 🎯 **같은 날 같은 교훈이 [[LTX-2.5]] 에서도 반복됐다** — 모델카드가 `gated: auto` 로 막혀 있었는데, **HF API `tags` 의 `arxiv:2601.03233` 가 논문 주소를 흘렸고 거기 구조(14B+5B)가 전부 있었다.** **봉인은 대개 한 채널에만 걸린다.**
> 🔴 **반대 사례도 같은 날 도착했다** — [[HexaAnything]] 은 **논문 초록 자체에 수치가 없다**(*"improves ... over XR-1 VLA"*). **이건 채널을 더 찾아도 안 풀리는 종류**다(본문에만 있거나 아예 없다). 봉인의 두 유형을 구분한다: **채널 봉인**(우회 가능) vs **보고 유보**(우회 불가).

🎯 **커널 컴파일러와 이미지 모델은 공통 관행을 가질 이유가 없다.** 📌 **그런데 같은 형태로 봉인됐다** ⇒ **이것은 분야 문화가 아니라 README/모델카드라는 매체의 속성이다.** 표를 쓰는 비용이 이미지를 붙이는 비용보다 높고, 벤치 결과는 보통 플롯으로 먼저 생산된다.

🔴 **TileLang 에서 텍스트로 확인된 유일한 정량치는 *"DeepSeek V3.2 top-k 최적화 ≈1.9배"* 1건이고, 이것도 "reported benchmark" 라는 자기 인용이다.**

> [!insight] 🎯 자매 개념과의 경계가 정리됐다
> | 개념 | 증거의 상태 |
> |---|---|
> | **벤치마크 이미지 봉인** | 수치가 **이미지에 갇혀 있다**(존재하나 읽을 수 없다) |
> | [[선언된-구현체-공백]] 🆕 | **레포는 있고 내용이 비어 있다** |

> | [[CorrGRPO]] 형 | 🔴 **텍스트에도 이미지에도 없다** — 초록이 *"improvements"* 정성 표현으로 끝남 |
> 📌 **마지막 유형이 가장 나쁘다.** 이미지 봉인은 **사람이 보면 읽을 수 있다**(볼트가 못 읽을 뿐). CorrGRPO 는 **아무도 읽을 수 없다.**
