> 3. **동결·감소는 이제 "관측 실패"로 남기지 않는다** — 누적 축으로 교차 확인한다. (기존 [[Qwen3.8-27B]] 109행의 *"격일 갱신 가설"* 도 누적 축으로 재검토 가능해졌다)
> 4. 창 길이는 **⬜ 문서 미확인** 상태로 표기한다. "30일"을 단정하지 않는다.

## 🏆 2026-10-02 — **규칙이 정교해졌다: 기준은 `createdAt` 이 아니라 공개일이다**

[[Nemotron-3-Diarization]] 실측에서 **10-01 에 굳힌 규칙이 반례를 만났다.**

```
downloads(30일)   = 40,936
downloadsAllTime  = 40,936     ← 일치
createdAt         = 2026-09-01 → 나이 31일 (30일 초과)
```

🔴 **10-01 규칙대로면 불일치해야 한다**(*"나이 30일 초과 → 창 밖 일자 존재 → 감소/불일치"*). **일치했다.**

✅ **원인이 카드에 있다 — `Release Date` = 2026-09-23.** 레포 생성(09-01)과 실제 공개(09-23) 사이 **22일간 다운로드가 ~0** 이었으므로, **나이가 30일을 넘겨도 창 밖 구간에 실제 다운로드가 없어 두 값이 일치한다.**

> [!action] ⚖️ 규칙 정교화 (2026-10-02 발효)
> **`createdAt` 나이 30일 초과는 두 값 불일치의 필요조건이지 충분조건이 아니다.**
> 판정 기준은 나이가 아니라 **"창 밖 구간에 실제 다운로드가 있었는지"** 이고, 그것을 가르는 것은 `createdAt` 이 아니라 **공개일(`Release Date` · 카드 기재)** 이다.
> 🎯 **이로써 이 개념의 변수가 3개로 분해됐다**: `createdAt`(레포 생성) · **`Release Date`(실제 공개)** · 조회 시점. **10-01 까지 볼트는 첫째와 셋째만 보고 있었다.**
> 📌 즉 레포 생성과 공개 사이의 **잠복 기간**이 세 번째 변수였고, 그것이 없다고 암묵 가정하고 있었다 → [[암묵을-명시로]].
