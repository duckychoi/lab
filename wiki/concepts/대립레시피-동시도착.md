# 대립 레시피 동시 도착

> [!insight] 🎯 핵심 — **2026-09-27 배치에 포스트트레이닝 RL 의 정반대 답 두 개가 같이 왔다**
> - **[[Rufus-Air]]**: **8단계 직렬.** SFT → Reasoning RL → Coding RL → Instruction-Following RL → General Agent → Coding Agent → Search Agent → RLHF. 🎯 주장하는 원칙은 *"**리워드 신뢰도가 단계 순서를 정한다**"* — 검증 가능한 리워드를 먼저, 애매한 것을 나중에.
> - **[[MiMo-V2.6-Pro-RL]]**: **단일 혼합 런("You Only RL Once").** 코딩·일반 에이전트·비주얼·사이버보안을 **한 배치에 섞어** 한 번에 돌린다. 🎯 주장하는 이득은 *"학습에서 본 적 없는 하니스로도 전략이 전이된다"*.
>
> 🔴 **분리와 혼합은 양립하지 않는다.** Rufus-Air 의 전제는 *단계를 나눠야 리워드 품질을 관리할 수 있다*이고, MiMo 의 전제는 *섞어야 전이가 생긴다*이다. **한쪽이 맞으면 다른 쪽은 차선이다.**
> 📌 **그런데 둘 다 상대를 언급하지 않고, 둘 다 자기 방식으로 좋은 결과를 얻었다고 보고한다.**

> [!warning] 🔴 이것이 볼트에 주는 문제 — 비교 불가능성이 구조적이다
> 왜 어느 쪽이 맞는지 판정할 수 없는가:
> 1. **베이스 모델이 다르다** — Rufus-Air 는 GLM-4.5-Air-Base(106B-A12B), MiMo 는 자사 1.024T 옴니모달.
> 2. **평가 벤치가 겹치지 않는다** — Rufus-Air 는 **벤치 이름조차 초록에 없다**, MiMo 는 18개 벤치를 제시하나 **3개가 자사 명칭**이다.
> 3. **목표가 다르다** — Rufus-Air 는 *재현 가능한 레시피 공개*, MiMo 는 *플래그십 성능*. **최적화 대상이 다르면 설계가 달라지는 것이 정상이다.**
> 🎯 **그러므로 "대립"이라는 볼트의 판정 자체를 조심해야 한다** — 두 논문은 같은 문제의 다른 답이 아니라 **다른 문제의 각자 답일 수 있다.** 이 구분을 볼트는 **초록·카드 범위에서는 할 수 없다.**
> 📌 이것이 [[비매칭-비교]] 의 **메타 층위 사례**다. 지금까지 이 개념은 *하나의 표 안에서 조건이 다른 값을 나란히 놓는 것*을 다뤘다. 여기서는 **볼트가 서로 다른 두 소스를 나란히 놓으려는 유혹**이 문제다 — **비매칭 비교를 벤더가 하는 것이 아니라 독자가 만들 수 있다.**

> [!insight] 🎯 그래도 건질 수 있는 것 — 교집합이 하나 있다
> 두 논문은 방법이 반대인데 **한 지점에서 같은 진단을 한다**: **이진 pass/fail 리워드는 부족하다.**
> - Rufus-Air: *"리워드 **신뢰도**"* 가 순서 결정 기준이다 = 리워드에 **품질 등급**이 있다는 전제
> - MiMo: **GAR**(Groupwise Advantage Reranking) — *"이진 pass/fail 로는 **통과한 해답들끼리** 서열화할 수 없다"* 며 통과 trajectory 를 온라인 서열화
> 🎯 **즉 "통과했다"와 "잘 통과했다"를 구분해야 한다는 데는 둘 다 동의한다.** 방법은 반대인데 **문제 인식은 같다.**
> 📌 **이것이 [[검사가능성-공사]] 의 5번째 외부 생태계 근거다.** 볼트는 09-20부터 *"`✅확인`/`🔴확인 불가` 2값이 부족하다"* 를 알고 있었고 **8일째 3값화를 구현하지 않았다.** 오늘 **대립하는 두 진영이 같은 칸의 필요성을 각자 독립적으로 말했다** — 합의가 아니라 **수렴**이므로 근거가 더 강하다.

> [!note] 볼트 절차 — 대립을 발견하면 무엇을 하는가
> 1. **대립을 기록하되 승자를 정하지 않는다.** 근거가 없으면 판정하지 않는 것이 규칙이다.
> 2. **교집합을 먼저 찾는다.** 반대되는 두 방법이 **동의하는 지점**은 한쪽 진영의 주장보다 강한 증거다.
> 3. **비교 가능 조건을 명시한다** — 무엇이 같아야 비교가 성립하는지 적어 두면, 나중에 그 조건이 갖춰진 소스가 올 때 알아볼 수 있다.
>    → 이 건의 조건: **같은 베이스 모델 + 겹치는 제3자 벤치**. 둘 중 하나라도 만족하는 후속 소스가 오면 재판정한다.
> 4. ⬜ **미확인**: 두 논문이 실제로 상대를 인용하는지(arXiv 본문·기술보고서 미열람). **초록·카드에 없다는 것만 확인됐다.**
