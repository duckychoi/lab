# 배포출처-봉인

> [!insight] 명제
> **배포자가 "공식 산출물은 여기서만 나온다"를 선제적으로 명시하는 서술.** 자기 능력을 제한하는 [[자기제한-명시]] 와 달리, **배포 경로의 정당성을 봉인**해 사칭·복제본을 사용자가 식별할 수 있게 만든다.

## 신설 계기 — [[diagram-design]] (2026-10-10)

> *"Official builds come only from this repository… a listing under any other name is an unofficial copy"*

여기에 `PRIVACY.md` 로 **네트워크 전송 항목을 분리**해 둔다.
⇒ 📌 **공급망 사칭을 README 가 선제 경고한 금일 유일 사례다.**

## 왜 별도 개념인가 — [[자기제한-명시]] 와 축이 다르다

- [[자기제한-명시]]: *"우리 도구는 이것을 못 한다 / 1.0 미만이다 / 포크해서 떠나도 된다"* ⇒ **능력·지배력의 제한**
- **배포출처-봉인**: *"우리 것은 여기서만 나온다"* ⇒ **정체성의 주장**

⚖️ **후자는 제한이 아니라 경계 설정이다.** 사용자에게 주는 효용은 비슷하지만(**신뢰 판단 비용 감소**) 작동 방식이 반대다 — 하나는 권한을 놓고, 하나는 권한을 확정한다.

## 왜 지금 중요한가 — 스킬 배포 포맷이 수렴하는 중이다

2026-10-06 ~ 10-10 두 배치에서 **`skills.sh` / Agent Skills 배포가 5건 관측됐다**([[text-to-cad]] · [[t3code]] · [[rea]] · [[mattpocock-skills]] · [[diagram-design]]).
⇒ 📌 **배포 포맷이 표준화되면 사칭 비용이 내려간다** — 같은 포맷이므로 복제본이 진짜처럼 보인다.
🎯 즉 **배포출처-봉인은 스킬 생태계가 커지면 필요해지는 서술이고, [[diagram-design]] 이 그것을 먼저 했다.**

📌 대조: [[mattpocock-skills]] 는 **중복 설치 위험**을 경고했고([[자기제한-명시]] 축), [[diagram-design]] 은 **출처 사칭**을 경고했다(본 개념 축) ⇒ **같은 날 두 종류의 선제 경고가 나왔다.**

## 한계

🔴 **n=1 이고 검증하지 않았다.** README 서술의 존재만 확인했고, 실제로 비공식 복제본이 존재하는지·봉인이 효과가 있는지는 **측정되지 않았다.**
⚖️ **또한 이 서술 자체가 마케팅일 수 있다** — *"우리만 진짜"* 는 경쟁 억제로도 읽힌다. 금일은 `PRIVACY.md` 분리가 함께 있어 **신뢰 쪽으로 해석했으나 단정하지 않는다.**
