# 동일대상 분리오판

> [!insight] 🏆 2026-10-04 **시간축 유형 2건 — 수집기의 "첫/신규" 표기가 같은 배치에서 두 번 틀렸다**
> 이 개념은 같은 대상을 **다른 둘로 오판**하는 것을 다뤘다. 🆕 **오늘 시간축 버전이 확정된다: 같은 사실의 재관측을 "신규/첫 관측"으로 세는 것.**
> | # | 대상 | 수집기 표기 | 볼트 이력 | 간격 |
> |---|---|---|---|---|
> | ① | [[ponytail]] README 자기 하향 | *"🎯 README 자체가 과거 주장을 하향한다"* | **10-02 에 이미 기록**(*"80~94% → 과제별 상한"* + LOC −54% 표 + *"0이득 구간"*) | **2일** |
> | ② | [[ECC]] 공급망 경고 | *"★27만 하네스가 스스로 사칭 위험을 공지한 **첫 관측**"* | **08-23 에 이미 기록**(*"벤더가 '공식 채널 외 재배포본은 멀웨어 가능성'을 README에 명시"*) | **42일** |
> ⇒ ⚖️ **둘 다 벤더 쪽에 변화가 없고 수집기 쪽 첫 수집일 뿐이다.** 🔴 **그대로 받으면 [[자기제한-명시]] 의 n 이 1건→2건으로 부풀려진다.**
> 🏆 **볼트 규약: 수집기의 "첫/신규/최초" 표기는 볼트 이력과 대조한 뒤에만 사례 수에 반영한다. 오늘 배치에서 그 표기가 2건 틀렸다.**
> ✅ **다만 실질 증분은 분리해 기록한다** — ②에서 수집기는 공식 채널 **6종 목록**(GitHub·npm `ecc-universal`·npm `ecc-agentshield`·GitHub App·플러그인 슬러그·`ecc.tools`)을 적었고 **08-23 기록에는 경고의 존재만 있고 목록이 없었다.** 📌 **"재관측"과 "증분 없음"은 다르다.**
>
> ## 🆕 반대 방향 — **분리해야 할 것을 묶지 않기**([[DMM]])
> 수집기는 [[DMM]] 을 10-03 신설 **"층간 동형 쌍"**([[HC-DLM]] ↔ [[Beyond-Memory-PoS]])의 **3번째 점(n=3)** 으로 제안했다.
> 🔴 **볼트 보류.** 기록된 쌍의 공유 처방은 **"지속되는 단일 상태"** 인데, DMM 의 의도는 **에이전트별로 분산돼 있고 이산적**이다. DMM 이 거부하는 것은 *단일 상태의 부재* 가 아니라 *일회 확정(one-shot commitment)* 이다.
> ⇒ ⚖️ **n 을 올리려면 쌍의 정의를 "지속되는 단일 상태" → "일회 확정 거부" 로 일반화해야 하고, 그러면 반복적 생성 절차 거의 전부가 들어온다**(마스크 확산 자체가 반복이므로 같은 배치 [[E-MoE]] 도 들어온다). 🔴 **범위를 넓혀 n 을 키우면 "무관한 분야가 독립 도달했다"는 원래의 강한 신호가 희석된다.**
> ✅ **처리: n=2 유지 + DMM 을 인접한 별개 패턴 "일회-확정-거부"로 분리 기록.** 🏆 **묶을지 나눌지는 사례가 더 모이면 판정한다 — 지금 묶으면 되돌리기 어렵다.** 📌 **이 개념의 양방향성이 확정된다: 묶어서 틀리는 것과 나눠서 틀리는 것이 모두 실재한다.**

> [!insight] 한 줄
> **중복 검사가 실패하는 방향은 두 개다.** 하나는 *"볼트가 안 갖고 있다"* 고 오판해 **없는 신규를 만드는 것**([[백필-우회]]), 다른 하나는 *"볼트가 가진 건 다른 것이다"* 고 오판해 **같은 대상을 둘로 쪼개는 것**이다. 후자가 이 페이지다.

## 2026-09-30 — 신설 사례

**수집기 raw 원문**([[Ternary-Bonsai-2-27B]] 항목):
> *"**갱신**(볼트 기록은 비-gguf 본체 DL 3,457,124 이며 **본 항목과 다른 저장소**다)."*

🔴 **틀렸다. 같은 저장소다.** 볼트 대조 3건:

```
위치                                   실제 기록 내용
──────────────────────────────────────────────────────────────────────────────
sources/Ternary-Bonsai-2-27B.md 190행  prism-ml/Ternary-Bonsai-2-27B-gguf
                                       (볼트 09-29 09:08 UTC 실측)
                                       → -gguf 명시 · 그 블록 DL = 3,457,124
같은 파일 124행 (출처)                  https://huggingface.co/prism-ml/
                                       Ternary-Bonsai-2-27B-gguf
entities/prism-ml.md 19행              "prism-ml/Ternary-Bonsai-2-27B-gguf ·
                                       DL 3,457,124 (30일 · 볼트 실측 09-29)"
```

✅ **결정적 확인 2건**:
1. 볼트 09-29 기록의 `created 2026-09-16` · `modified 2026-09-25` 가 **오늘 실측한 gguf 저장소 값과 정확히 동일**하다.
2. 🔴 **수집기가 비교 대상으로 든 "비-gguf 본체" 저장소는 조회되지 않는다** — `https://huggingface.co/api/models/prism-ml/Ternary-Bonsai-2-27B` → **`Invalid username or password.`**(2026-09-30 09:13 UTC 실측). **실재가 확인되지 않는 저장소를 근거로 분리 판정이 나왔다.**

> [!warning] 🔴 오판의 원인 추정 — 볼트 파일명 관례
> 볼트 파일명이 `Ternary-Bonsai-2-27B.md`(**`-gguf` 없음**)인데 대상 저장소는 `…-2-27B-gguf` 다. **파일명만 보면 다른 대상처럼 보인다.**
> 🎯 **그런데 파일 내부(H1 · 출처 URL · 실측 블록)는 전부 `-gguf` 를 명시한다.** 즉 **파일명은 식별자가 아니고 본문이 식별자**인데, 판정이 파일명 층에서 멈췄을 가능성이 높다(⬜ 수집기 내부 동작 미확인 — **추정임을 명시**).
> 📌 **[[정규명-우선-중복검사]] 가 09-24에 신설된 이유와 같은 뿌리다.** 그때는 정규명 대조로 **거짓 신규**를 막았고, 오늘은 정규명 대조가 **거짓 분리**를 막았어야 했다. **같은 도구가 두 방향 오류를 동시에 담당한다.**

## 피해 규모 — 막혔지만 막힌 이유가 우연이 아니다

🔴 **볼트가 이 판정을 그대로 받았다면 `Ternary-Bonsai-2-27B-gguf.md` 라는 중복 페이지가 생겼을 것이다.** 그러면:
- 같은 저장소가 두 페이지로 갈려 DL 궤적이 **양쪽에서 각각 끊긴다**
- 하루 증분 **+123,903** 이 *"다른 저장소의 별도 수치"* 로 기록돼 **드리프트 검증이 무효화**된다
- [[Qwen3.8-27B]] ↔ 파생 계보가 **두 갈래로 중복 연결**된다

✅ **막힌 이유**: 수집기가 **근거 수치(3,457,124)를 함께 적었다.** 그 값을 볼트가 자기 파일에서 역검색(`grep`)해 `-gguf` 명시 줄을 즉시 찾았다 → [[자기제한-명시]] 의 실효 사례.
🎯 **만약 *"다른 저장소다"* 만 적혀 있었다면 역추적할 실마리가 없었다.** **판정에 근거를 붙이는 것이 판정의 오류를 잡는다.**

## 검출 규칙 (볼트 적용)

1. 수집기가 *"다른 저장소/다른 대상"* 이라고 판정하면 **인용된 근거 수치를 볼트 전체에서 `grep`** 한다. 히트하면 **같은 대상일 가능성을 먼저 검토**한다.
2. **볼트 파일명이 아니라 페이지 내 `출처:` URL 을 식별자로 쓴다.** 파일명 관례(접미사 생략 등)는 대상을 구분하지 않는다.
3. 분리 판정의 **비교 대상 저장소가 실재하는지 API 로 확인**한다. 오늘 사례에서 비교 대상은 **조회 불가**였다.
4. `created` · `lastModified` 쌍이 일치하면 **동일 저장소의 강한 증거**다(오늘 이 쌍이 결정적이었다).
