# 메타데이터 부재 추론 (Absence-in-Metadata Inference)

> [!insight] 정의
> **큐레이션된 메타데이터 필드가 비어 있는 것을, 그 필드가 가리키는 사실이 존재하지 않는 것으로 읽는 오류.**
> `topics` 에 ML이 없다 → ML이 아니다. basename grep이 0히트다 → 중복이 아니다. `license:` 태그가 없다 → 라이선스가 없다.
> **세 추론 모두 같은 형태이고, 셋 다 틀릴 수 있다.** 메타데이터는 **작성자가 채운 것**이지 **세계의 상태**가 아니기 때문이다.

## 2026-09-15 배치 — 같은 실패가 두 채널에서 동시에 나왔다

### 사례 1: basename grep 0히트인데 실재 중복 (수집기 발견)

수집기 보고: `openai/skills` · `openai/plugins` · `tech-leads-club/agent-skills` 는 **basename 히트가 없었는데도** 전체 식별자 grep으로 **정상 검출**됐다.
반대로 `huggingface/transformers` 는 **38히트**를 냈지만 **오탐**이었다 — 히트의 실체는 일반 명사 `transformers`(`library_name:` 태그 · `ktransformers` · `sentence-transformers/...` · 본문 서술어)였고, **리터럴 전체 식별자 grep은 0히트**였다.

> [!action] 볼트 규칙 (채택) — 수집기 09-15 요청 이행
> **중복 판정은 `org/name` 리터럴 grep을 1순위로 한다. basename은 보조 신호로만 쓴다.**
> **일반 명사 basename 예외 목록**(basename grep 결과를 중복 근거로 **쓸 수 없는** 이름):
> `transformers` · `skills` · `plugins` · `agents` · `agent-skills` · `tools` · `core` · `api` · `cli` · `docs` · `examples` · `templates` · `server` · `client`
> **판정 방향은 비대칭이다**: 리터럴 0히트 = **NEW 확정 가능**. basename 0히트 = **아무것도 확정 못 함.**
> 📌 09-14에 *"basename 8건 전부 완전 일치"* 로 basename 신뢰도가 높게 평가됐던 것은 `colibri`·`OpenMontage` 처럼 **고유명사였기 때문**이다. **basename 신뢰도는 그 단어가 고유명사인지에 전적으로 의존한다.**

### 사례 2: topics에 ML이 없는데 실재 AI 기능 (볼트 발견) 🔴

수집기는 [[gods-eye-view]] 를 **도메인 불일치로 제외**했다 — 당일 **+14,403**(이 배치 전체 최대 급상승) · ★34,045 · NEW.
제외 근거: *"레포 topics에 ML 관련 항목이 0개"*.

**볼트가 GitHub API로 실검증한 결과 — 제외 판단은 틀렸다.**
`bilawalsidhu/gods-eye-view` (★34,053 실측) README 9행:

> *"Photorealistic 3D globe. Live aircraft, ships, satellites, earthquakes, traffic, and public cameras. **Hands-free voice control powered by a realtime AI agent.**"*

**실시간 AI 에이전트가 제품의 3대 축 중 하나로 README 서두에 적혀 있다.** topics 12개(`3d-globe`·`cesium`·`flight-tracking`·`geospatial`·`geospatial-intelligence`·`gis`·`osint`·`photogrammetry`·`satellite-tracking`·`spatial-intelligence`·`webgl`·`worldview`)에 그 사실이 **반영되지 않았을 뿐이다.**
GitHub `description` 필드에도 AI 언급이 없다 — **즉 topics와 description 어느 쪽만 봐도 놓친다.**

> [!action] 볼트 규칙 (신설)
> **도메인 판정에 `topics`·`description` 만 쓰지 않는다. README 서두(최소 60행)를 함께 읽는다.**
> 근거: topics는 **작성자가 SEO·발견성 목적으로 고르는 태그**이지 기능 명세가 아니다. 저자가 자기 제품을 "AI 프로젝트"로 포지셔닝하지 않기로 선택하면 AI 기능이 있어도 ML topic을 달지 않는다.
> 🎯 **비용이 비대칭이다**: README 60행 읽기 = 후보당 1회 fetch. 놓치는 것 = **배치 최대 급상승 건 전체.**

### 사례 3 (대조군): 라이선스 미선언을 **올바르게** 처리한 경우 ✅

[[clip-vit-base-patch32]] 는 HF 태그에 `license:` 항목이 **없다**(볼트 API 실측 확인).
수집기는 이것을 *"라이선스 없음"* 이 아니라 **"미선언이므로 상용 사용 판단 시 별도 확인 필요"** 로 적었다.
📌 **같은 배치에서 같은 사람이, 한 필드에서는 부재를 올바르게 처리하고 다른 필드에서는 틀렸다.** 규칙이 내면화된 게 아니라 **필드마다 따로 학습된 상태**다 — 그래서 일반형을 명문화할 가치가 있다.

## 일반형

> [!insight] 한 줄
> **메타데이터 필드의 부재는 "모른다"이지 "아니다"가 아니다.**
> 부재에서 결론을 내리려면 **그 필드가 완전성을 보장하는지**를 먼저 물어야 한다. `topics`·basename·`license:` 태그는 **전부 보장하지 않는다.**

판정 절차:
1. **이 필드는 누가 채우는가?** — 작성자가 자발적으로 채우면 완전성 보장 없음
2. **부재의 두 해석을 모두 적는다** — "없다" / "안 적었다"
3. **부재를 근거로 배제할 때는 1차 소스(README·카드 본문)를 최소 1회 확인**한다
4. **확인이 막히면**([[Llama-3.1-8B-Instruct]] 의 401) **막혔다고 적는다** — 추정으로 채우지 않는다

> [!insight] 🎯 `topics` 포화도 — 0에서 만석까지 같은 배치 안에 있다

> - **20개 만석**: 자리가 없어서 빠진 것이다 — 09-16 [[omniget-재판정]] 에서 저자 진술로 확정됨(*"GitHub allows 20 topics. The repository uses **exactly these 20**"*)

> 이 개념은 지금까지 *"필드가 비었다고 없는 게 아니다"* 를 축적해 왔다. 09-17에 **반대 방향**이 나왔다.
> 수집기 채택 논거: *"원본에 없는 `int8_convrot` 양자화 축이 생겼다 — bf16/int8 두 점 비교 가능."*
> **볼트 실측**: 파일은 **실재한다**(`checkpoints/yue2_3b_int8_convrot.safetensors`). 🔴 **그런데 카드가 그 파일을 언급하지 않는다** — 배치 폴더 안내는 **bf16 2개만** 적고, `convrot` 의 의미·손실·배치 위치가 **한 글자도 없다**.
> 🎯 **따라서 "두 점 비교"가 성립하지 않는다 — 비교에는 두 파일이 아니라 두 측정값이 필요하다.**
> 📌 **일반형 추가**: **부재는 부정의 근거가 아니고, 존재는 사용 가능성의 근거가 아니다.** 둘 다 **1차 출처에서 용도를 확인**해야 한다.

> [!note] 🔴 `trendingScore` — 개별 엔드포인트에서는 아예 `None` 이다
> 볼트 실측(09-17): HF 모델 3건 모두 **개별 모델 API(`/api/models/{id}`)에서 `trendingScore: None`**. 목록 API(`?sort=trendingScore`)에서만 **126·139·147** 로 반환된다.
> 🎯 **즉 `trendingScore` 는 모델의 속성이 아니라 목록 질의의 속성이다** — 사후에 개별 조회로 **검증할 수 없다.** 수집기 자기 한계 4번(*웹 파싱 실패로 API 우회*)이 **구조적으로 맞다.**
> 📌 볼트 기존 규칙(*trendingScore는 목록 API에만*) **재확인** + 강화: **검증 불가 필드로 분류**한다.

## 2026-09-16 — 🔴 **확장: 밀도는 신뢰도와 무관하다 (필드가 가득 차도 못 믿는다)**

09-15의 결론은 **"필드 부재 ≠ 사실 부재"** 였다. 이번 배치가 그 반대편을 채운다.

**같은 배치, 같은 필드(`topics`), 세 가지 밀도 — 전부 기능을 말하지 않았다:**

| 레포 | `topics` 밀도 | 실제 | 결과 |
|---|---|---|---|
| [[pi-agent-harness]] | **0개** (빈 배열) | AI 에이전트 툴킷(★106,058) | description으로 겨우 잡힘 |
| [[gods-eye-view]] (09-15) | **12개**, AI 0 | 실시간 AI 에이전트가 3대 축 | 🔴 **놓칠 뻔함** |
| [[omniget-재판정]] | **20개 = GitHub 상한 만석** | README에 AI 카테고리 6개·MCP 서버 | 재판정 대상 |

> [!insight] 🎯 **저자가 이유를 직접 적은 결정적 증거**
> `tonhowtf/omniget` README 2~18행 HTML 주석:
> > *"Search keywords (kept here so GitHub search, Google and **AI assistants** can find the project)... **GitHub allows 20 topics. The repository uses exactly these 20**: downloader, download-manager, ..."*
>
> **저자는 20개 상한을 인지하고 발견성이 높은 다운로더 키워드로 전부 채웠다.**
> 🔴 **AI 기능이 없어서 topics에 AI가 없는 게 아니라, 자리가 없어서 없다.**
> 볼트가 09-15에 **추론으로** 쓴 문장 — *"topics는 작성자가 SEO·발견성 목적으로 고르는 태그이지 기능 명세가 아니다"* — 이 **작성자 본인 진술로 확인됐다.**

> [!action] 볼트 규칙 (확장)
> **`topics` 는 작성자의 발견성 전략이다. 유무·밀도 어느 쪽도 기능 신호로 쓰지 않는다.**
> - topics 0개 → 아무 정보 없음
> - topics에 AI 없음 → 아무 정보 없음
> - **topics 20개 만석 → 아무 정보 없음** (오히려 상한 경쟁이 일어나 정보가 더 왜곡된다)
> 📌 **판정은 README 본문으로만 한다.** 09-15 규칙(서두 최소 60행)을 유지한다.

## 🔄 2026-09-23 — **`null` 은 부재가 아니라 미요청이었다** (교과서 사례)

> [!warning] 🔴 수집기 주장: *"`downloadsAllTime` 은 이 응답에서 전부 `null`"*(3/3) — **틀렸다**
> ✅ 볼트 실측: `GET /api/models/{id}` 기본 응답에는 **빠지고**, **`?expand[]=downloadsAllTime` 을 붙이면 값이 온다.**
> - Qwen/Qwen3.8-27B → **9,681,199**
> - unsloth/Qwen3.8-27B-GGUF → **13,993,047**
> - prism-ml/Ternary-Bonsai-2-27B-gguf → **2,569,604**

> [!insight] 🎯 이 개념의 새 범주 — **API 기본 사영(projection)이 만드는 그림자 부재**
> 기존 사례들은 *"제작자가 안 적었다"*(카드 필드 미기재·topics 포화도 0)였다. 이번 건은 다르다 — **데이터는 서버에 있는데 응답 형태가 가렸다.**
> 📌 즉 부재의 원인이 **제작자 쪽이 아니라 조회자 쪽**이다. 수집기는 *"필드가 null이다"* 를 관측했고 그건 사실이지만, 거기서 *"값이 존재하지 않는다"* 로 간 추론이 틀렸다.
> 🎯 **"응답에 없다" ≠ "존재하지 않는다" ≠ "측정되지 않았다"** — 세 단계를 구분해야 한다.

> [!action] 규칙 추가
> API에서 필드가 `null`/누락일 때 **부재로 판정하기 전에 `expand`·`full`·`fields` 류 파라미터를 먼저 시도한다.** 그리고 부재를 적을 땐 **요청 URL 전체**를 확인 범위로 남긴다(볼트 요청 4의 API판).
> 📌 부재 주장 오류 **4배치 연속**(09-19 수치 · 09-20 PageIndex 비용 · 09-21 autoclip ASR·Paint HTML · **09-23 downloadsAllTime**). 이번엔 수집기의 독해가 아니라 **조회 방식**에서 났다는 점이 새롭다.
