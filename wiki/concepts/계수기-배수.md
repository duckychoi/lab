# 계수기 배수

> [!insight] 정의
> **HF 다운로드 수는 "사람 수"도 "레포 받기 횟수"도 아니다. 레포의 `library_name` 이 정하는 *쿼리 파일* 에 대한 HTTP 요청(GET·HEAD) 수다.** 쿼리 파일이 사용 1회당 여러 번 맞는 레포는 같은 사용량에서 **정수배로 크게** 나온다.
> ⇒ **`library_name` 이 다른 두 레포의 다운로드 비는 동일 단위 비교가 아니다.**
> 짝 개념: [[구조적-영값]](쿼리 파일이 **없어서** 0 — 과소) ↔ **계수기 배수**(쿼리 파일이 **여러 개 맞아서** n배 — 과대).

## 규칙 출처 (2026-10-24 원문 확인)
- `huggingface/hub-docs` `docs/hub/models-download-stats.md`: *"Every HTTP request to these files, including GET and HEAD, will be counted as a download."* 기본 쿼리 파일은 `config.json` 등.
- `huggingface.js/packages/tasks/src/model-libraries.ts`: **`diffusion-single-file` → `countDownloads: path_extension:"safetensors"`** ⇒ **`.safetensors` 파일마다 1회**.
- 같은 문서: **diffusers** 는 `model_index.json`·`modular_model_index.json` + **최상위** `*.safetensors/.ckpt/.bin` 만 센다 — *"Filter out nested safetensors … to avoid double counting"* ⇒ **이중계수를 막도록 설계된 쪽**.
- 같은 문서: **GGUF** 는 모든 GGUF 파일을 센다 — 문서 스스로 *"This will double count downloads in the case a user performs cloning of a whole repository"* 라고 인정.

## 판정 절차 (볼트 규약 후보)
1. 두 레포 다운로드를 비교하기 전에 `?expand[]=library_name`(또는 기본 응답의 `library_name`)을 본다.
2. 다르면 `model-libraries.ts` 에서 각 `countDownloads` 를 확인한다.
3. 파일 단위 계수 쪽은 `tree/main` 으로 쿼리 파일 수와 **카드가 권하는 다운로드 구성**을 확인해 1인당 계수를 추정한다.
4. 결과는 **"요청 수 비 X배 · 사람 단위 추정 범위 Y~Z배"** 로 둘 다 적는다. 추정 범위만 적고 원 배수를 지우지 않는다.

> [!warning] 한계
> 1인당 실제 파일 수는 관측 불가다(정밀도 선택·재다운로드·CI). 사람 단위 수치는 HF Publisher Analytics 원시 로그(조직 전용)로만 나온다. ⇒ 이 개념이 확정하는 것은 **"비교 불가"까지**이고, **"실제로 몇 배"는 확정하지 못한다.**
