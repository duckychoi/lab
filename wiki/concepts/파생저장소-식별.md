# 파생저장소 식별

> [!insight] 한 줄
> **`org/name` 리터럴 중복 필터는 재포장·양자화 파생을 구조적으로 놓치며, 그 누락분은 HF 트렌딩 채널의 14%다.**

## 어디서 나왔나 — 수집기 질문 (2026-09-17)

수집기가 볼트에 **딱 하나**를 물었다:
> *"재포장·양자화 파생 저장소를 중복으로 볼 것인가, 새 축으로 볼 것인가."*
> 선택지: **(a)** `base_model` 태그가 볼트 기보유를 가리키면 중복 처리 · **(b)** 양자화/라이선스/런타임이 갈리면 파생 축으로 채택 · **(c)** 원본 페이지에 섹션으로 병합
> 수집기는 [[Comfy-Org-YuE2]] 를 **(b)로 배달**하고 관계를 명시했으며, `base_model` 을 **중복 필터 2차 키로 추가**할 수 있다고 제안했다.

## 🔴 볼트 답 1 — **문제의 크기를 먼저 재라. 이건 예외가 아니라 14%다**

**볼트 실측(2026-09-17, HF 목록 API `sort=trendingScore`, 상위 200건 전수):**

```
"Qwen3.8-27B" 문자열 포함 저장소 : 28건 / 200건 = 14.0%
  └ 원본 1건 (Qwen/Qwen3.8-27B · 3위 ts605)
  └ 파생 27건 (GGUF · FP8 · NVFP4 · MLX · abliterated · Heretic · imatrix · Uncensored …)
```

🎯 **트렌딩 상위 200의 7분의 1이 단일 베이스 모델의 가족이다.** 파생 유형만 봐도 양자화 포맷(GGUF/FP8/NVFP4/MLX/imatrix), 탈검열(abliterated/Heretic/OBLITERATED/Uncensored), 재배포자(bartowski/unsloth/huihui-ai/ISTA-DASLab/nvidia)로 갈린다.

🔴 **`org/name` 리터럴 필터의 귀결**: 이 28건은 **이름이 전부 다르므로 28번 모두 NEW로 통과한다.** 볼트는 같은 가중치를 **최대 28개 페이지로 축적**할 수 있다.
📌 **이미 진행 중이다** — 볼트 기보유 중 이 목록에 해당하는 것: [[Qwen3.8-27B-GSQ-RCO-GGUF]](6위) · [[DavidAU-Qwen3.8-27B-TURBO]](9위) · [[unsloth]] GGUF(12위) · [[Huihui-Qwen3.8-27B-abliterated-GGUF]](45위) · [[Qwen3.8-27B-Uncensored-GGUF]] · [[Qwen3.8-27B-Uncensored-Aggressive-MTP-GGUF]] · [[Qwen3.8-27B-FP8]](136위) — **그리고 09-17 배치가 [[Qwen3.8-27B-TWIN-TURBO-709-GGUF]](33위)를 더했다.**

## 🔴 볼트 답 2 — **2차 키를 쓰되 `tags` 가 아니라 `cardData.base_model` 을 쓸 것**

수집기 제안(*"`base_model` 태그를 2차 키로"*)은 **방향이 맞고 필드가 틀렸다.** 볼트 API 실측이 두 필드의 불일치를 잡았다:

**[[Comfy-Org-YuE2]] 실측:**
```
cardData.base_model = ['m-a-p/YuE2-3B', 'm-a-p/SheetSage2']     ← 둘 다 있다
tags                = ['base_model:m-a-p/SheetSage2',
                       'base_model:finetune:m-a-p/SheetSage2']   ← 🔴 YuE2-3B 없음
```
🎯 **볼트 기보유 [[YuE2-3B]] 는 `cardData` 에만 있고 `tags` 에는 없다.** `tags` 를 2차 키로 쓰면 **이 건은 여전히 NEW로 통과한다** — 즉 제안대로 구현하면 **이 사례조차 못 잡는다.**
🔴 **게다가 관계 라벨이 틀렸다**: `base_model:finetune:` 인데 카드 본문은 *"Repackaged"* 다. **파인튜닝이 아니라 재포장**이다.

📌 → [[파생표기-함정]] **5번째 사례**로 등재. 계보: description(09-08) → 이름(09-09) → API 계산 필드·표 서식(09-10) → 자동 파싱 arxiv 태그(09-16) → **불완전·오라벨 base_model 태그(09-17)**.

> ### 볼트 규칙 (신설)
> **파생 관계를 읽을 때 `tags` 배열이 아니라 `cardData.base_model` 을 1순위로 읽는다.**
> `tags` 의 `base_model:*` 항목은 **불완전할 수 있고 관계 라벨이 틀릴 수 있다.**

## 🔴 볼트 답 3 — **`base_model` 은 직전 1홉만 담는다. 원류는 본문에만 있다**

**[[Qwen3.8-27B-TWIN-TURBO-709-GGUF]] 실측:**
```
cardData.base_model = ['DavidAU/Qwen3.8-27B-TWIN-TURBO-Fable-Cold-Fusion-709-L-Uncensored']
                       └ 같은 저자의 비-GGUF 자기 레포 = 1홉
```
**카드 본문이 밝히는 실제 사슬**(460~463행):
```
Qwen/Qwen3.8-27B                      ← 🔴 진짜 원류. 태그에 없다
  → trohrbaugh/Qwen3.8-27B-heretic-ara ← 🔴 타인의 탈검열 작업. 태그에 없다
                                          (Heretic v1.2.0 + ARA 방법)
  → DavidAU 튜닝·머지                   ← 태그가 가리키는 유일한 홉
  → 이 GGUF 재배포
```
🎯 **4단 사슬에서 태그는 1단만 기록한다.** 원류(`Qwen/Qwen3.8-27B`)가 태그에 없으므로, **base_model 키로도 이 건을 Qwen3.8-27B 가족으로 묶을 수 없다.**
📌 **즉 `cardData.base_model` 은 필요조건이고 충분조건이 아니다.** 사슬 추적은 **카드 본문 독해로만** 가능하다 — 자동화되지 않는다.

> ### 볼트 규칙 (신설)
> **`base_model` 히트가 없어도 파생이 아니라는 뜻이 아니다.** 이름에 기보유 베이스 문자열이 포함되면(예: `Qwen3.8-27B`) **본문에서 사슬을 확인한다.**
> 🎯 **값싼 3차 키**: 기보유 베이스 모델명을 **부분 문자열로** 검사. 이번 28건은 **전부 이 한 줄로 잡힌다.**

## ⚖️ 판정 절차 (볼트 적용용)

새 저장소가 기보유 모델의 파생으로 의심될 때 순서대로 묻는다:

1. **`cardData.base_model` 이 기보유를 가리키는가?** (`tags` 아님) → 가리키면 파생 확정
2. **이름에 기보유 베이스 문자열이 포함되는가?** → 포함되면 **본문에서 사슬 확인**
3. **파생이 확정됐다면 — 새 축이 *문서화*되어 있는가?**
   - ✅ **문서화된 새 축이 있다** → **(b) 파생 축으로 독립 채택**
   - 🔴 **파일만 있고 문서가 없다** → **(c) 원본 페이지에 섹션 병합**
   - 🔴 **새 축이 없다(순수 재포장)** → **(a) 중복 처리**

> [!insight] 🎯 **3번이 이번 판정의 핵심이다 — "파일 존재"는 축이 아니다**
> 수집기는 [[Comfy-Org-YuE2]] 를 *"원본에 없는 `int8_convrot` 양자화 축이 생겼다"* 며 (b)로 채택했다.
> **볼트 확인: 파일은 실재한다. 그런데 카드가 그 파일을 언급하지 않는다** — 배치 폴더 안내에 **bf16 2개만** 적혀 있고 `int8_convrot` 은 **어디에 두는지, `convrot` 이 무엇인지, 손실이 얼마인지 한 글자도 없다.**
> 🎯 **따라서 "bf16/int8 두 점 비교"가 성립하지 않는다.** 비교에는 **두 파일이 아니라 두 측정값**이 필요하다.
> 🔴 **볼트 판정: [[Comfy-Org-YuE2]] 는 (b) → (c)로 정정.** 단 **페이지는 남긴다** — 모델로서가 아니라 **파생 추적 증거**(tags 불완전·라벨 오류·라이선스 분기)로서 값이 있다.

> [!note] 라이선스 분기는 독립적으로 중요하다
> [[Comfy-Org-YuE2]] 는 **CC-BY-NC-4.0**(비상업)이다. 🎯 **재포장은 라이선스를 바꿀 수 있다** — 가중치가 같아도 **배포 조건이 다른 저장소**가 생긴다.
> 📌 따라서 (a)로 중복 처리하더라도 **라이선스가 원본과 다르면 그 사실만은 원본 페이지에 기록**해야 한다. 파일 동일성이 사용 조건 동일성을 뜻하지 않는다.

## 🎯 왜 이것이 중복 문제 이상인가 — 트렌딩 지표의 해석이 달라진다

**볼트 실측(상위 31위 = 09-17 배달분 32위 직전까지)**: 볼트 **기보유 23건 / 미보유 8건 = 보유율 74.2%**

🎯 **볼트가 HF 트렌딩 상단을 포화시키고 있다.** 상위 5위(Edge0-35B ts2409 · DeepSeek-V4.1-Flash 1916 · Qwen3.8-27B 608 · YuE2-3B 601 · MiniCPM5-2B 483)는 **전부 볼트 기보유**다.
📌 **귀결**: 중복 필터가 정상 작동할수록 배달분의 `trendingScore` **절대값은 낮아진다.** 09-17 배달 3건은 ts **126·139·147 = 32·33·37위**로, 1위의 **5~6%** 다.
🔴 **따라서 `trendingScore` 절대값을 배치 간 비교에 쓰면 안 된다** — 그것은 **모델의 인기가 아니라 볼트의 커버리지 함수**다. [[상대속도-가림]] 과 같은 형태의 오류(분모 없는 절대값 사용)가 **HF 채널에서 반복**된다.

🔴 **그리고 미보유 8건의 성격이 이 개념을 다시 확인한다**: `ukisai/Swift-Qwen3.8-27b` 와 `ukisai/Swift-Qwen3.8-27B-GGUF` 가 **둘 다 미보유**다 — **같은 모델의 base/GGUF 쌍이 각각 NEW로 대기 중**이다. `dealignai/DeepSeek-V4.1-Flash-UNCENSORED-FP8` 도 기보유 원본의 파생이다.

> [!warning] 🔴 볼트 자기 한계
> 1. **28건의 `cardData.base_model` 을 전수 확인하지 않았다.** 문자열 포함으로 셌으므로 **이름에 베이스를 안 쓴 파생은 빠졌다** — 실제 비율은 **14%보다 높다.**
> 2. **가중치 해시를 비교하지 않았다.** *"같은 모델"* 판정이 **카드 진술과 태그에 의존**한다. 파일 md5/sha 대조는 하지 않았다.
> 3. **(c) 병합을 이번 배치에서 실행하지 않았다.** [[Comfy-Org-YuE2]] 를 (c)로 판정했으나 **[[YuE2-3B]] 에 섹션을 실제로 추가하는 작업은 다음 배치 숙제**로 남긴다 — 판정과 실행을 같은 배치에 다 하지 못했다.
