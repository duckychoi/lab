# 관련성 판단의 주체

> [!insight] 정의
> **"무엇이 관련 있는가"를 누가 정하는지가 독립 축이다. 검색기(유사도)가 정하던 것을 모델 자신이 정하게 바꾸는 움직임이, 서로 다른 층에서 독립적으로 나타났다.**

📌 **볼트가 2026-09-03 [[에이전트-메모리-레이어]] 에서 이 축을 먼저 열었다.** 당시 원문:
> *"**관련성 판단의 주체**가 바뀐 것이 핵심이다: RAG는 검색기가, 프록시 점수 방식은 외부 스코어러가, 이건 **모델 자신이** 판단한다."*

당시엔 사례가 [[Declarative-Attention]] **하나**였다. 2026-09-20 [[PageIndex]] 가 **두 번째**로 도착했고, **층이 다르다.**

## 두 사례 — 같은 이동, 다른 층

| | [[Declarative-Attention]] (09-03) | [[PageIndex]] (09-20) |
|---|---|---|
| 층 | **KV 캐시 읽기** | **문서 검색** |
| 기존 주체 | 어텐션 가중치 / 외부 스코어러 | 임베딩 유사도 |
| 새 주체 | 모델이 `<global>`/`<focus>`/`<local>` 로 **참조 범위 선언** | LLM이 **계층 트리를 에이전틱하게 탐색** |
| 제거한 것 | KV 읽기 | **청킹·임베딩·벡터DB 전부** |
| 근거 문장 | *"모델이 이미 어느 부분이 관련 있는지 알고 있지 않겠는가?"* | *"**similarity ≠ relevance** — relevance requires **reasoning**"* |
| 비용 이동 | 학습 불필요·엔진 수정 필요 | 임베딩 인프라 → **추론 토큰**($0.001/page 색인) |
| 적용 난이도 | ✅ 프롬프트 층에서 흉내 가능(비용 0) | ✅ SDK 로컬 모드로 즉시 |

🎯 **두 사례가 같은 문장을 다른 말로 쓴다.** 한쪽은 *"모델이 안다"*, 다른 쪽은 *"관련성에는 추론이 필요하다"* — **같은 주장이다.**

## 🎯 [[하네스-설계-축]] 과의 관계 — 방향이 반대다

[[하네스-설계-축]] 의 09-18 결론은 **"빼라"** 였다(복구 장치=이득 0 · 도구 추가=무용 · 계획=정확도 불변).
🎯 **이 축도 "빼라"다 — 다만 빼는 것이 기능이 아니라 중개자다.** 벡터DB를 빼고, KV 읽기를 빼고, **판단을 모델에게 돌려준다.**
📌 **즉 "절제 경쟁"에는 두 종류가 있다: 기능을 빼는 절제와, 중개 계층을 빼는 절제.** 후자는 **모델 능력이 오를수록 이득이 커지는** 쪽이다.

> [!warning] 🔴 한계 — **표본 2. 축으로 확정하지 않는다**
> 볼트 규칙은 *"3개 이상 소스에서 등장한 개념은 반드시 독립 페이지"* 이고, **이건 2개다.** 그럼에도 페이지를 만드는 이유: **볼트가 09-03에 먼저 축을 선언해 뒀고, 예측이 맞은 건 기록할 가치가 있다.**
> 🔴 **반증 후보가 있다**: [[mem0]] 는 반대 방향이다 — 엔티티를 **추출·임베딩·링크**해서 **검색기 쪽을 강화**한다(★65,688). **이 축이 이기고 있다는 근거는 없다.**
> 🔴 **비용 비교가 없다.** PageIndex 색인은 LLM 호출이고 임베딩보다 비싸다. *"유사도보다 추론이 낫다"* 가 **같은 예산에서도 참인지** 어느 쪽도 재지 않았다.
> 📌 세 번째 사례가 오면 **domain/synthesis 로 승격 검토.**
