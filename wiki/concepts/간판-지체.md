# 간판 지체

> [!insight] 정의
> **저장소의 제목·한줄설명(간판)이 갱신되지 않아, 본문이 주장하는 현재 능력과 어긋나는 현상.** 과장 경계와 달리 **방향이 반대일 수 있다** — 간판이 본문보다 **낮게** 멈춰 있으면 레포가 자기 능력을 **과소표기**한다.
>
> 🎯 핵심은 **수집·요약 공정이 간판을 먼저 읽는다**는 것이다. API `description`, README 제목, 레포 이름은 **가장 싸게 얻어지는 필드**이므로 한줄요약의 기본 재료가 된다. 간판이 낡으면 **그 낡음이 그대로 하류로 전파된다.**

## 신설 계기 — [[airllm]] (2026-10-12)

볼트가 README 전문(18,934 B / 461행)을 열어 간판과 본문을 대조했다.

| 층 | 표기 | 출처 시점 |
|---|---|---|
| **GitHub API `description`** | *"AirLLM **70B** inference with single **4GB** GPU"* | **2024/04/20** 항목과 동일 |
| **README 제목(동일 문구)** | 같음 | 같음 |
| 🎯 **README 헤드라인(11행)** | *"You can even run **Kimi K3 (2.8T)** … on **under 4GB**, **Qwen3.8-Flash-Next** on **6GB**, and **DeepSeek-V3 (671B)** on **~12GB**"* | **2026/07~08** |

⇒ 🔴 **간판은 70B, 본문은 2.8T — 파라미터 40배 차이다.**
📌 **수집기 한줄요약은 간판을 따랐다**: *"레이어 단위 로딩으로 4GB 단일 GPU에서 70B 모델 추론"*. ⚖️ **수집기 과실이라기 어렵다** — 레포가 스스로 그렇게 적고 있다.

> [!insight] 🎯 왜 과장보다 탐지가 어려운가
> 과장은 **본문을 읽으면 근거가 없다는 것이 드러난다**(수치 부재·조건 누락). 📌 **과소표기는 본문이 더 강한 주장을 하고 있으므로, 간판만 읽은 사람은 "검증 통과"로 느낀다** — 70B/4GB 는 2026년 기준으로 **의심스럽지 않은 주장**이기 때문이다.
> ⇒ 🔴 **의심 신호가 발생하지 않는다.** 이것이 이 유형의 탐지 난점이다.

## 인접 개념과의 경계

| 개념 | 무엇이 낡았나 | 처방 |
|---|---|---|
| [[캐시된-지표-신선도]] | **지표**(스타·DL 수)가 캐시돼 낡음 | 재조회 |
| **간판 지체**(이 개념) | **자기설명**(제목·description)이 낡음 | 본문 뉴스/변경이력 대조 |
| [[게시일-이중화]] | **날짜**가 두 개(목록일 vs 발행일) | 둘을 분리 기록 |
| [[파생표기-함정]] | **파생 필드**를 원문 대신 읽음 | 원문 열람 |

🎯 **간판 지체는 [[파생표기-함정]] 의 특수형으로 볼 수 있다** — `description` 은 레포 소유자가 손으로 쓴 **파생 요약**이고, README 본문이 원문이다. 📌 다만 **파생표기 함정은 "기계가 만든 필드"**(`spdx_id: NOASSERTION`)를 주로 다루므로, **사람이 쓰고 방치한 필드**는 별 유형으로 둔다.

## 볼트 규약

1. 🔴 **한줄요약을 쓸 때 `description`·README 제목만 쓰지 않는다.** README 의 **뉴스/업데이트/변경이력 섹션 최상단 1~3개 항목**을 함께 읽는다 — 그곳이 현재 능력의 실제 위치다.
2. 📌 **간판과 본문이 어긋나면 둘 다 적는다**: *"간판 70B/4GB · 본문 최신 2.8T/3.72GB(2026/07)"*.
3. ⚖️ **과소표기를 레포의 결함으로 적지 않는다.** 📌 다만 **"이 레포의 능력을 간판으로 판단하면 틀린다"** 는 경고는 남긴다.
4. 🆕 **간판 지체가 확인된 레포는 재수집 시 간판 변경 여부를 먼저 본다** — 변경되면 레포가 스스로 정리한 것이고, 그 자체가 신호다.

> [!warning] 🔴 한계
> - **표본 1건**([[airllm]]). 일반 패턴인지 단발인지 알 수 없다.
> - ⬜ **볼트 기존 소스 중 간판 지체가 몇 건인지 전수 확인하지 않았다.** 특히 **생성이 오래된 레포**(artcraft 2022 · pytorch 2016)가 후보다 — 다만 그 둘은 금일 확인 시 간판과 본문의 괴리가 관측되지 않았다.
> - ⬜ **반대 방향(간판이 본문보다 과장)** 사례를 이 개념에 포함할지 미정. 현재 정의는 양방향을 허용하지만 **관측된 것은 과소 1건뿐**이다.

# 🏆🏆🏆 2026-10-17 — **과대 방향 1호 확보. 이 개념이 예측한 양방향성이 n=2 로 입증됐다.**

> [!insight] 신설 당시(10-12) 이 페이지는 **방향이 반대일 수 있다**고 썼지만 사례는 과소 1건([[airllm]])뿐이었다. 금일 [[xerj]] 로 **과대 방향이 채워졌다.**

| | **[[airllm]]** (10-12 · 과소) | 🆕 **[[xerj]]** (10-17 · 과대) |
|---|---|---|
| 간판(`description`) | *"**70B** inference with single 4GB GPU"* | *"using **40x** fewer tokens than grep"* |
| 본문(README) | *"**Kimi K3 (2.8T)** … under 4GB"* | *"**2.7x** fewer output tokens than grep"* |
| 괴리 | 🔴 **40배 과소** | 🔴 **14.8배 과대** |
| 하류 전파 | 수집기 요약이 **70B** 를 따랐다 | 수집기 요약이 **40x** 를 따랐다 |

⇒ 🏆 **두 사례가 같은 메커니즘이고 부호만 다르다**: `description` 은 **가장 싸게 얻어지는 필드**이므로 요약 공정의 기본 재료가 되고, **간판의 오차는 부호와 무관하게 하류로 전파된다.**
⇒ ✅ **따라서 `reliability: medium → high`** — 양방향 각 1건이고 메커니즘이 동일하게 관측됐다.

## 🎯 금일 사례가 추가하는 새 축 — **간판 오차는 "오래됨"만으로 설명되지 않는다**

[[airllm]] 의 간판은 **낡아서** 틀렸다(2024/04 표기가 2026/07 본문과 어긋남 = 지체).
🔴 **[[xerj]] 의 간판은 낡지 않았다.** `pushed` 가 **2026-10-17T09:10Z**(관측 8분 전)이고 레포는 활발히 갱신 중이다. 그런데도 간판이 본문과 14.8배 어긋난다.
⇒ ⚖️ **즉 "지체"는 원인 중 하나일 뿐이고, 본질은 *간판과 본문이 서로 다른 목적을 가진다*는 것이다** — 간판은 유통용, 본문은 설명용이다.
⇒ 🆕 **개념 범위 확장: 「간판 지체」를 「간판-본문 괴리」의 **시간 원인 하위형**으로 재정의한다.** 금일부터 두 하위형을 구분해 적는다:
> - **① 지체형** — 간판이 과거 상태에 멈춤 ([[airllm]])
> - **② 유통형** — 간판이 최신이지만 **유통에 유리한 수치를 고름** ([[xerj]] · [[caveman]] 65%↔33.2% · [[context-mode]] 98%↔96%/13%)

🏆 **②형은 이제 n=3 이다**([[caveman]] 10-04 · [[context-mode]] 10-14 · [[xerj]] 10-17) ⇒ 🔴 **3회 반복 = 법칙으로 승격.** 📌 **규약: 레포의 수치 주장을 적을 때는 `description` 과 README 를 **둘 다** 읽고, 다르면 **본문을 채택하고 간판을 괴리로 기록**한다.**

## 🔴 금일 사례의 추가 교훈 — 수집기는 맞는 수치를 틀린 이유로 뺐다

수집기는 40x 를 *"측정 조건이 카드에 없다 ⇒ 마케팅 문구"* 로 배제했다. **배제는 옳고 사유는 틀렸다.**
🔴 측정 조건은 **공시돼 있다**(`benchmarks/grep-vs-retrieval-lucene/` 실행 하네스 전량 + `docs/TOKEN_USAGE.md` 재현 가능 표 + 케이스스터디 8태스크·4언어·16run).
⇒ 🎯 **"모름"과 "모순"은 다른 판정이다.** "모름"으로 분류되면 레포는 *검증 불가 마케팅*으로 남고, "모순"으로 분류되면 **본문이 간판을 반박한다는 더 큰 발견**이 나온다.
⇒ 🆕 **규약: 간판 수치를 배제할 때 사유를 둘 중 하나로 특정한다 — ①본문에도 근거 없음(모름) ②본문이 다른 값을 제시(모순).** 전자는 레포 결함이고 **후자는 간판 결함이다.**
