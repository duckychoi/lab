# 하네스 설계 축

> [!insight] 🏆 2026-10-03 **축에 측정 통화가 붙었다 + 이식성이 두 층으로 분해됐다**
> **① [[Sharpening-Tax]] 가 이 축에 측정 가능한 통화를 준다 — "커버리지".**
> *"경량 추론 하네스를 붙인 사전학습(base) 모델이 유능한 에이전트로 동작하고, pass@1 은 훨씬 낮아도 테스트시 예산이 충분하면 후처리 모델의 해법 커버리지(pass@K)를 자주 상회한다."*
> ⇒ ⚖️ ***"무엇을 모델에 넣고 무엇을 하네스에 둘 것인가"* 가 처음으로 수치 축(pass@K)으로 번역됐다.** 📌 종전까지 이 축은 **분류 도구**였고 **비교 도구가 아니었다.**
> 🔴 **그러나 볼트 PDF 실측이 전제를 드러냈다**: 초록의 *"sufficient test-time budget"* 은 본문에서 **`pass@128`**(37회 언급 · 주 설정)이다. ⚖️ **base + 하네스 경로가 이기는 조건은 128배 샘플링이다. 초록만 읽으면 "base 모델이 더 낫다"로 오독한다.** ⇒ 📌 **축의 두 끝에 가격표가 다르게 붙는다: 모델 쪽은 학습 비용, 하네스 쪽은 추론 비용(×128).**
>
> **② 본문이 과제 쪽 분해를 준다 — 축이 제공자 쪽만이 아니다.**
> [[Sharpening-Tax]] 본문은 에이전트 과제가 수학/코딩과 다른 이유를 **4가지**로 쪼갠다: ① 구조화된 액션 실행 ② 시나리오별 인터페이스로 다양한 도구 호출 ③ 불확실성 하 이질적 환경 피드백 반영 ④ 장기 궤적 일관성 유지.
> ⇒ 📌 **볼트는 지금까지 이 축을 *제공자 쪽*(모델/하네스)으로만 쪼갰다. 과제 쪽 분해가 없었다** → [[암묵을-명시로]].
>
> **③ 이식성이 "문서 열거"와 "매니페스트 유지"로 분해된다.**
> | 레포 | 형태 | 증거 |
> |---|---|---|
> | [[superpowers]] | **문서가 15종 이상 설치 경로를 열거** | README |
> | **[[ponytail]]** | **9개 매니페스트를 실제 유지보수** | 🏆 **릴리스 1건에서 전부 +1-1 커밋** |

> ⇒ ⚖️ **둘은 같은 지표가 아니다. README 열거 수 ≠ 유지되는 매니페스트 수.** 📌 superpowers 쪽은 ②의 증거를 볼트가 **확인하지 않았다** — 공정하게 비교하려면 superpowers 커밋 로그도 열어야 한다(미수행 → actionable).
>
> **④ 층들이 또 서로를 지목했다(2배치 연속).** [[ponytail]] 이 `.openclaw/skills/` 를 `skills/` 와 **이중 유지**하고 커밋마다 양쪽을 동시 수정한다 ⇒ 📌 **[[openclaw]](★391,087)가 별도 스킬 디렉터리 규약을 요구하는 플랫폼임을 벤더 커밋이 증명한다.** 10-02 에 [[pi-agent-harness]] README 가 [[OpenShell]] 을 호명한 것에 이어 **분석자가 묶던 두 층을 벤더가 스스로 묶은 2번째 사례**다.

## 🎯 이 배치의 가장 강한 신호 — 독립된 두 방법이 같은 지점을 가리킨다

**[[SoL-Pi]]**: 자동연구 루프로 환경을 늘려 **선택압을 통과한 메커니즘 4개**만 남겼다 → 4개 중 **2개가 컨텍스트 관련**(압축·관측 처리).
**[[Harness-Design-Empirical]]**: 176개 대조 설정으로 3요소를 절제 측정 → **컨텍스트 관리가 가장 중요**하고 이득의 대부분은 **오버플로 실패 방지**에서 온다.

🎯 **탐색으로 *남은 것*과 절제로 재서 *중요한 것*이 일치한다.** 방법이 완전히 다른 두 연구가 같은 부품을 지목했다.
📌 **볼트 판정: 이 일치는 단일 논문의 결론보다 강한 근거다.** 🔴 **단 두 논문 다 같은 주(09-17 공개)에 나왔고 서로를 인용하지 않았을 가능성이 높다** — 독립성은 추정이고 확인하지 않았다.

## 🔴 이 축의 결론이 반직관적인 방향으로 모인다

[[Harness-Design-Empirical]] 의 4개 결론을 다시 읽으면 **셋이 "빼라"** 다:
- **생략분 복구 장치** → 모델이 거의 쓰지 않아 **정확도 이득 없음**(빼라)
- **사전정의 도구** → bash 능숙 모델에는 **bash 단독이 더 싸다**(빼라)
- **계획** → 강한 모델에서는 정확도 **불변**, 비용만 절감(효과가 다르다)
- **컨텍스트 관리** → 유일하게 "넣어라", 단 **예산이 빠듯할 때만**

🎯 **[[SoL-Pi]] 도 같은 형태다** — 다수 환경에서 **살아남은 것만 4개**다. 무엇을 추가할지 설계한 게 아니라 **무엇이 죽는지 관찰**했다.
🎯 **[[opensre]] 도 같은 방향이다** — *"AI SRE remains unsolved"* 로 **주장 자체를 뺐다.**
📌 **축의 성숙 신호: 기능 추가 경쟁이 아니라 절제 경쟁으로 넘어갔다.**
