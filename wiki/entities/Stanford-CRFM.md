# Stanford CRFM

> [!insight] 핵심 — **"open source ≠ open weights"** 를 구분하고 개발 과정 자체를 공개하는 쪽
> [[marin]] 핵심 기여 기관(Open Athena 와 공동). 실험마다 GitHub 이슈 번호를 붙이고(이슈 = 실험 장부), 회고 문서에 **실패·오염·패배를 수치로** 적는다.
> 🎯 대표 사례: 32B 학습의 **역방향 GSM8K 오염**(점수를 올린 게 아니라 약 22점 깎았다) → [[포맷-불일치-오염]] · Delphi 스케일링을 **사전등록**해 333배 외삽, 손실 0.2% 이내(🔴 CI ±4%, 1차 시도 발산).
> 후원: Google TRC · Jen-Hsun and Lori Huang Foundation (marin README 기재).
