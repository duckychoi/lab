각 격자의 J(θ)는 2-파라미터 정책으로 실제 물리 에피소드를 끝까지 굴린 누적 보상이다(손으로 만든 함수 아님). 블랙박스 환경이라 세 옵티마이저(FD/ES/ESC)는 모두 GT 없이 0차로 ∇J 추정한다. 이론: 📖 아이디어 탭 참고

🎯 PCGrad — gradient surgery (다중보상 충돌 해소 · "beamforming")

전진/직립 보상과 에너지 패널티의 성분 그래디언트가 충돌(cos<0)하면 naive 합은 서로 상쇄돼 정체한다. PCGrad는 충돌 성분을 상대의 법평면으로 투영해 제거(=간섭원 nulling)한다.

∇전진·직립 ∇(−에너지) naive 합 PCGrad

FD: 축당 중앙차분으로 ∇J 추정. ES: 무작위 섭동 return 차이(Salimans 2017). ESC: 정현파 dither 방향미분. naive Σ∇: 성분 그래디언트 단순합(=전체 ∇J). PCGrad: 충돌 성분 제거 후 합(Yu 2020). 모두 GT 불필요.

📖 누적 리워드 "변화 방향" 학습 — 이론·구현·아이디어

0. 핵심 재정의

RL의 목적은 누적이지만 학습 신호는 이미 미분(변화)이다. 정책 그래디언트가 곧 "누적 보상이 가장 빨리 증가하는 방향"이며, baseline 불변성으로 절대 누적량이 아니라 상대적 advantage만 작동한다.

\[ J(\theta)=\mathbb{E}\Big[\textstyle\sum_t \gamma^t r_t\Big],\qquad \nabla_\theta J(\theta)=\mathbb{E}\big[\nabla_\theta\log\pi_\theta(a_t\mid s_t)\,A(s_t,a_t)\big] \]

"GT가 없어서 가능한가?" → score-function 추정기가 최적점의 GT가 아니라 그래디언트만 샘플로 불편 추정한다. 그래서 GT 없이도 표준적으로 가능하다. (더 정확한 최속 방향은 Fisher 계량의 natural gradient.)

1. "변화량을 신호로" — 6가지 해석

해석의미기존 연구
(a) 보상 차분 shaping\(F=\gamma\Phi(s')-\Phi(s)\)Potential-based shaping (Ng 1999) — 최적성 보존
(b) 기대값 변화TD 오차 \(\delta\), advantageActor-Critic (이미 표준)
(c) 보상의 시간미분\(r\sim\Delta(\text{진척})\)비-potential이면 최적점 변형 위험
(d) 평균보상 미분differential valueaverage-reward RL
(e) 목적 자체 학습리턴/할인 메타학습Meta-gradient RL (Xu 2018)
(f) 리턴 변화율로 과제 선택학습 진척도 커리큘럼ALP-GMM (Portelas 2019, BipedalWalker)

안전하게 변화량을 보상에 넣으려면 potential-based shaping만이 최적 정책을 보존한다:

\[ r'(s,a,s')=r(s,a,s')+\gamma\Phi(s')-\Phi(s) \]

2. GT 없이 급증 방향 추정 (구현 가능)

  • Score-function (REINFORCE/PPO) — 블랙박스 보상, 불편추정.
  • Evolution Strategies (Salimans 2017) — 파라미터 섭동의 유한차분:
\[ \hat\nabla_\theta J \approx \frac{1}{\sigma N}\sum_{i=1}^{N} R(\theta+\sigma\epsilon_i)\,\epsilon_i,\quad \epsilon_i\sim\mathcal N(0,I) \]
  • Extremum Seeking Control — dither + demodulation으로 미지 목적의 그래디언트를 실시간 측정(연속시간 0차 ascent).

→ 시뮬레이터 탭에서 진자·전진 hopper 실제 롤아웃 위에 FD/ES/ESC를 직접 돌려볼 수 있다.

3. 보상 지형 / 등고선

(A) 고정 보상에서 \(J(\theta)\) reward surface — "Cliff Diving"(2022)은 정책 그래디언트 방향의 절벽(cliff)을 발견. (B) 보상 가중치 \(w\)를 바꾸면 \(J_w(\theta)\) 지형·최적점이 이동(다목적 Pareto). 시뮬레이터가 두 개념을 실측으로 보여준다.

4.2 ALP Curriculum 구현 스케치

개념. terrain/task parameter \(z\)별로 최근 episode return 또는 success의 변화량 \(ALP(z)=|R_{new}-R_{old}|\)를 기록하고, 너무 쉽거나 너무 어려운 샘플 대신 학습 진척이 큰 구간을 더 자주 뽑는다.

class ALPCurriculum:
    def __init__(self, bins_or_gmm, p_random=0.2):
        self.stats = RunningStatsByTask()
        self.p_random = p_random

    def sample(self):
        if rand() < self.p_random:
            return sample_random_task_or_terrain()
        return sample_weighted_by_abs_learning_progress(self.stats)

    def update(self, task_id, episode_return, success):
        # store recent return/success and update |new - old|
        self.stats.add(task_id, episode_return, success)

4.3 PCGrad/CAGrad Reward-Term PPO

핵심. scalar reward 하나로 합친 뒤 PPO를 돌리면 어떤 보상 성분이 policy gradient를 서로 상쇄하는지 사라진다. 먼저 reward term을 분해 저장하고, term별 advantage 또는 term별 return을 계산한 뒤 policy gradient surgery를 한다.

PCGrad(Yu 2020): 두 보상 성분 그래디언트가 충돌(\(g_i\cdot g_j<0\))하면 상대 법평면으로 투영해 파괴적 간섭 제거 — 시뮬레이터의 PCGrad 데모에서 \(\cos\approx-0.99\) 충돌을 확인할 수 있다.

\[ g_i \leftarrow g_i - \frac{g_i\cdot g_j}{\lVert g_j\rVert^2}\,g_j \qquad (\text{if } g_i\cdot g_j<0) \] 
# reward 계산부: 합산 전 term을 보존
reward_terms = {
    "task": r_task,
    "posture": r_posture,
    "energy": r_energy,
    "collision": r_collision,
    "clearance": r_clearance,
}
reward = sum(w[k] * reward_terms[k] for k in reward_terms)
extras["reward_terms"] = {k: v.detach() for k, v in reward_terms.items()}

# PPO update부: term별 policy loss gradient를 추출
grads = []
for k in selected_terms:
    adv_k = compute_gae(reward_terms_rollout[k], values_or_zero)
    loss_k = ppo_surrogate_loss(logprob, old_logprob, adv_k)
    grads.append(flat_grad(loss_k, actor_params))

g = pcgrad_or_cagrad(grads)
assign_flat_grad(actor_params, g)
optimizer.step()

MQE에는 team reward, individual progress, collision avoidance, object interaction reward 사이의 충돌을 분석하는 데 적합하다. Extreme Parkour에는 forward/heading progress, obstacle clearance, energy/action smoothness, collision/fall penalty 간 충돌을 줄이는 데 적합하다.

4.4 Fuzzy/Lyapunov Shaping

T-S fuzzy는 보상 항 자체를 대체하기보다 상태의 안전도·자세 안정도·진척도 potential을 부드럽게 만드는 용도로 쓴다. 직접 \(+r_{fuzzy}\)를 더하면 shortcut과 최적 정책 변형 위험이 있으므로, 기본형은 아래처럼 둔다.

# fuzzy potential: 높을수록 좋은 상태
Phi = fuzzy_potential(
    body_height=base_z,
    roll_pitch_norm=torch.norm(projected_gravity_error),
    foot_clearance=clearance,
    distance_to_goal=dist_goal,
)
shaping = gamma * Phi_next - Phi
reward = task_reward + lambda_phi * shaping

규칙 예: body height가 낮고 roll/pitch가 크면 potential 급감, 목표 진척이 좋고 자세가 안정하면 완만히 증가. 규칙 수가 폭발하지 않도록 입력은 3~5개로 제한한다.

4.5 ESC는 어떻게 쓸 것인가

정정. ESC가 실로봇에서 원천적으로 부적절한 것은 아니다. 실제 제어에서 ESC는 미지 목적을 온라인 최적화하는 방법으로 쓰인다. 문제는 사족보행 RL에서 정책 파라미터나 12-DoF action에 지속 dither를 직접 넣는 방식이 발 미끄러짐, 충돌, actuator 과부하, 넘어짐을 유발할 수 있다는 점이다.

ESC 적용 위치평가권고
joint action 직접 dither위험 큼. 보행 위상과 접촉 안정성을 깨기 쉽다.실기체 금지, 시뮬 ablation만.
policy weight dither비정상·고차원·느림. PPO/actor 분포와 충돌.권장하지 않음.
reward weight / terrain difficulty dither저차원이고 느린 outer-loop라 안전 관리 가능.시뮬에서 가능. 실기체는 아주 작은 amplitude와 watchdog 필요.
PD gain / gait frequency / foot clearance dither제어에서 쓰기 쉬운 스칼라 튜닝 문제.bounded parameter, rate limit, fallback controller와 함께 제한적으로 가능.
# safe ESC outer-loop: action이 아니라 저차원 scalar만 조정
z = [reward_energy_weight, terrain_difficulty, foot_clearance]
z_probe = clamp(z + amp * sin(omega * t), z_min, z_max)
score = eval_rollout_return_or_success(z_probe)
grad_est = lowpass(score * sin(omega * t))
z = clamp(z + lr * grad_est, z_min, z_max)

# hard safety gates
if fall_rate > threshold or torque_violation > threshold:
    z = last_safe_z
    amp *= 0.5

4.6 SMC/CBF/CLF를 RL에 붙이는 안정적 방식

SMC의 철학은 “좋은 sliding surface \(\sigma(s)=0\)로 상태를 끌어오고 그 표면을 따라 움직이게 한다”이다. RL에는 action을 대체하는 hard controller보다 constraint, potential, shield, teacher 네 가지로 붙이는 편이 안정적이다.

방식구현장점주의
SMC surface as cost\(c=\max(0,\sigma\dot\sigma+\eta|\sigma|)\)를 constraint cost로 추가PPO-Lagrangian/CaT와 결합 쉬움\(\dot\sigma\) 추정 노이즈 필터 필요
Potential shaping\(\Phi(s)=-\|\sigma(s)\|^2\), \(r'=r+\gamma\Phi(s')-\Phi(s)\)reward shaping으로 간단, 안정 표면 유도surface 설계가 성능 좌우
Action shield\(u_{RL}\)을 최소 수정해 \(\sigma\dot\sigma\le-\eta|\sigma|\) 또는 CBF 조건 만족실기체 안전 논리와 가장 잘 맞음QP/projection 실패 시 fallback 필요
Recovery teacherSMC/heuristic recovery controller를 teacher로 rollout하고 student에 distillExtreme Parkour distillation 흐름과 잘 맞음teacher가 너무 보수적이면 agility 저하
# shield 개념: policy action을 위험할 때만 최소 수정
u_rl = policy(obs)
sigma = sliding_surface(obs)       # 예: roll/pitch, base height, lateral slip, contact phase error
sigma_dot = estimate_sigma_dot(obs, prev_obs)

if sigma * sigma_dot > -eta * abs(sigma):
    u_safe = project_action_min_norm(
        u_rl,
        constraint=lambda u: predicted_sigma_dot(obs, u) <= -eta * abs(sigma)
    )
else:
    u_safe = u_rl
env.step(u_safe)

4.7 SMC/ESC는 네트워크·액션·리워드 중 어디에 들어가는가

핵심 결론. SMC는 주로 액션 안전필터와 리워드/제약에 들어가고, ESC는 주로 학습 바깥의 저차원 튜닝 루프에 들어간다. 둘 다 사족보행 RL에서 네트워크 구조 자체에 넣는 1순위 아이디어는 아니다.

철학네트워크액션리워드/제약학습 루프
SMC보조 estimator 정도만 적합. 예: \(\sigma,\dot\sigma\) 예측기매우 적합. policy action 후 위험할 때만 projection/shield매우 적합. sliding surface cost, CLF/CBF constraint, potential shapingrecovery teacher, safety critic, CaT/PPO-Lagrangian과 결합
ESC부적합. policy weight dither는 고차원·비정상직접 joint/action dither는 위험. 시뮬 ablation만reward weight를 ESC로 조정 가능가장 적합. terrain difficulty, gait parameter, PD gain, foot clearance의 slow outer-loop tuner

SMC 삽입 위치. policy가 낸 action \(u_{RL}\)을 바로 env에 넣지 않고, sliding condition을 위반할 때만 최소 수정한다. 이때 nominal 구간에서는 \(u_{safe}\approx u_{RL}\)이어야 하며, shield가 계속 개입하면 policy가 스스로 안정성을 학습하지 못했다는 신호로 본다.

# SMC-style action shield
u_rl = policy(obs)
sigma = sliding_surface(obs)                  # roll/pitch, base height, lateral slip, contact phase error 등
sigma_dot_pred = predict_sigma_dot(obs, u_rl)

if sigma * sigma_dot_pred > -eta * abs(sigma):
    u_safe = project_min_norm(u_rl, constraint="sigma_dot <= -eta * |sigma|")
else:
    u_safe = u_rl
env.step(u_safe)

SMC를 리워드/제약으로 넣는 위치. action shield가 부담스럽다면 먼저 cost로 넣는다. CaT라면 위반량 \(c\)를 종료확률로 바꾸고, PPO-Lagrangian이라면 constraint cost로 dual update한다.

# SMC surface as cost
sigma = sliding_surface(obs)
sigma_dot = estimate_sigma_dot(obs, prev_obs)
smc_violation = relu(sigma * sigma_dot + eta * abs(sigma))

reward = task_reward
costs["smc_surface"] = smc_violation          # PPO-Lagrangian / CPO / CaT에 전달
# 또는 potential shaping:
Phi = -sigma.pow(2)
reward += lambda_phi * (gamma * Phi_next - Phi)

ESC 삽입 위치. ESC는 policy action이나 weight를 흔드는 용도가 아니라, episode 단위로 평가 가능한 저차원 파라미터 \(z\)를 조정하는 outer loop로 둔다. 예: reward weight, terrain 난이도, command range, PD gain, gait frequency, foot clearance.

# ESC-style slow outer-loop tuner
z = [energy_weight, terrain_difficulty, foot_clearance]
z_probe = clamp(z + amp * sin(omega * episode_idx), z_min, z_max)
score = rollout_and_measure_success_or_return(z_probe)
grad_est = lowpass(score * sin(omega * episode_idx))
z = clamp(z + lr * grad_est, z_min, z_max)

if fall_rate > limit or torque_violation > limit:
    z = last_safe_z
    amp *= 0.5

권장 조합. 사족보행 RL에서 가장 깔끔한 구조는 SMC = action shield + constraint cost, ESC = curriculum/reward/gait parameter outer-loop tuner이다. 이 조합은 네트워크 본체를 크게 바꾸지 않고 MQE/Extreme Parkour 스타일 코드에 붙일 수 있다.

5. 사족보행 권고

  • 바로 시도: ① ALP 지형/태스크 커리큘럼 → ② reward-term logging → ③ PCGrad/CAGrad 다중보상 → ④ potential fuzzy shaping.
  • ESC/ES는 직접 action·policy 섭동 금지. 시뮬 또는 저차원 slow outer-loop 튜닝에 제한하고, 실기체에서는 amplitude/rate limit, violation watchdog, fallback controller를 둔다.
  • SMC/CBF/CLF는 action을 대체하기보다 safety cost, potential shaping, action shield, recovery teacher로 접목한다.
  • "변화량"을 보상에 직접 넣을 땐 반드시 potential-based shaping으로.
